# 임베디드 & 온디바이스 AI 직무 이해

교과목 1(32시간)에 대응하는 문서다. **실습 코드가 아니다.**

이 저장소의 실습 80개는 전부 "무엇을 어떻게 만드는가"를 다룬다.
이 문서는 그 앞에 오는 질문 — **"왜 이 일이 따로 존재하는가"** — 을 다룬다.

각 절 끝에 그 이야기가 코드로 나타나는 실습을 붙였다.
개념만 읽고 넘어가지 말고, 그 실습을 돌려서 숫자로 확인해야 한다.

## 1. AI 기술의 산업 적용 흐름 변화

```text
2015년경   클라우드에 모델을 두고 데이터를 올려 보낸다
2020년경   지연·회선·비용 때문에 일부를 현장으로 내린다
지금       판단은 현장에서, 학습과 통제는 클라우드에서
```

세 번째 줄이 이 과정의 구조다. 모듈 6 이 그 순환을 코드로 만든다.

> 확인: [6-10](../curriculum/6-10.md) Edge → Cloud → Edge 순환

## 2. 온디바이스 AI가 요구되는 구조적 배경

세 가지가 각각 독립적인 이유다.

### 실시간 판단

라인은 30ms 마다 한 장을 찍는다. 클라우드 왕복은 40ms 다.
**모델을 아무리 줄여도 왕복 시간은 안 줄어든다.**

> 확인: [4-14](../curriculum/4-14.md), [6-14](../curriculum/6-14.md)

### 네트워크

공장 회선은 끊긴다. 정전, 스위치 교체, 공사.
클라우드 추론에만 의존하면 그 시간 동안 라인이 서거나 검사 없이 흘러간다.

> 확인: [6-14](../curriculum/6-14.md) `EP_NO_OFFLINE_FALLBACK`

### 보안·비용

현장 신호에는 생산량과 가동 패턴이 들어 있다.
전부 올리면 회선과 청구서가 먼저 터지고, 한 번 올라간 것은 지워도 지워지지 않는다.

> 확인: [6-1](../curriculum/6-1.md), [6-13](../curriculum/6-13.md)

## 3. AI 모델 개발자 vs 온디바이스 AI 엔지니어

| | 모델 개발자 | 온디바이스 AI 엔지니어 |
|---|---|---|
| 끝나는 지점 | 정확도가 나온 노트북 | 현장에서 6개월째 도는 모델 |
| 주로 보는 숫자 | accuracy, loss | p95 지연, RSS, 알람/시간, 롤백 시간 |
| 실패의 모습 | 학습이 안 된다 | **에러 없이 틀린다** |
| 마지막 책임 | 모델 | 시스템 |

세 번째 줄이 핵심이다.
이 과정의 실습 대부분은 **에러가 안 나는 실패**를 잡는 방법을 다룬다.

```text
표본 간격이 10초에서 30초로 바뀌었다      → 에러 없음, 현장에서만 틀림 (5-1, 5-12)
전처리가 학습 때와 다르다                  → 에러 없음 (5-12, 5-15)
가지치기 뒤 미세조정이 0을 다시 채웠다     → 에러 없음 (4-11)
분할 전에 리샘플링했다                     → 정확도가 **올라간다** (2-11)
```

## 4. 실제 산업 현장 AI 시스템 구성 요소

```text
Data → Data Quality → Model → Optimization → Deployment → Operations → Cloud → Fleet
```

이 저장소의 모듈 1~6 이 그대로 이 순서다.
그리고 각 단계에는 **다음 단계로 넘어가도 되는지 판정하는 게이트**가 있다.

```text
모듈 1 끝  학습 착수 판정          (1-10)
모듈 2 끝  Data Quality Gate       (2-10)
모듈 3 끝  모델 승인 판정          (3-10)
모듈 4 끝  배포 후보 선택          (4-10)
모듈 5     격리·롤백·재학습 판정   (5-8, 5-10, 5-11)
모듈 6     릴리스·웨이브·중단      (6-7, 6-8, 6-9)
```

게이트가 없으면 각 단계가 "일단 넘김"으로 이어지고,
그 비용은 전부 마지막 단계인 현장이 낸다.

## 5. 단순한 모델 개발과 운영 가능한 AI 시스템의 차이

같은 모델이 두 문장으로 설명된다.

```text
"test 정확도 1.000 이 나왔습니다."
"판단 기회 11,511건 중 9,511건(82.6%)만 답이 되었고,
 알람은 시간당 2.5건이며, 되돌리는 데 20초 걸립니다."
```

앞 문장은 노트북에서 나오고, 뒤 문장은 시스템에서만 나온다.
**뒤 문장을 만들 수 있는 사람이 이 직무다.**

> 확인: [5-12](../curriculum/5-12.md), [5-13](../curriculum/5-13.md), [5-15](../curriculum/5-15.md)

## 6. 이 과정에서 반복되는 원칙

전 모듈에서 같은 문장이 계속 나온다. 우연이 아니라 설계다.

```text
측정은 Infrastructure, 판정은 Domain
숫자에는 어떻게 쟀는지가 붙어 있어야 한다
막는 소견이 남아 있으면 그건 아직 결론이 아니다
확인하지 못한 것을 확인한 척하지 않는다
```

마지막 줄은 이 저장소가 스스로에게도 적용한다 —
합성한 지연시간, moto 가 지원하지 않는 API, 고정 응답을 돌려주는 `invoke_endpoint` 를
전부 해당 실습 문서에 적어 두었다.
