# 5-11. 재학습이 필요한 순간을 직접 정의하라

## 문제

가장 흔한 답: **"정확도가 떨어지면 재학습한다."**

이 문장은 실행할 수 없다. **현장에 정답이 없어서 정확도를 못 재기 때문이다.**
모듈 5 전체가 그 사실 위에 서 있었다.

실행 가능한 기준은 이렇게 생겼다.

```text
입력 분포가 변했고         (실습 5-7)
그 상태가 지속됐고         (실습 5-4 — 한 번 튄 게 아니다)
새 라벨이 충분히 모였다    (없으면 재학습해도 같은 것을 배운다)
```

## 무엇을 보게 되는가

```text
재학습 판정: 필요  (긴급도 PLAN)
  근거 : INPUT_DRIFT, NEW_LABELS_AVAILABLE
  라벨 : 라벨 4,118/34,533 (11.9%)  배포 후 4,118건  [FAULT 30  NORMAL 3232  OVERLOAD 856]

  - WARNING RETRAIN_SUSTAINED_INPUT_DRIFT (INPUT_PSI)
            입력 분포가 '05-22 00시' 부터 3창 연속으로 기준을 넘었다.
            현실이 학습 데이터에서 멀어진 것이다.  [측정 4.625 / 기준 0.2]

  지금 시작할 수 있다. → 모듈 1 로 돌아간다.
```

## 한 번 튄 것으로 재학습하지 않는다

[5-4](5-4.md) 의 구분이 여기서 실제로 쓰인다.

```text
INFO RETRAIN_DRIFT_SPIKE_ONLY
     '05-21 08시' 에서 한 번 튀었지만 이어지지 않았다. 재학습 사유가 아니다.
```

```python
drift = timeline.onset_of(
    HealthMetric.INPUT_PSI, self.drift_psi_threshold,
    consecutive=self.sustained_windows,
)
if drift.is_sustained:
    reasons.append(TriggerReason.INPUT_DRIFT)
elif drift.spike_only:
    urgency = Urgency.WATCH   # 지켜보되 시작하지 않는다
```

연속 창 수를 몇으로 둘지는 **재학습 비용이 정한다.**
라벨링에 2주가 걸리면 짧게 잡아 미리 시작해야 한다.

## 재학습해야 하는데 지금은 할 수 없다

**이것이 이 판정의 진짜 값어치다.**

```text
재학습 판정: 필요  (긴급도 PLAN)
  근거 : INPUT_DRIFT

  지금 시작할 수 없는 이유:
    ✗ 배포 후 새로 붙은 라벨이 4,118건뿐이다 (5,000건 필요).
      지금 학습하면 예전 데이터를 다시 배운다.
```

```python
@property
def can_start(self) -> bool:
    return self.needed and not self.blockers
```

**"필요하다"와 "지금 시작할 수 있다"는 다르다.**
그리고 막고 있는 것의 목록이 곧 **할 일 목록**이다.

## 소수 클래스 라벨이 없으면 그 클래스는 안 나아진다

```text
라벨 4,118/34,000 (12.1%)  [FAULT 30  NORMAL 3232  OVERLOAD 856]

지금 시작할 수 없는 이유:
  ✗ 'FAULT' 의 새 라벨이 100건 미만이다. 이 클래스는 재학습해도 나아지지 않는다.
```

전체 라벨은 4,118건으로 충분하다. 그런데 **FAULT 는 30건**이다.

그러니 할 일은 "재학습"이 아니라 **"FAULT 구간을 찾아 라벨링"** 이다.
그 구분이 몇 주를 아낀다.

```python
minority_label_counts: dict[str, int]
"""클래스별 새 라벨 수.
**FAULT 가 0건이면 재학습해도 FAULT 를 못 배운다.**
"""
```

이건 모듈 2 의 클래스 불균형([2-5](2-5.md))이 운영에서 다시 나타난 것이다.

## 정답이 있으면 가장 강한 근거가 된다

```text
재학습 판정: 필요  (긴급도 NOW)
  근거 : INPUT_DRIFT, MEASURED_ACCURACY_DROP, NEW_LABELS_AVAILABLE

  - CRITICAL RETRAIN_MEASURED_ACCURACY_DROP (measured_accuracy)
             정답이 붙은 표본에서 실제 정확도가 0.7290 다.
             **추정이 아니라 확인된 하락이다.**  [측정 0.729 / 기준 0.8]
```

| 근거 | 무엇을 말하는가 |
|---|---|
| INPUT_DRIFT | 아마 나빠졌을 것이다 |
| PREDICTION_SHIFT | 아마 나빠졌을 것이다 |
| CONFIDENCE_DECAY | 아마 나빠졌을 것이다 |
| **MEASURED_ACCURACY_DROP** | **나빠졌다** |

11.9% 의 라벨만으로도 이 판정이 가능해진다.
**현장 라벨링에 사람을 붙이는 것이 결국 가장 싼 관측 장치다.**

## 긴급도는 셋이다

```python
class Urgency(Enum):
    WATCH = "WATCH"   # 지금 시작할 필요 없다. 다음 창을 본다.
    PLAN  = "PLAN"    # 라벨링을 시작한다. 모델은 아직 돌려도 된다.
    NOW   = "NOW"     # 멈추고 시작한다.
```

"재학습이 필요한가"에 예/아니오로 답하면 현장은 움직이지 않는다.
**"무엇부터 해야 하는가"에 답해야 움직인다.**

## 관측 없이는 판단할 수 없다

```text
[INVARIANT_VIOLATION] timeline: 관측 없이 재학습을 판단할 수 없다.
```

배포하고 아무것도 안 보고 있었다면 이 질문 자체가 성립하지 않는다.
[5-1](5-1.md) 에서 배포와 동시에 관측을 연 이유가 여기까지 이어진다.

## 순환은 여기서 닫힌다

```text
RetrainingRequested
```

```python
@dataclass(frozen=True, slots=True)
class RetrainingRequested(DomainEvent):
    """모듈 1 로 돌아가는 신호. 순환은 여기서 닫힌다."""
    watch_id: WatchId
    deployment_id: DeploymentId
    urgency: str
    reasons: tuple[str, ...]
```

이 사건을 받는 쪽이 모듈 1 의 데이터 수집이다.

그리고 돌아갈 때 두 가지를 들고 간다.

```text
무엇이 어떻게 변했는가        → 다음 데이터를 어느 구간에서 모을지
어느 클래스의 라벨이 모자란가 → 무엇부터 라벨링할지
```

**그 두 가지가 다음 데이터 수집 계획이 된다.**

```text
데이터 → 품질 → 모델 → 최적화 → 운영 → **다시 데이터**
```

## 자주 하는 실수

- **"정확도가 떨어지면"을 기준으로 삼는다.** 현장에서는 실행할 수 없다.
- **드리프트만 보고 시작한다.** 라벨이 없으면 같은 것을 다시 배운다.
- **전체 라벨 수만 센다.** 소수 클래스가 비어 있으면 그 클래스는 안 나아진다.
- **한 번 튄 것으로 재학습한다.** 비용만 쓰고 아무것도 안 바뀐다.
