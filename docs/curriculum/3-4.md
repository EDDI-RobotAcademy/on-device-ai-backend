# 3-4. 센서의 시간을 AI가 볼 수 있게 잘라라

## 문제

실습 1-7 에서 "몇 초를 한 덩어리로 볼 것인가"를 정했다.
여기서는 그 창을 **실제로 자를 때** 생기는 두 문제를 다룬다.

1. 창의 라벨은 무엇인가?
2. 창이 겹치면 표본이 몇 개인가?

## 실습

```bash
pytest -m lesson_3_4 -s
```

## 첫 번째 문제 — 창의 라벨

30 표본(5분)짜리 창 안에 NORMAL 21개와 FAULT 9개가 있다. 이 창은 무엇인가?

```text
창 안의 라벨 : {'NORMAL': 21, 'FAULT': 9}
다수결       : NORMAL
현장 규칙    : FAULT   (FAULT 30% 이상 → OVERLOAD 50% 이상 → 그 외 NORMAL)
```

**다수결로 하면 5분 중 1분 반 동안 설비가 멈춰 있던 창이 '정상'이 된다.**
반대로 "하나라도 있으면 FAULT" 로 하면 거의 모든 창이 FAULT 가 된다.

짧게 스쳐도 사고는 사고다 — 그 판단이 **30% 라는 숫자**에 들어 있다.
그리고 그 숫자는 코드가 정하는 것이 아니라 현장이 정한다.

```python
@dataclass(frozen=True, slots=True)
class WindowLabelPolicy:
    priority: tuple[tuple[str, float], ...]   # (라벨, 최소 비율), 순서대로 검사
    default_label: str
```

## 두 번째 문제 — 겹침

```text
12,960행 → 창 1,294개 (length=30, stride=10, 겹침 67%)
  독립 표본 환산 431개
```

```text
WARNING WINDOW_OVERLAP_HIGH  창이 67% 겹친다.
                             창 1,294개처럼 보이지만 독립 표본은 431개다.
```

**'데이터가 1,294개 있습니다'라는 보고가 3배 부풀려진 것이다.**

실습 2-7 에서 봤던 중복 문제와 같은 성질이다.
다만 여기서는 우리가 **의도적으로 만들어 낸** 중복이다.

## stride 를 바꾸면

```text
              창    겹침   독립표본  FAULT창
stride 10   1,294    67%       431       50
stride 30     432     0%       432       17
```

겹침을 없애면 표본이 3분의 1로 준다. 대신 그 표본은 **전부 서로 다르다.**

> 어느 쪽이 정직한 숫자인가.

이 선택의 결과는 실습 3-8(분할 누수)과 3-10(승인 판정)에서 그대로 돌아온다.

## stride 가 너무 크면 데이터가 버려진다

```text
CRITICAL WINDOW_COVERAGE_LOW  원본의 상당 부분이 어떤 창에도 들어가지 않았다.
```

창 30, stride 100 이면 표본 70개마다 한 번씩 통째로 건너뛴다.
그 70개 안에 사고가 있었다면 학습 데이터에서 사라진 것이다.

```python
@property
def coverage_ratio(self) -> float:
    """원본 표본 중 어느 하나의 창에라도 **실제로 들어간** 비율.

    창이 이어진 구간의 길이가 아니라, 창 안에 들어간 표본 수로 센다.
    """
```

## 원본에 있던 클래스가 창에서 사라진다

```text
CRITICAL WINDOW_CLASS_TOO_FEW (FAULT)  'FAULT' 창이 3개뿐이다.
                                       원본에는 표본이 있어도 창으로 자르면 사라질 수 있다.
```

원본에는 FAULT 표본이 240개 있었다. 창으로 자르니 3개다.

**표본 수를 원본 기준으로 세면 이 사실을 놓친다.**
실습 2-5 에서 "비율이 아니라 개수"라고 했던 것이, 창을 자른 뒤에는 또 다른 개수가 된다.

## 실습 데이터가 이렇게 만들어진 이유

```python
# M02 — 트립을 36시간에 고르게 배치한다.
# 무작위로 뿌리면 우연히 한쪽에 몰리고, 그러면 test 분할에 사건이 하나도 없게 된다.
spacing = rows // fault_runs
```

이건 교재를 만들면서 실제로 겪은 문제다.
처음에는 트립을 무작위로 뿌렸는데, 시간순 분할의 마지막 15% 에 사건이 하나도 없었다.
혼동 행렬이 한 줄짜리가 되어 실습 3-9 가 성립하지 않았다.

현장에서도 같은 일이 일어난다. **사건이 드물면 분할 하나가 통째로 비어 버린다.**

## 자주 하는 실수

- **`stride=1` 로 최대한 많은 표본을 만든다.** 표본 수는 늘고 정보는 그대로다.
  그리고 분할이 통째로 샌다.
- **창 라벨을 다수결로 정한다.** 짧은 사건이 전부 사라진다.
- **창을 자른 뒤 클래스 분포를 다시 세지 않는다.**
