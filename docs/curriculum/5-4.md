# 5-4. AI가 언제부터 이상해졌는지 찾아라

## 문제

지금 이상하다는 것은 지금 봐도 안다.
**언제부터인지는 기록이 없으면 영영 모른다.**

## 실습

```bash
pytest -m lesson_5_4 -s
```

## 무엇을 보게 되는가

```text
창                       판정                       p95(ms)      분포이동      PSI
----------------------------------------------------------------------------
05-20 00시               PASSED                     0.030      0.0%   0.0051
05-20 08시               PASSED                     0.030      1.1%   0.0052
05-20 16시               PASSED                     0.030      0.5%   0.0050
05-21 00시               PASSED                     0.030      0.4%   0.0119
05-21 08시               FAILED                     0.030      9.3%   7.3032
05-21 16시               PASSED                     0.030      0.7%   0.0110
05-22 00시               FAILED                     0.030      5.1%   4.6248
05-22 08시               FAILED                     0.030      5.0%   4.6409
05-22 16시               FAILED                     0.030      4.9%   3.3506
05-23 00시               FAILED                     0.076      6.1%  10.1501
05-23 08시               FAILED                     0.075      5.9%   9.5505
05-23 16시               FAILED                     0.075      6.0%   9.4578
```

**이 표를 만들 수 있는지는 지금이 아니라 배포하던 날 결정됐다.**
관측을 그때 켰기 때문에 1일차 창이 남아 있다 (실습 5-1).

## 한 번 튄 것과 무너진 것은 다르다

```text
INPUT_PSI 기준 0.2 — 3창 연속을 사건으로 본다
--------------------------------------------------------------
  · 05-20 00시                   0.0051
  · 05-20 08시                   0.0052
  · 05-20 16시                   0.0050
  · 05-21 00시                   0.0119
  ✗ 05-21 08시                   7.3032      ← 도장 부스 문이 열렸다
  · 05-21 16시                   0.0110      ← 다음 창에서 돌아왔다
  ✗ 05-22 00시                   4.6248      ← 여기서부터 이어진다
  ✗ 05-22 08시                   4.6409
  ✗ 05-22 16시                   3.3506
  ✗ 05-23 00시                  10.1501
--------------------------------------------------------------
  처음 넘긴 창   : 05-21 08시
  **무너진 시점** : 05-22 00시
```

**이 실습의 전부다.**

처음 넘긴 창(05-21 08시)은 사건이 아니다. 다음 창에서 돌아왔다.
실제로 무너진 시점은 05-22 00시 — 여기서부터 3창 연속으로 기준을 넘었다.

이 둘을 구분하지 않으면 알람이 하루에 열 번 울리고, **사람은 곧 알람을 끈다.**
알람을 끈 시스템은 없는 시스템이다.

```python
def onset_of(self, metric, threshold, *, consecutive: int = 3) -> OnsetFinding:
    """기준을 처음 넘긴 창과, 연속으로 넘기 시작한 창을 찾는다.

    **찾는 것은 마지막이 아니라 처음이다.**
    사람이 알아챈 시각이 아니라 실제로 시작된 시각을 답해야 하기 때문이다.
    """
```

## 연속 창 수는 현장이 정한다

```text
연속 1창 → 무너진 시점 05-21 08시   (스파이크도 사건이 된다)
연속 3창 → 무너진 시점 05-22 00시   (스파이크는 걸러진다)
```

| 짧게 잡으면 | 길게 잡으면 |
|---|---|
| 헛알람이 잦다 | 대응이 늦다 |
| 사람이 알람을 끈다 | 그동안 불량이 나간다 |

**둘 다 비용이 있다.** 그 비용을 아는 사람이 숫자를 정한다.

## 지표마다 무너진 시점이 다르다

```text
입력 분포   : 05-22 00시
지연시간    : 05-23 00시
```

하루 차이가 난다. **서로 다른 원인이기 때문이다** —
하나는 여름이 온 것이고([5-7](5-7.md)), 하나는 팬이 고장 난 것이다([5-5](5-5.md)).

지표를 하나만 보고 있었으면 둘 중 하나를 놓쳤을 것이다.

## 기준이 판정을 만든다

```text
기준 0.2   → 무너진 시점 05-22 00시
기준 100   → 아무 일도 없었다
```

같은 데이터, 같은 코드. 바뀐 것은 숫자 하나다.
**"이상하다"는 데이터의 성질이 아니라 기준과의 관계다.**

## 창은 거꾸로 들어오지 않는다

```text
[INVARIANT_VIOLATION] 05-20 08시:
    '05-20 08시' 이 직전 창보다 앞선다.
    시간선이 뒤엉키면 '언제부터'에 답할 수 없다.
```

`HealthWatch.record()` 가 지키는 불변식이다.
같은 창을 다시 재면 덮어쓰고, 앞선 창을 밀어 넣으면 막는다.

## 창의 표본 수는 실제 로그 수로 다시 센다

```python
def _resize(window, sample_count) -> ObservationWindow:
    """창의 표본 수는 **실제로 들어온 로그 수**다.

    창을 만들 때 미리 적어 둔 숫자를 믿으면, 로그가 안 올라온 구간을 못 알아챈다.
    """
```

디바이스가 죽어서 로그가 안 올라온 구간은 **아무 소견도 안 나오는 조용한 창**이 된다.
그게 가장 위험한 상태다. 그래서 표본 수를 다시 세고 `OPS_WINDOW_TOO_SMALL` 로 지적한다.

## 자주 하는 실수

- **지금 값만 본다.** 언제부터인지 모르면 원인 후보를 좁힐 수 없다.
- **스파이크로 알람을 울린다.** 사람이 알람을 끈다.
- **지표를 하나만 본다.** 원인이 여럿이면 시점도 여럿이다.
- **로그가 안 올라온 구간을 정상으로 센다.** 조용한 창이 가장 위험하다.
