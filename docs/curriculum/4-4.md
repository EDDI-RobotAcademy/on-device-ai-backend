# 4-4. TFLite로 모델을 디바이스에 맞춰라

## 문제

여기서 **프레임워크가 통째로 바뀐다.** PyTorch → TensorFlow.

가능한 이유는 하나다.
**모듈 3 에서 `ModelArchitecture` 를 `nn.Module` 이 아니라 '명세'로 만들어 두었기 때문이다.**

## 실습

```bash
pytest -m lesson_4_4 -s
```

## 무엇을 보게 되는가

```text
후보 TFLITE/FP32
  변환   : PYTORCH → TFLITE (FP32)  표본 66개  max|diff| 1.907e-06  argmax 일치 100.00%
  크기   : 16,780B (가중치 12,748 + 오버헤드 4,032)
  속도   : p50 0.0029ms / p95 0.0030ms
  정확도 : 1.0000 / macro recall 1.0000
```

기준 대비 **10배 빨라졌다.** PyTorch 로 학습한 가중치가 TensorFlow 인터프리터에서 같은 답을 냈다.

## 명세가 있으면 프레임워크는 교체 가능한 부품이다

```text
ModelArchitecture (모듈 3의 명세)
    ├──→ build_module()        PyTorch nn.Module     학습용
    └──→ build_keras_model()   Keras Model           변환용
```

```python
# infrastructure/optimization/keras_bridge.py
def _build_cnn1d(architecture, state_dict, tf):
    length, channels = architecture.input_spec.shape
    inputs = tf.keras.Input(shape=(length, channels))
    for out_channels in architecture.hidden_channels:
        conv = tf.keras.layers.Conv1D(out_channels, architecture.kernel_size, padding="same")
        x = tf.keras.layers.ReLU()(conv(x))
```

같은 명세를 읽어 Keras 모델을 조립하고, 가중치만 옮긴다.
**이것이 CLAUDE.md §14 가 실제로 값어치를 내는 지점이다.**

## 축 순서를 반드시 바꿔야 한다

```python
PyTorch Conv1d 커널   (out_channels, in_channels, kernel)
Keras   Conv1D 커널   (kernel, in_channels, out_channels)

PyTorch Linear 가중치 (out_features, in_features)
Keras   Dense  가중치 (in_features, out_features)
```

```python
conv.set_weights([weight.transpose(2, 1, 0), bias])   # (O,I,K) → (K,I,O)
dense.set_weights([state_dict["classifier.weight"].numpy().T, bias])  # (O,I) → (I,O)
```

실습 3-3 에서 "축을 틀려도 reshape 이 그냥 된다"고 했던 그 문제가
**여기서 실제 비용으로 돌아온다.**

## 축을 틀리면 조용히 다른 모델이 된다

```text
올바른 변환의 예측 : [2, 1, 2, 2, 2, 2, 2, 1]
뒤집힌 변환의 예측 : [0, 1, 0, 0, 0, 0, 0, 1]
```

모양이 같으니 아무도 못 알아챈다. **예외도 안 난다.**

정확도를 재 보면 30% 대가 나올 것이고,
"양자화 때문에 정확도가 떨어졌나 보다"라고 넘어가면 그대로 현장에 나간다.

**대조하지 않으면 이 모델이 현장에 나간다.**

## 지원하지 않으면 지원하지 않는다고 말한다

```text
[UNSUPPORTED_SOURCE_FORMAT] CNN2D:
    CNN2D 는 아직 TFLite 경로를 지원하지 않는다.
    지원하지 않는다는 사실을 조용히 숨기지 않는다.
```

이미지 모델(실습 3-3)의 TFLite 경로는 아직 없다.
**'아직 없다'고 말하는 것과 조용히 이상한 것을 내주는 것은 완전히 다르다.**

```python
def supports(self, runtime: RuntimeTarget, precision: Precision) -> bool: ...
```

`ModelExporter` Port 에 `supports()` 가 있는 이유다.
Use Case 는 먼저 물어보고, 못 한다고 하면 시도하지 않는다.

## 실패도 결과다

```text
✗ TFLITE/INT8: [CONVERSION_FAILED] TFLITE: 이 연산자는 TFLite 에 없다: custom_op_42
```

```python
def record_rejection(self, label: str, reason: str) -> None:
    """변환이 실패했다는 사실을 남긴다.

    "TFLite 로는 안 되더라"가 구전으로만 남으면 다음 사람이 또 해 본다.
    """
```

이유 없는 실패 기록은 받지 않는다 (`InvariantViolation`).
이유가 없으면 다음 사람이 똑같이 하루를 쓴다.

## 인터프리터의 입력 모양은 사본이다

```python
current_shape = tuple(input_detail["shape"])

def predict(x):
    nonlocal current_shape
    if current_shape != batch.shape:
        interpreter.resize_tensor_input(input_detail["index"], batch.shape)
        interpreter.allocate_tensors()
        current_shape = batch.shape
```

`get_input_details()` 가 돌려준 dict 는 **그 시점의 사본**이다.
`resize` 해도 그 dict 는 안 바뀐다.
이걸 놓치면 `Got 1 but expected 66` 같은 오류가 한참 뒤에 나온다.

## 자주 하는 실수

- **축 전치를 잊는다.** 오류 없이 다른 모델이 나온다.
- **변환 후 대조를 건너뛴다.** 위 실수를 잡을 유일한 방법이 그것이다.
- **지원하지 않는 조합을 비슷한 것으로 대체한다.** 가장 나쁜 실패다.
- **실패를 기록하지 않는다.** 다음 사람이 같은 하루를 쓴다.
