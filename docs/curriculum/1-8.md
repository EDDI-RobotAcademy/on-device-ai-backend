# 1-8. 데이터를 쪼개야 진짜 문제가 보인다

## 문제

분할은 나누기가 아니라 **시험 문제를 격리하는 일**이다.

현장 데이터에서 가장 흔한 사고 두 가지가 여기서 발생한다.

1. **시계열을 무작위로 섞어 나눈다.**
   10:00:00 이 train, 10:00:01 이 test 로 간다.
   사실상 정답을 옆에서 보고 푸는 것이다. 검증 점수 99%, 현장에서는 실패.

2. **같은 설비/LOT/제품의 데이터가 train 과 test 에 흩어진다.**
   모델은 결함이 아니라 그 LOT 의 배경을 외운다.

## 규칙을 외우기 전에 숫자를 봐라

이 실습은 순서가 중요하다. **먼저 직접 새게 만들어 보고**, 그 다음 규칙을 만난다.

```bash
pytest -m lesson_1_8 -s
```

```text
같은 데이터, 다른 분할
                 train     val    test    그룹누수    시간누수(초)
RANDOM           6,048   1,296   1,296        48         86,340
TIME_ORDERED     6,048   1,296   1,296         0              0
```

**86,340초 = 23.98시간.**
무작위 분할은 train 이 test 구간을 하루치 통째로 침범한다.
그리고 48개 LOT 전부가 양쪽에 걸쳐 있다.

행 수는 똑같다. 겉으로는 아무 차이가 없다.

## 그래서 Domain 이 계획 자체를 거부한다

```python
PartitionPlan(strategy=RANDOM, ratio=..., time_field="timestamp")
# InvariantViolation: 시간축이 있는 데이터를 무작위로 나누면 미래가 학습에 섞인다.
#                     TIME_ORDERED 를 쓴다.
```

숫자를 본 뒤에야 이 규칙이 납득된다.
규칙을 먼저 외우면 다음 프로젝트에서 다시 어긴다.

## 측정기는 나쁜 분할도 그대로 수행한다

```python
# Infrastructure — 막지 않는다. 얼마나 새는지 숫자로 보여 준다.
engine.apply(source, schema, random_plan, label_field)

# Domain — 막는다.
plan.validate_against(schema)
```

이 역할 분담이 중요하다.
측정기가 막아 버리면 학생은 누수의 크기를 영영 볼 수 없다.

## 세 가지 전략

| 전략 | 언제 쓰는가 |
|------|-------------|
| `RANDOM` | 행 사이에 순서도 그룹도 없을 때**만** 안전하다 |
| `TIME_ORDERED` | 과거로 배우고 미래로 평가한다. **시계열의 기본값** |
| `GROUP_HOLDOUT` | 같은 그룹(설비/LOT/제품)은 통째로 한쪽에만 넣는다 |

전략은 취향이 아니라 **데이터 구조가 결정한다.**

## 그룹 분할은 비율이 딱 떨어지지 않는다

```text
분할 결과 (curated) — 전략 GROUP_HOLDOUT
  train      :    5,940  (68.8%)
  validation :    1,260
  test       :    1,440
  그룹 누수  : 0 개 그룹
```

7:1.5:1.5 를 요청했지만 68.8% 가 나왔다. LOT 단위로 끊기 때문이다.
**그 대가로 누수가 사라진다.** 어느 쪽이 중요한지는 명확하다.

`PartitionPolicy.ratio_tolerance` 로 이 오차를 얼마나 허용할지 정한다.

## 이미지에서는 어떻게 되는가

실습 1-4 에서 찾은 **중복 이미지 4장**을 기억해라.
무작위로 나누면 원본은 train, 사본은 test 로 간다.
모델은 시험 문제를 이미 본 상태가 되고, 정확도는 올라간다.

그래서 이미지 데이터셋도 LOT/부품 단위 `GROUP_HOLDOUT` 이 기본이어야 한다.

## 클래스 구성비도 본다

```python
PARTITION_CLASS_SKEW  # train 과 test 의 클래스 비중이 크게 다르다
```

test 에 FAULT 가 한 건도 없으면, 그 모델의 "정확도 99%"는 아무 의미가 없다.
불균형이 심한 데이터(실습 1-6)에서는 시간 분할만으로 이런 일이 실제로 생긴다.

## 자주 하는 실수

- **`train_test_split(shuffle=True)` 를 반사적으로 쓴다.** sklearn 기본값이 `shuffle=True` 다.
- **누수를 확인하지 않고 "시간순으로 나눴으니 괜찮다"고 믿는다.**
  측정해서 0초임을 확인해야 안 것이다.
- **분할을 학습 스크립트 안에서 매번 다시 한다.** seed 가 달라지면 다른 시험을 본 것이다.
  분할 계획은 Dataset 에 **기록되어야** 한다.
