# 1-1. 데이터를 열어보는 순간 현실이 보인다

## 문제

현장에서 CSV 를 하나 받았다. 파일 이름은 `plant_power_raw.csv`,
"3라인 주회로 전력 24시간분"이라고 들었다.

여기서 대부분의 프로젝트가 하는 일은 `pd.read_csv()` 후 바로 모델 코드를 쓰는 것이다.
그리고 3주 뒤에 "왜 성능이 안 나오지?"를 시작한다.

이 실습에서는 아무 판단도 하지 않는다. **무엇이 들어 있는지 사실만 확인한다.**
그런데 사실만으로도 이미 문제가 보인다.

## 준비

```bash
.venv/bin/python -m scripts.generate_sample_data
```

먼저 파일을 그냥 열어 봐라. 에디터로, 스크롤해서.

```bash
head -3 data/samples/plant_power_raw.csv
wc -l data/samples/plant_power_raw.csv
```

## 실습

```bash
pytest -m lesson_1_1 -s
```

## 무엇을 보게 되는가

```text
rows=8,460  columns=12  bytes=843,079
column              type         missing  distinct           min           max
------------------------------------------------------------------------------
timestamp           TIMESTAMP      0.00%     8,420             -             -
meter_id            CATEGORY       0.00%         1             -             -
...
current_a           REAL           0.00%     8,286        -2.813         492.4
temperature_c       REAL           3.01%     5,349         20.02         32.26
condition           CATEGORY       0.14%         4             -             -
```

여기서 이미 네 가지가 보인다.

1. **행 수가 맞지 않는다.** 24시간 × 10초 주기라면 8,641개여야 한다. 실제는 8,460개다.
   181개가 어딘가에서 사라졌다. (→ 실습 1-5)
2. **`meter_id` 는 값이 하나뿐이다.** 정보량이 0이다. 학습에 넣어도 아무것도 배우지 못한다.
3. **`temperature_c` 가 3% 비어 있다.** 그리고 `condition`(라벨)에도 빈 값이 있다.
   정답이 없는 행이 존재한다는 뜻이다. (→ 실습 1-6)
4. **전류 최소값이 음수다.** 전류가 음수로 흐를 수는 없다. (→ 실습 1-2, 1-4)

## 설계 관점

이 단계에서 만들어지는 것은 `DatasetProfile` 하나다.
`DatasetProfile` 은 **판단이 없는 사실**이다.

```text
"결측이 3.01% 다"        → Profile      (사실)
"3.01% 는 학습 불가다"   → Policy 의 판단 (다음 단계)
```

둘을 섞으면 나중에 기준을 바꿀 때 측정 코드까지 뜯어고쳐야 한다.

측정은 Infrastructure(`PandasDatasetProfiler`)가 하고, 타입은 Domain 이 소유한다.
그래서 pandas 를 polars 로 바꿔도 Domain 은 그대로다.

```text
Domain          DatasetProfile / ColumnProfile   (타입 정의)
    ↑
Infrastructure  PandasDatasetProfiler            (값 채우기)
```

## 상태의 의미

```text
REGISTERED   존재는 안다. 아직 아무것도 열어보지 않았다.
PROFILED     열어봤다. 무엇이 들어 있는지는 안다. 의미는 아직 모른다.
```

"데이터를 가지고 있다"와 "데이터를 알고 있다"는 다르다.
`REGISTERED` 상태에서는 행이 몇 개인지조차 모른다. 이 구분이 Aggregate 에 박혀 있다.

## API 로 해보기

```bash
curl -X POST localhost:8000/datasets -H 'Content-Type: application/json' -d '{
  "dataset_id": "plant-power-raw",
  "name": "3라인 주회로 전력 24시간",
  "uri": "data/samples/plant_power_raw.csv",
  "source_format": "CSV",
  "modality": "TIME_SERIES",
  "collected_from": "LINE-3 / PM-MAIN-01"
}'

curl -X POST localhost:8000/datasets/plant-power-raw/profile
```

## 자주 하는 실수

- **`describe()` 만 보고 넘어간다.** 평균과 표준편차는 결측과 상수 열을 숨긴다.
- **행 수를 확인하지 않는다.** "24시간이라고 했으니 24시간이겠지"가 가장 비싼 가정이다.
- **`collected_from` 을 안 적는다.** 석 달 뒤 이 데이터가 어느 설비 것인지 아무도 모른다.
  그래서 `DataSourceDescriptor` 는 이 값이 비어 있으면 생성 자체를 거부한다.
