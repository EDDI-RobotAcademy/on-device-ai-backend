# 3-14. 실험을 반복하고 비교하라

## 문제

모델은 한 번 만들고 끝나지 않는다. 스무 번쯤 만든다.
그러면 두 달 뒤에 반드시 이 질문이 온다.

> "그때 그 0.95 짜리, 어떻게 만든 거였죠?"

기록이 없으면 대답은 "다시 해 봐야 압니다"다.

## 실습

```bash
pytest -m lesson_3_14 -s
```

## 결과와 조건이 함께 있어야 한다

```text
시행                      accuracy   macroF1   recall     loss      표본    params
base                       1.000     1.000    1.000    0.026      66     3,187
lr 낮춤                      0.788     0.294    0.333    0.662      66     3,187
채널 키움                      1.000     1.000    1.000    0.029      66    11,491
둘 한꺼번에                     0.924     0.887    0.848    0.382      66    11,491
  base       hidden=16-32 lr=3e-3
  lr 낮춤     hidden=16-32 lr=3e-4
  채널 키움     hidden=32-64 lr=3e-3
  둘 한꺼번에    hidden=32-64 lr=3e-4
```

## 정확도만 적으면 정확도만 좋아진다

`lr 낮춤` 은 정확도 0.788 로 아직 높아 보인다.
**macro F1 은 0.294 다** — 다수 클래스만 찍고 있다 ([3-9](3-9.md)).

## 이 실습의 본론

```text
WARNING EXP_MULTIPLE_KNOBS_CHANGED
        'lr 낮춤' → '채널 키움' 에서 2개를 한꺼번에 바꿨다 (hidden, lr).
        좋아져도 **무엇 때문인지 알 수 없다.**
```

두 개를 같이 바꾸고 좋아지면 무엇 때문인지 알 수 없고,
나빠졌다면 어느 쪽을 되돌려야 할지도 알 수 없다.

**그 상태로 다음 실험을 하면 잘못된 방향으로 스무 번을 간다.**

## 시드도 데이터도 손잡이다

```text
CRITICAL EXP_SEEDS_DIFFER
         시드가 [7, 42] 로 서로 다른데 손잡이에 적혀 있지 않다.
         차이가 구조 때문인지 **운 때문인지 구분할 수 없다.**

CRITICAL EXP_DATA_DIFFERS
         데이터가 2종류인데 손잡이에 적혀 있지 않다.
         **모델을 비교한 것이 아니라 데이터를 비교한 것이다.**
```

6월 데이터가 더 깨끗해서 좋아진 것을 "모델을 개선했다"고 보고하는 일은
**현장에서 실제로 일어난다.**

바꾼 것이 무엇이든 손잡이에 적으면 소견이 뜨지 않는다 ([3-15](3-15.md) 가 그 예다).

## 이름이 겹치면 못 찾는다

```text
InvariantViolation: 'A' 이라는 시행이 이미 있다.
```

`실험3`, `실험3_최종`, `실험3_최종_진짜` 는 현장에서 실제로 생긴다.

## 흔들림 폭

```text
WARNING EXP_WITHIN_NOISE
        1등과 2등의 차이가 0.0000 다. 흔들림 폭(0.02) 안이다 —
        **이 차이로 결론을 내면 안 된다.**
```

## 자주 하는 실수

- **한 번에 여러 개를 바꾼다.** 원인을 못 찾는다.
- **결과만 적는다.** 두 달 뒤에 재현할 수 없다.
- **시드를 안 적는다.** 운과 실력이 섞인다.
- **작은 차이로 결론을 낸다.** 다음 사람이 그 결론을 믿는다.
