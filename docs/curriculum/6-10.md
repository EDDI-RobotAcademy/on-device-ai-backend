# 6-10. Edge → Cloud → Edge 순환 구조를 완성하라

## 문제

순환이 닫혔다는 것을 무엇으로 증명하는가?

> **계보(lineage)로 증명한다.**

사슬이 한 칸이라도 끊기면 순환이 아니라 **일방통행**이다 —
데이터는 올라갔고 모델은 내려왔는데, 둘이 이어져 있다는 증거가 없다.

## 실습

```bash
pytest -m lesson_6_10 -s
```

## 다섯 칸

```text
계보 — DEV-00
--------------------------------------------------------------
    디바이스            DEV-00
  ↑ 릴리스             v2.0.0
  ↑ 학습              train-2026-05-24
  ↑ 데이터셋            build-2026-05-24
  ↑ 원본 구간           2026-05-22 00:00:00 ~ 2026-05-23 23:59:59  디바이스 24대
--------------------------------------------------------------
  사슬이 이어져 있다.

순환 판정: PASSED
  Edge → Cloud → Edge 가 이어져 있다.
```

**지금 DEV-00 에서 돌고 있는 모델이 어느 데이터에서 왔는지** 다섯 칸으로 답한다.

## 이 질문은 6개월 뒤에 반드시 나온다

```text
"이 모델 뭐로 만들었죠?"
"그때 그 불량이 학습 데이터에 들어갔나요?"
"이 디바이스만 이상한데 얘 데이터로 학습한 적 있나요?"
```

## 한 칸이 비면 그 위로 못 올라간다

```text
    디바이스            DEV-00
  ↑ 릴리스             v2.0.0
  ↑ 학습              train-2026-05-24
  ↑ 데이터셋            (끊김)
  ↑ 원본 구간           2026-05-22 ~ 2026-05-23

CRITICAL LINEAGE_BROKEN (데이터셋)
         '데이터셋' 칸이 비어 있다. 여기서 사슬이 끊기면 그 위로는 못 올라간다.
```

학습까지는 되짚어 갔는데 거기서 멈춘다.
**빈 칸을 숨기지 않는다** — `(끊김)` 이라고 적는다.

## 여섯 모듈이 한 바퀴를 돈다

```text
모듈 1·2    현장 데이터를 검증하고 품질을 판정한다
모듈 3      모델을 학습하고 승인한다
모듈 4      디바이스에 올릴 수 있게 바꾸고 고른다
모듈 5      배포하고 지켜보다 재학습이 필요하다고 판단한다
모듈 6-1~3  현장 데이터를 클라우드로 올린다
모듈 6-4    그것으로 다시 학습 데이터를 만든다   ← **모듈 1 로 돌아간다**
모듈 6-5~9  클라우드에서 학습하고 현장으로 내보낸다
```

모듈 5-11 의 `RetrainingRequested` 가 이 순환의 시작 신호였고,
여기 계보가 **그것이 실제로 돌았다는 증거**다.

## 자기 데이터가 학습에 안 들어간 디바이스

```text
INFO LINEAGE_SELF_EXCLUDED (DEV-00)
     'DEV-00' 는 이 모델의 학습 데이터에 들어가지 않았다.
     **틀린 것은 아니다** — 격리됐거나 나중에 설치된 디바이스일 수 있다.
     다만 그 사실을 알고 있어야 한다.
```

INFO 다 — 막지 않는다.
그런데 **그 디바이스에서 이상이 나면 이것이 첫 번째 단서다.**

## 버전 이름은 있는데 그 위가 없다

```text
    디바이스            DEV-20
  ↑ 릴리스             v1.0.0
  ↑ 학습              (끊김)
  ↑ 데이터셋            (끊김)
```

`v1.0.0` 은 이 플릿에 **등록된 적이 없는** 버전이다 — 공장 초기 이미지로 깔려 나왔다.

현장에서 실제로 이렇다. 초기 이미지는 대개 추적이 안 된다.
**그 사실을 아는 것과 모르는 것이 다르다.**

## 계보는 기록해 둔 만큼만 있다

사슬은 세 곳에 나뉘어 저장된다.

```text
manifest.json (S3)      구간·디바이스·제외 이유       ← 6-4 에서 남긴다
ReleaseBundle           source_build_id / job_id      ← 6-6 에서 붙인다
Fleet._lineage          릴리스 → (build, job)         ← 6-6 등록 때 기록된다
Device.current_version  디바이스 → 릴리스             ← 6-3 에서 디바이스가 보고한다
```

**네 곳 중 하나라도 안 남기면 거기서 끊긴다.**
그래서 6-4 는 이유 없는 제외를 막고, 6-6 은 계보 없는 릴리스를 막는다.

## API

```http
POST /fleets/line3/devices/DEV-00/lineage
{
  "source_devices": ["DEV-00", "DEV-01", "…"],
  "window": "2026-05-22 00:00:00 ~ 2026-05-23 23:59:59"
}
```

## 자주 하는 실수

- **모델 파일만 관리한다.** 어디서 왔는지가 안 남는다.
- **빈 칸을 채워 넣는다.** 모르는 것을 아는 척하면 더 나쁘다.
- **초기 이미지를 추적 대상에서 뺀다.** 그 디바이스만 설명이 안 된다.
- **계보를 나중에 만들려 한다.** 지나간 기록은 다시 안 생긴다.
