# 6-6. Cloud에서 만든 모델을 Edge로 보내라

## 문제

모듈 5 에서 배웠다 — **결과물 파일만 보내면 조용히 다른 모델이 된다.**

수천 대에 보낼 때는 거기에 두 가지가 더 붙는다.

```text
체크섬   좁은 회선에서 잘려 도착한 파일을 알아채기 위해
크기     **한 대 크기 × 대수**가 전송 예산에 맞는지
```

그래서 **릴리스는 파일이 아니라 묶음(bundle)이다.**

## 실습

```bash
pytest -m lesson_6_6 -s
```

## 묶음에 들어 있는 것

```text
결과물     s3://ondevice-ai-artifacts/v2.0.0/model.tflite (11,724B)
체크섬     deadbeefdeadbeef…
전처리     정규화 1채널, 표본 간격 10초, 창 30
기준       p95 0.0031ms, 예측 분포 3클래스
계보       build-2026-05-24 / train-2026-05-24
```

**모듈 5 의 `DeployedArtifactRef` 가 요구하던 것이 전부 들어 있다.**
다른 점은 회선을 건넌다는 것뿐이고, 그래서 체크섬과 크기가 붙는다.

## 전처리는 정규화 통계만이 아니다

```text
CRITICAL RELEASE_NO_PREPROCESSING
         전처리가 묶이지 않았다 — 정규화 통계나 표본 간격이 없다.
         **전처리는 모델의 일부다** (실습 5-1).
```

```python
@property
def has_preprocessing(self) -> bool:
    if not self.input_fields:
        return False
    return bool(self.normalization) and self.sample_interval_seconds > 0
```

표본 간격이 빠지면 어떻게 되는지는 모듈 5 에서 실제로 봤다.

```text
학습     10초 간격 × 30 표본 = 5분짜리 창
현장     30초 간격 × 30 표본 = 15분짜리 창
→ OVERLOAD 예측 비율 16.7% → 1.6%
```

입력 모양은 `(30, 6)` 으로 똑같고 오류도 안 난다.

## 한 대에 작은 것이 수천 대면 달라진다

```text
WARNING RELEASE_FLEET_TRANSFER_TOO_LARGE
        24대에 보내면 4.6MiB 가 나간다.
        **한 대 기준으로 보면 작아 보이는 것이 대수를 곱하면 달라진다.**
```

195KiB 는 작다. 3,000대면 572MiB 다 — 그건 회선 계획이 필요한 크기다.

```python
def fleet_transfer_kib(self, device_count: int) -> float:
    return self.artifact_kib * device_count
```

## 플래시 한도는 모듈 4 와 같은 숫자여야 한다

```text
CRITICAL RELEASE_TOO_LARGE
         디바이스 플래시에 안 들어간다.  [측정 585.9 / 기준 256]
```

`max_artifact_kib` 는 모듈 4 의 `DeviceBudget.storage_kib` 과 같아야 한다.
배포 전에 지킨 예산을 배포할 때 다른 숫자로 재면 **그 예산은 의미가 없다.**

## 계보가 없으면 6개월 뒤에 못 답한다

```text
CRITICAL RELEASE_NO_LINEAGE
         어느 학습 데이터셋에서 왔는지 없다.
         6개월 뒤 '이 모델 뭐로 만들었죠?'에 답할 수 없다.
```

`source_build_id` 와 `source_job_id` 한 줄씩이다.
그 두 줄이 [6-10](6-10.md) 의 사슬을 잇는다.

## 체크섬 없는 묶음은 만들 수도 없다

```python
if not self.checksum.strip():
    raise InvariantViolation(
        "체크섬이 없으면 잘려 도착한 파일을 알아챌 수 없다.", subject="checksum"
    )
```

디바이스가 **스스로 검증할 수 있어야 한다.**
그래서 OTA 문서에도 체크섬이 들어간다 ([6-8](6-8.md)).

## 같은 버전 이름으로 다른 내용

```text
[INVARIANT_VIOLATION] v2.0.0: 버전 'v2.0.0' 이 이미 있다.
    같은 버전 이름으로 다른 내용을 올리면 계보가 끊긴다.
```

현장에서 실제로 일어난다 — 급해서 같은 태그로 다시 빌드해 올린다.
그러면 `v2.0.0` 이 두 가지를 뜻하게 되고, 어느 디바이스가 무엇을 받았는지 모른다.

## 등록과 배포는 다른 일이다

```python
def publish(self, bundle, build_id="", job_id="") -> None:
    """릴리스를 이 플릿에 등록한다.

    등록만 한다. 아직 아무 디바이스에도 안 갔다 — 그것은 롤아웃의 일이다.
    """
```

등록은 즉시 끝나고, 배포는 며칠 걸린다 ([6-8](6-8.md)).

## API

```http
POST /fleets/line3/releases
{
  "bundle": {
    "version": "v2.0.0",
    "artifact_uri": "s3://.../model.tflite",
    "artifact_bytes": 11724,
    "checksum": "…",
    "normalization": {"active_power_kw": [147.8, 39.8]},
    "sample_interval_seconds": 10,
    "window_length": 30,
    "expected_p95_ms": 0.0031,
    "source_build_id": "build-2026-05-24"
  }
}
```

## 자주 하는 실수

- **모델 파일만 보낸다.** 전처리가 빠지면 다른 모델이 된다.
- **표본 간격을 안 보낸다.** 같은 30표본이 다른 시간을 덮는다.
- **한 대 크기만 본다.** 대수를 곱하면 회선 계획이 필요해진다.
- **같은 버전 이름을 다시 쓴다.** 계보가 끊긴다.
