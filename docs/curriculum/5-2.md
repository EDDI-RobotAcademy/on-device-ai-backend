# 5-2. 배포된 모델에 Version을 부여하라

## 문제

현장에서 실제로 나오는 질문은 이런 것들이다.

```text
"어제 3시에 3라인에서 돌던 게 뭐였죠?"
"그거 언제부터 돌았어요?"
"그 전 건요?"
```

**이 질문들은 배포 버전으로만 답할 수 있다.**

## 실습

```bash
pytest -m lesson_5_2 -s
```

## 세 가지 버전이 있고, 서로 다르다

```text
모델 버전  : mv-power-opt-cnn1d-s42          어떤 학습이 만든 가중치인가
결과물     : ...-tflite-fp32                 어떤 형식으로 바꿨는가
배포 버전  : v1                              언제 어디에 올라갔는가
```

같은 모델을 두 번 배포하면 모델 버전은 같고 배포 버전은 다르다.
같은 모델을 다른 라인에 올려도 배포 버전은 따로다.

`DeploymentVersion` 이 셋을 한 묶음으로 들고 있다.

```python
@dataclass(frozen=True, slots=True)
class DeploymentVersion:
    number: int
    artifact: DeployedArtifactRef   # 모델 버전 + 결과물 형식이 여기 들어 있다
    released_at: str
    note: str = ""
    rolled_back_from: int | None = None
```

## 그 시각에 무엇이 돌고 있었는가

```text
2026-05-21 03:00 → v1  (TFLITE/FP32)
2026-05-22 03:00 → v2  (TFLITE/INT8)
```

```python
def version_at(self, moment: str) -> DeploymentVersion | None:
    """그 시각에 돌고 있던 버전.

    **버전 번호를 되감지 않기 때문에 이 질문에 답할 수 있다.**
    """
    active = [v for v in self._versions if v.released_at <= moment]
    return active[-1] if active else None
```

이 한 줄이 되는 이유는 [5-10](5-10.md) 의 설계 결정 때문이다.
**롤백해도 번호가 줄지 않는다.** 번호를 되감으면 그 시간의 기록이 사라진다.

## 시각 없는 버전은 버전이 아니다

```python
if not self.released_at.strip():
    raise InvariantViolation(
        "언제 올라갔는지 없으면 '언제부터'에 답할 수 없다.",
        subject="released_at",
    )
```

"v2 가 돌고 있습니다" 는 절반짜리 답이다.
"v2 가 5월 21일 12시부터 돌고 있습니다" 가 답이다.

## 격리된 배포에는 새 버전을 올릴 수 없다

```text
[ILLEGAL_STATE_TRANSITION] dep-line3:
    격리 상태에서는 '새 버전 배포' 을 할 수 없다.
    원인을 확인해 resume 하거나, rollback 으로 되돌린 뒤에 한다.
```

멈춰 세운 상태에서 새 것을 밀어 넣으면 **무엇이 문제였는지 영영 모른다.**
이건 현장에서 실제로 자주 일어나는 일이다 — 급하니까 일단 새 버전을 올린다.

## 배포 이력은 사건 조사의 출발점이다

```text
2026-05-19 23:00:00  v1 배포 — mv-power-opt-cnn1d-s42 (TFLITE/FP32, 16,780B)
2026-05-21 12:00:00  v2 배포 — mv-power-opt-cnn1d-s42 (TFLITE/INT8, 9,512B)
2026-05-22 12:00:00  v3 배포 — mv-power-opt-cnn1d-s42 (ONNX/FP32, 14,169B)
2026-05-23 09:00:00  격리 — 입력 드리프트 확인
2026-05-23 10:00:00  v4 롤백 (v3 → v1 의 내용) — 여름 데이터 부재
```

**언제 무엇을 했는가**가 한 표에 있다.
사건이 났을 때 사람들이 가장 먼저 찾는 것이 이 표다.

## 한 대와 수천 대는 다른 일이다

```python
class TargetKind(Enum):
    DEVICE = "DEVICE"              # 한 대. 파일럿.
    DEVICE_GROUP = "DEVICE_GROUP"  # 같은 조건의 몇 대. 단계적 배포의 첫 칸.
    FLEET = "FLEET"                # 전부. 여기에 바로 올리는 것을 5-9 가 막는다.
```

이 구분이 모듈 6 의 OTA 로 이어진다.
지금은 타입으로만 남겨 두고, 넓은 배포에 대한 경고(실습 5-1)에 쓴다.

## API

```http
POST /deployments/dep-line3/versions
{
  "optimization_run_id": "opt-power",
  "training_run_id": "run-opt",
  "artifact_label": "TFLITE/INT8",
  "note": "플래시가 모자라 INT8 로 교체",
  "released_at": "2026-05-21 12:00:00"
}

GET /deployments/dep-line3
```

조회 응답에 `versions` 와 `history` 가 함께 온다.

## 자주 하는 실수

- **모델 버전만 관리한다.** "같은 모델인데 언제 올라갔죠?"에 답할 수 없다.
- **배포 시각을 안 남긴다.** '언제부터'가 전부 추정이 된다.
- **롤백할 때 번호를 되감는다.** 그 시간의 기록이 사라진다 (실습 5-10).
- **격리 중에 새 버전을 밀어 넣는다.** 원인 분석이 불가능해진다.
