# 2-8. 데이터 품질을 감이 아니라 숫자로 측정하라

## 문제

> "데이터가 좀 지저분한 것 같은데요."
> "그럼 정리 좀 해 주세요."
> "얼마나요?"

이 대화는 끝나지 않는다. 공통 단위가 없기 때문이다.

## 실습

```bash
pytest -m lesson_2_8 -s
```

## 무엇을 보게 되는가

```text
품질 종합 (dirty) — 69.7 (D)

차원                    점수    등급  판정
--------------------------------------------------
BALANCE             97.1     A  PASSED_WITH_WARNINGS
COMPLETENESS        77.4     C  FAILED
LABEL_QUALITY       59.8     F  FAILED
NOISE               43.8     F  FAILED
UNIQUENESS          85.9     B  FAILED
VALIDITY            61.6     D  FAILED

학습 관점
  전체 8,640행 → 학습 가능 8,251행 (부풀림 1.05배)
    결측 포함 행 347 / 라벨 모순 113
    정확도 상한 96.61% / baseline 정확도 85.07% / 소수 클래스 180개
```

## 두 가지를 낸다

### 1. 종합 점수 — 대화를 시작하기 위한 공통 단위

축별 점수가 있어야 **무엇을 고칠지**가 나온다.
종합 점수만 있으면 "나쁘다"까지만 말할 수 있다.

가중치는 라벨 품질에 가장 무겁다.

```text
LABEL_QUALITY      25%
COMPLETENESS       20%
VALIDITY           20%
UNIQUENESS         15%
BALANCE            10%
NOISE              10%
```

다른 축은 고칠 수 있다. 정답이 틀린 데이터는 아무리 고쳐도 그 이상 좋아지지 않는다.

### 2. 학습 영향 — 점수를 표본 수 언어로 환산

**이것이 없으면 점수는 그냥 점수다.**

```text
"COMPLETENESS 77점"        → 회의에서 아무 일도 안 일어난다
"학습 가능 표본 8,640 → 8,251" → 사람들이 움직인다
```

```python
def estimate_training_impact(*, missing, duplicates, balance, labels) -> TrainingImpact:
    """네 축의 측정값을 '표본 수'라는 하나의 언어로 환산한다."""
```

| 지표 | 의미 |
|---|---|
| `usable_rows` | 중복과 모순을 걷어낸 실제 표본 수 |
| `inflation_ratio` | 표본 수가 몇 배로 부풀려져 보이는가 |
| `accuracy_ceiling` | 라벨 오류가 만든 정확도 천장 |
| `baseline_accuracy` | 아무것도 안 배우고 얻는 정확도 |
| `minority_count` | 소수 클래스 절대 개수 |

`baseline 85.07%` 와 `상한 96.61%` 사이가 **모델이 실제로 벌 수 있는 전부**다.
11.5%p. 그 폭이 이 데이터의 실제 가치다.

## 감점 공식은 설명할 수 있어야 한다

```text
measured <= tolerance  → 0점 감점
measured >= cap        → weight 전부 감점
그 사이                 → 선형 비례
```

```python
def deduct(measured: float, *, tolerance: float, cap: float, weight: float) -> float:
    if measured <= tolerance:
        return 0.0
    ratio = (measured - tolerance) / (cap - tolerance)
    return weight * min(ratio, 1.0)
```

**공식이 단순한 것은 의도다.**
점수가 왜 그렇게 나왔는지 설명할 수 없으면, 아무도 그 점수를 고치려 하지 않는다.

## 측정하지 않은 축은 0점이 아니다

```text
[한 축만 측정한 경우]
  종합 점수 : 100.0
  → 그런데 게이트는 막는다
```

'측정하지 않았다'와 '0점이다'는 다르다.
0점으로 처리하면 **왜 점수가 낮은지**가 뭉개진다.

```python
def overall_score(self, results) -> QualityScore:
    """측정된 축들의 가중 평균.

    측정하지 않은 축은 0점으로 치지 않는다. 그것은 별도의 차단 사유다.
    """
```

**점수는 대화를 위한 것이고, 차단은 게이트가 한다.** 둘을 섞지 않는다. → [2-10](2-10.md)

## 왜 점수를 낼 때 다시 측정하는가

`ScoreQuality` 는 네 축(결측·중복·균형·라벨)을 한 번 더 잰다.

각 축을 측정한 시점이 서로 다를 수 있기 때문이다.
학습 영향 환산은 **같은 시점의 값**으로 해야 의미가 있다.
(2-2 를 어제 재고 2-7 을 오늘 쟀다면, 그 둘을 더한 숫자는 어느 날의 데이터도 아니다)

## 자주 하는 실수

- **종합 점수 하나만 보고한다.** 무엇을 고칠지가 사라진다.
- **점수 공식을 복잡하게 만든다.** 정교해 보이지만 아무도 못 고친다.
- **점수를 목표로 삼는다.** 점수를 올리는 가장 쉬운 방법은 검사를 느슨하게 하는 것이다.
- **학습 영향 없이 점수만 낸다.** 현장에서 움직이지 않는다.
