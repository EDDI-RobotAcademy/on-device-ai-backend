# 1-4. 센서와 이미지는 거짓말을 어떻게 하는가?

## 문제

결측(NaN)은 눈에 보인다. 그래서 오히려 덜 위험하다.

센서는 **값을 비우면서** 거짓말하지 않는다.
**그럴듯한 값을 계속 뱉으면서** 거짓말한다.

- 케이블이 빠져도 마지막 값을 계속 유지한다 (고착)
- 측정 한계에 붙어 실제 값을 잘라먹는다 (포화)
- 물리적으로 불가능한 값을 정상처럼 기록한다 (범위 이탈)

이미지는 또 다르게 거짓말한다.

- 조명이 바뀌어 밝기 분포가 통째로 이동한다
- 초점이 나가 결함 자체가 화면에서 사라진다
- 같은 사진이 다른 이름으로 여러 장 들어온다

## 무엇을 보게 되는가 — 센서

```text
[SIGNAL_PLAUSIBILITY] FAILED  (raw)
  - WARNING  SIGNAL_SATURATED   (active_power_kw) 측정 한계에 붙어 실제 값이 잘려 있다.
                                                  [측정 0.03262 / 기준 0.02]
  - CRITICAL SIGNAL_OUT_OF_RANGE (current_a) 물리적으로 불가능한 값이 정상 표본처럼 기록되어 있다.
                                             [측정 0.002364 / 기준 0]
  - CRITICAL SIGNAL_STUCK        (voltage_v) 값이 600 표본 동안 변하지 않았다.
                                             센서 고착 또는 통신 두절을 의심한다.
                                             [측정 0.07092 / 기준 0.05]
```

전압이 **100분 동안** 정확히 `379.412` 였다.
이 구간의 데이터는 전부 존재하고, 전부 그럴듯하고, 전부 거짓이다.

## 세 거짓말의 무게가 다르다

| 결함 | 심각도 | 이유 |
|------|--------|------|
| 고착 (`STUCK`) | CRITICAL | 그 구간 **전체가** 거짓이다. 쓰면 안 된다 |
| 범위 이탈 (`OUT_OF_RANGE`) | CRITICAL | 단 한 건이라도 계측 신뢰성이 무너졌다는 신호다 |
| 포화 (`SATURATED`) | WARNING | 값은 남아 있되 **잘렸다**. 알고 쓰면 된다 |

포화를 CRITICAL 로 만들면 정상 운전 중 피크가 있는 라인은 영원히 학습을 못 한다.
반대로 고착을 WARNING 으로 두면 죽은 센서로 학습한다. 이 구분이 Policy 의 값이다.

## 어떻게 세는가

```python
# 고착: 값이 변하지 않고 이어진 최대 길이. NaN 은 연속을 끊는다.
_longest_constant_run(values)

# 포화: 관측 최대/최소값에 정확히 붙어 있는 표본 수 (극값 1회 등장은 제외)
_saturated_count(present)

# 범위 이탈: FieldSpec.value_range 를 벗어난 표본 수
(present < spec.value_range.minimum) | (present > spec.value_range.maximum)
```

정상 신호라면 최대값은 **한 번만** 나온다.
여러 번 나온다면 그 지점에서 값이 잘려 나갔다는 뜻이다.

## 무엇을 보게 되는가 — 이미지

```text
[SIGNAL_PLAUSIBILITY] FAILED  (castings)
  - CRITICAL SIGNAL_UNREADABLE       열리지 않는 이미지가 있다.        [0.0588 / 0]
  - CRITICAL SIGNAL_DEFOCUSED        초점이 나간 이미지가 6 장이다.    [0.1176 / 0.05]
  - WARNING  SIGNAL_EXPOSURE_SHIFT   밝기 산포가 크다.                 [41.21 / 40]
  - WARNING  SIGNAL_VISUAL_DUPLICATE 사실상 같은 이미지가 여러 장이다. [0.0784 / 0.02]
  - WARNING  SIGNAL_RESOLUTION_MIXED 해상도가 2 종류로 섞여 있다.      [2 / 1]
```

- 초점 점수는 **Laplacian 응답의 분산**이다. 경계가 뚜렷할수록 커진다.
- 중복은 **difference hash** 로 잡는다. 이웃 화소의 밝기 순서를 지문으로 삼는다.
- 중복 이미지는 분할 때 학습/평가에 나뉘어 들어가면 성능을 부풀린다. → 실습 1-8

## 측정과 판정의 분리

여기가 이 프로젝트 설계의 핵심이 가장 잘 보이는 지점이다.

```python
# Infrastructure — 점수만 넘긴다. "몇 장이 흐린가"를 세지 않는다.
ImageIntegrityMeasurement(focus_scores=(4.4, 512.0, 380.1, ...))

# Domain — 기준선은 Policy 가 갖는다.
policy.min_focus_score = 50.0
measurement.defocused_count(50.0)
```

흐림의 기준선은 현장마다 다르다. 카메라가 다르고, 결함 크기가 다르다.
측정기가 기준선을 알면, 라인마다 측정기를 새로 만들어야 한다.

테스트에서 이것을 직접 확인한다.

```python
관대 = SignalPlausibilityPolicy(min_focus_score=5.0)
엄격 = SignalPlausibilityPolicy(min_focus_score=50.0)
# 같은 측정값, 다른 판정
```

## 모달리티에 따라 측정기가 갈린다

```python
if modality is Modality.IMAGE:
    measurement = self._image_measurer.measure(dataset.source)
    report = command.policy.inspect_images(measurement)
else:
    measurements = self._sensor_measurer.measure(dataset.source, schema)
    report = command.policy.inspect_sensors(measurements)
```

이 분기는 기술 선택이 아니다.
**"센서와 이미지는 다르게 거짓말한다"**는 도메인 사실의 반영이다.

## 자주 하는 실수

- **결측만 처리하고 넘어간다.** `fillna()` 는 고착도 포화도 건드리지 못한다.
- **고착 구간을 평균으로 채운다.** 없는 데이터를 그럴듯하게 만드는 것은 더 나쁘다.
  못 믿을 구간은 **잘라내는** 것이 맞다.
- **이미지를 눈으로 몇 장만 본다.** 51장 중 3장이 깨져 있는 것은 눈으로 안 보인다.
