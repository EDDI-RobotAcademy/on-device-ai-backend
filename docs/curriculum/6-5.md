# 6-5. SageMaker에서 새로운 모델을 학습시켜라

## 문제

원격 학습은 로컬 학습(모듈 3)과 세 가지가 다르다.

```text
입력이 저장소에 있다
계산이 남의 기계에서 돈다
**언제 끝나는지 모른다**
```

세 번째가 결정적이다. `trainer.fit()` 은 돌아올 때까지 기다리면 됐다.
여기서는 기다릴 수 없다.

```text
Command → Job → Status → Result   (CLAUDE.md §11)
```

## 실습

```bash
pytest -m lesson_6_5 -s
```

## 이 세 줄이 곧 청구서다

```text
ml.m5.large × 1  최대 30분  최대 $0.07
ml.p3.8xlarge × 2  최대 240분  최대 $140.80
```

**학습 코드보다 이 세 줄을 먼저 본다.**
클라우드 학습에서 가장 흔한 사고는 정확도가 아니라 청구서다.

```python
@property
def worst_case_cost_usd(self) -> float:
    """최악의 경우 얼마인가. **평균이 아니라 상한을 본다.**"""
    return self.hourly_cost_usd * self.instance_count * (self.max_runtime_seconds / 3600)
```

## 예산을 넘으면 제출하지 않는다

```text
CRITICAL TRAIN_OVER_BUDGET
         최악의 경우 $563.20 다.
         최대 실행 시간을 줄이거나 기계를 낮춘다.
```

**제출한 뒤에 멈추면 이미 과금됐다.** 그래서 제출 자체를 안 한다.

```python
if any(f.severity is Severity.CRITICAL for f in findings):
    # 예산을 넘는 학습은 **제출하지 않는다.**
    return TrainingJobView.of(planned, ...)
```

## 비용은 AWS 응답에 없다

```text
WARNING TRAIN_NO_COST_ESTIMATE
        시간당 비용을 모른 채 제출하고 있다.
```

가격은 **우리 설정에서 온다.** 그래서 어댑터가 `describe()` 결과에 그것을 되살린다.

```python
# 비용 추정치는 **우리 설정에서 온다.** AWS 응답에는 가격이 없다.
return replace(self.describe(job_id), compute=compute)
```

## 상한이 곧 안전장치다

```text
WARNING TRAIN_RUNTIME_TOO_LONG
        최대 실행 시간이 너무 길다.
        **멈추지 않는 학습은 끝나지 않고 과금만 된다** — 상한이 곧 안전장치다.
```

`StoppingCondition.MaxRuntimeInSeconds` 는 선택이 아니다.
학습이 수렴하지 않아도 그 시각에는 멈춘다.

## 실패했는데 이유가 없으면 기록이 아니다

```python
if self.status is RemoteJobStatus.FAILED and not self.failure_reason.strip():
    raise InvariantViolation(
        "실패했는데 이유가 없다. 로그 어딘가에 있는 것은 없는 것과 같다.",
        subject="failure_reason",
    )
```

그래서 어댑터가 응답에 이유가 없으면 채워 넣는다.

```python
if status is RemoteJobStatus.FAILED and not failure:
    failure = f"{raw_status} (이유가 응답에 없다 — CloudWatch 로그를 확인한다)"
```

"CloudWatch 로그를 확인한다"라도 적혀 있어야 다음 사람이 찾아간다.

## 학습 성공과 쓸 만한 모델은 다르다

```text
CRITICAL TRAIN_METRIC_BELOW_FLOOR (macro_recall)
         'macro_recall' 가 기준 아래다. 이 결과물을 디바이스로 내보내지 않는다.
         [측정 0.71 / 기준 0.9]
```

SageMaker 는 **손실이 안 내려가도 Completed 라고 말한다.**
끝난 것과 잘된 것은 다르다.

```text
CRITICAL TRAIN_METRIC_MISSING
         'macro_recall' 지표가 결과에 없다.
         학습은 끝났는데 좋은지 나쁜지 말할 수 없다.
```

학습 컨테이너가 지표를 뱉는 형식을 정해 두는 것이 **학습 코드의 일부다.**

## 어댑터의 본체는 번역이다

```text
SageMaker            →  Domain
-----------------------------------------
InProgress           →  RUNNING
Completed            →  SUCCEEDED
Failed               →  FAILED
Stopped              →  STOPPED
ResourceConfig       →  ComputeSpec
ModelArtifacts       →  artifact_uri
FailureReason        →  failure_reason
```

`domain/fleet/training_job.py` 에는 **SageMaker 라는 단어가 없다.**
Vertex AI 든 사내 Kubernetes 든 같은 모양이기 때문이다.

## 실습 환경의 한계

moto 는 `create_training_job` 을 받으면 **즉시 Completed 로 만든다.**
실제 SageMaker 는 기계를 잡는 데만 몇 분이 걸린다.

그리고 `stop_training_job` 은 moto 에 **아예 없다.**

```python
def test_moto_에는_stop_training_job_이_없다(self, training) -> None:
    """**가짜의 한계를 숨기지 않는다.**"""
    with pytest.raises(NotImplementedError):
        training.stop("j2", "실습 확인")
```

가짜로 시험할 때는 **무엇이 시험되지 않았는지**를 아는 것이 그만큼 중요하다.

## 자주 하는 실수

- **기다린다.** 원격 학습은 몇 시간이다. 요청이 그것을 붙잡으면 안 된다.
- **비용을 안 적는다.** 예산 검사를 아예 못 한다.
- **MaxRuntime 을 안 건다.** 멈추지 않는 학습이 과금만 한다.
- **Completed 를 성공으로 읽는다.** 지표를 봐야 안다.
