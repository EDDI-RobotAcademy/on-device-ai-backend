# 3-6. Loss가 떨어지는 순간을 확인하라

## 문제

Loss 숫자 하나만 보면 아무것도 알 수 없다. **곡선의 모양**을 봐야 한다.

그런데 그 판단은 지금까지 **사람이 그래프를 눈으로 보고 하는 일**이었다.
눈으로 하면 사람마다 다르고, 기록에 남지 않는다.

그래서 규칙으로 만든다.

## 실습

```bash
pytest -m lesson_3_6 -s
```

## 무엇을 보게 되는가

```text
 epoch   train_loss    val_loss   train_acc   val_acc      gap
--------------------------------------------------------------
     1       0.7039      0.3636       0.744     0.887   -0.143
     2       0.2953      0.2082       0.883     0.892   -0.009
     3       0.1995      0.1122       0.918     0.969   -0.051
     ...
     9       0.1228      0.0595       0.950     0.985   -0.034  ← best
    10       0.1037      0.0617       0.954     0.974   -0.021

  학습 손실 감소 85.3% / 최저점 epoch 9 / 일반화 격차 -0.021
```

학습 손실이 85.3% 떨어졌다. **이 숫자가 0 에 가까우면 모델은 아무것도 배우지 않은 것이다.**

## 배우지 못하는 곡선

```text
8 epoch 동안 손실 1.10 그대로
→ CRITICAL LEARNING_LOSS_FLAT
   학습 손실이 0.0% 밖에 떨어지지 않았다.
   learning rate, 입력 정규화, 라벨 연결을 먼저 의심한다.
```

원인은 대개 셋이다.

| 의심 | 확인 방법 |
|---|---|
| learning rate 가 너무 작거나 크다 | 10배씩 바꿔 본다 |
| 입력이 정규화되지 않았다 | 실습 3-1 의 `feature_mean/std` 를 본다 |
| 라벨이 입력과 연결되지 않았다 | 창 라벨 규칙(실습 3-4)을 다시 본다 |

**모델 구조를 먼저 바꾸는 것은 대개 틀린 순서다.**

## 손실이 떨어져도 배운 것이 아닐 수 있다

이것이 이 실습에서 가장 중요한 장면이다.

```text
epoch 1  loss 1.10  →  acc 0.744
epoch 2  loss 0.60  →  acc 0.744
epoch 3  loss 0.40  →  acc 0.750

CRITICAL LEARNING_NO_BETTER_THAN_BASELINE
         검증 정확도 75.0% 가 다수 클래스만 찍는 74.4% 보다
         의미 있게 낫지 않다.
```

**손실은 1.10 → 0.40 으로 잘 떨어졌다.**
그런데 정확도는 다수 클래스 비율 그대로다.

모델은 "전부 NORMAL 이라고 말하는 법"을 배웠을 뿐이다.
손실이 떨어진 것은 그 확신이 세졌기 때문이다.

실습 2-5 에서 봤던 `baseline_accuracy` 가 여기서 다시 나온다.
**손실 곡선만 보면 이 실패가 안 보인다.**

## 우리 모델은 넘었는가

```text
모델 정확도 : 0.974
baseline    : 0.744
실제로 번 것: +0.231
```

23%p. 이것이 이 모델이 실제로 만들어 낸 값이다.

## 최저점 이후로 더 돈 횟수

```python
@property
def wasted_epochs(self) -> int:
    """최저점 이후로 더 돈 횟수. 외우는 데 쓴 시간이다."""
```

```text
WARNING LEARNING_WASTED_EPOCHS
        최저점(epoch 2) 이후 8 epoch 을 더 돌았다.
        조기 종료를 걸면 그만큼의 시간과 과적합을 아낀다.
```

시간만 낭비한 것이 아니다. **그 시간에 모델은 외우고 있었다.** → [3-7](3-7.md)

## 곡선의 판단은 파일 없이 이루어진다

```python
curve = TrainingCurve(records=(
    EpochRecord(1, 1.0, 1.0, 0.4, 0.4),
    EpochRecord(2, 0.2, 0.25, 0.9, 0.88),
))
assert curve.train_loss_drop == pytest.approx(0.8)
assert curve.best_epoch.epoch == 2
```

숫자만 있으면 판단할 수 있다. 그래서 이 테스트는 **0.001초**에 끝난다.
torch 도 pandas 도 파일도 부르지 않는다.

이것이 "측정은 Infrastructure, 판정은 Domain"을 모듈 3 에서 지킨 결과다.

## 자주 하는 실수

- **loss 만 보고 "학습됐다"고 판단한다.** baseline 을 함께 봐야 한다.
- **곡선을 눈으로만 본다.** 기록에 남지 않고, 사람마다 다르게 읽는다.
- **loss 가 안 떨어지면 모델을 키운다.** 대개 원인은 데이터 쪽이다.
