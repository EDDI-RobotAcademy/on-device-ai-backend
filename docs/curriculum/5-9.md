# 5-9. 새 모델과 기존 모델을 실제 데이터로 비교하라

## 문제

오프라인 평가에서 새 모델이 더 좋았다. 그래서 배포한다?

**아니다.** 오프라인 평가는 학습 때 모아 둔 데이터로 한 것이다.
현장은 그 데이터가 아니다 — **모듈 5 전체가 그 사실 위에 서 있었다.**

## 실습

```bash
pytest -m lesson_5_9 -s
```

## 같은 입력을 둘 다에게 넣는다

```text
그림자 비교 — 비교 창 (8,640건)
------------------------------------------------------------------
                  …n1d-s42-tflite-fp16  …n1d-s42-tflite-int8
  p95(ms)                        0.075                 0.031
  FAULT                            341                   341
  NORMAL                         6,980                 5,765
  OVERLOAD                       1,319                 2,534
------------------------------------------------------------------
  답이 같았던 비율 : 85.9% (1,222건에서 갈렸다)
  정답 붙은 1,047건 기준 정확도 : 0.7287 → 0.7956 (+0.0669)
```

**새 모델의 답은 쓰지 않았다.** 설비는 여전히 기존 모델의 답으로 움직였다.
새 모델은 옆에서 같은 입력을 받아 답만 남겼다.

이것을 shadow(그림자) 또는 canary 라고 부른다.

## 다르다와 낫다는 다른 말이다

**이 실습에서 정직해야 하는 지점이다.**

```text
답이 갈린 비율   : 14.1%     ← 정답 없이도 안다
정답 붙은 표본   : 1,047건
차이             : +0.0669   ← **정답이 있어야 안다**
```

```python
@property
def accuracy_gain(self) -> float | None:
    """정답이 있을 때만 답할 수 있다."""
    if not self.labeled_count:
        return None
    return (self.candidate_correct - self.incumbent_correct) / self.labeled_count
```

라벨이 없으면 이 비교는 "다르다"까지만 답한다.

```text
CRITICAL SHADOW_NO_LABELS
         정답이 붙은 표본이 하나도 없다.
         두 모델이 **다르다**는 것만 확인했지
         어느 쪽이 **낫다**는 것은 확인하지 못했다.
```

그것을 "낫다"로 바꿔 읽는 순간, **근거 없는 배포**가 된다.

## 이 실습이 실제로 찾아낸 것

이 데이터에서 나온 결과가 흥미롭다.

```text
모듈 4 가 고른 것   TFLITE/FP16   (PC 벤치마크에서 가장 빠르고 작았다)
그림자 비교 결과    TFLITE/INT8   가 현장에서 6.7%p 더 정확하고 2.4배 빠르다
```

모듈 4 는 INT8 을 고르지 않았다. PC 에서 더 느렸기 때문이다([4-8](4-8.md)).
그런데 **드리프트한 현장 데이터에서는 INT8 쪽이 낫게 나왔다.**

왜인지는 이 표만으로 단정할 수 없다.
INT8 의 보정 범위(calibration range)가 학습 데이터에서 왔으니,
범위를 벗어난 입력이 그 범위로 잘려 들어간 것이 도움이 됐을 **가능성**이 있다.
확인하려면 갈린 1,222건을 직접 봐야 한다.

중요한 것은 이것이다.
**오프라인 평가와 현장 비교의 결론이 다를 수 있고, 그건 재 봐야만 안다.**

## 한나절은 돌려 봐야 한다

```text
CRITICAL SHADOW_TOO_FEW_SAMPLES
         40건으로 판단하고 있다.
         현장 조건은 시간대마다 다르다 — 한나절은 돌려 봐야 한다.
```

야간 교대, 제품 전환, 온도 변화 — 하루가 다 다르다.
40건에서 새 모델이 4건 더 맞았다면 그 4건은 우연일 수 있다.

## 정확도를 얻고 사이클을 잃는 거래

```text
CRITICAL SHADOW_SLOWER
         새 모델이 2.80배 느리다.
         정확도를 조금 얻고 사이클 타임을 잃는 거래일 수 있다.
```

정확도가 올랐다고 무조건 갈아타지 않는다.
**모듈 4 의 예산을 다시 확인해야 하는 상황**이다.

## 답이 갈리는 것 자체는 나쁜 게 아니다

```text
WARNING SHADOW_HIGH_DISAGREEMENT
        두 모델의 답이 1,100건에서 갈렸다.
        그 자체가 나쁜 것은 아니지만, 갈린 건들을 사람이 봐야 한다.
```

22% 에서 갈렸는데 새 모델이 60건 더 맞았다면,
**갈렸다는 것은 나아졌다는 뜻**이다.

그래서 이건 WARNING 이다 — 막지는 않되, 갈린 건들이 곧 다음 라벨링 대상이다.

## 그림자 실행기가 없으면 비교가 아니다

```text
[UNSUPPORTED_OPERATION] shadow:
    그림자 실행기가 조립되지 않았다.
    비교하려면 새 결과물을 실제로 돌릴 수 있어야 한다.
```

숫자만 비교하는 것은 오프라인 평가와 같다.
**새 모델이 같은 현장 입력을 실제로 받아야** 이 비교가 성립한다.

## 승격 판정도 판정이다

```python
@dataclass(frozen=True, slots=True)
class PromotionPolicy:
    min_sample_count: int = 500
    min_labeled_count: int = 100
    min_accuracy_gain: float = 0.0
    max_slowdown_ratio: float = 1.2
    require_labels: bool = True   # **기본은 정답 없이 승격 불가**
```

모듈 1~4 의 게이트와 같은 모양이다 — 측정 → 판정 → 근거가 붙은 판정서.

## 자주 하는 실수

- **오프라인 평가 결과로 배포를 결정한다.** 현장은 그 데이터가 아니다.
- **정답 없이 "더 낫다"고 말한다.** 확인한 것은 "다르다"까지다.
- **한 시간 돌려 보고 결정한다.** 하루가 다 다르다.
- **정확도만 보고 갈아탄다.** 사이클 타임을 잃을 수 있다.
