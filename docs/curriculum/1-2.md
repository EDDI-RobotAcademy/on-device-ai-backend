# 1-2. CSV 하나에도 현장의 문제가 숨어 있다

## 문제

실습 1-1 에서 전류 최소값이 `-2.813` 인 것을 봤다.
그런데 그것이 문제라는 사실을 **누가 알려줬는가?**

데이터는 아무 말도 하지 않았다. "전류는 음수가 될 수 없다"는 지식은
파일이 아니라 설비 사양서에서 온다.

계약이 없으면 배신도 없다.
문제를 찾으려면 **먼저 계약을 세워야 한다.**

## 실습

```bash
pytest -m lesson_1_2 -s
```

## 무엇을 보게 되는가

```text
[SCHEMA] FAILED  (raw)
  - CRITICAL BELOW_PHYSICAL_RANGE (current_a) 물리적으로 불가능한 최소값이 존재한다.
                                              [측정 -2.813 / 기준 0]
  - WARNING UNDECLARED_FIELD (operator_note) 파일에는 있으나 스키마가 모르는 열이다.
```

그리고 **물리 범위를 뺀 스키마**로 같은 파일을 검사하면:

```text
[SCHEMA] PASSED_WITH_WARNINGS  (raw)
  - WARNING UNDECLARED_FIELD (operator_note) ...
```

전류 -2.813A 가 그대로 통과한다.
**데이터는 여전히 아무 말도 하지 않는다.** 말해 주는 것은 사양서다.

## Finding 의 형태

이 실습의 핵심 산출물은 `Finding` 이다.

```python
Finding(
    code="BELOW_PHYSICAL_RANGE",
    message="물리적으로 불가능한 최소값이 존재한다.",
    severity=Severity.CRITICAL,
    subject="current_a",
    measured=-2.813,
    threshold=0.0,
)
```

"이상하다"가 아니라 **"무엇이 얼마여서 기준 얼마를 넘었다"**까지 적는다.
숫자가 없는 Finding 은 현장에서 아무도 신뢰하지 않고, 아무도 고칠 수 없다.

## 심각도의 무게

| 심각도 | 의미 | 학습 진행 |
|--------|------|-----------|
| `CRITICAL` | 이 상태로 학습하면 모델이 아니라 현장이 대가를 치른다 | 막는다 |
| `WARNING` | 지금 학습해도 되지만, 이 사실을 알고 있어야 한다 | 막지 않는다 |
| `INFO` | 확인이 필요한 설계 선택 | 막지 않는다 |

`operator_note` 는 학습을 막을 이유가 아니다.
다만 **의미를 모르는 열을 학습에 넣으면 안 된다**는 것을 기록해 둔다.

## 판정은 저장하지 않는다

```python
@property
def verdict(self) -> Verdict:
    if any(f.severity is Severity.CRITICAL for f in self.findings):
        return Verdict.FAILED
    ...
```

`InspectionReport.verdict` 는 필드가 아니라 `findings` 에서 유도된다.
누군가 `report.verdict = PASSED` 로 덮어쓰는 경로 자체가 존재하지 않는다.

현장에서 검사 결과를 "일단 통과로 바꿔 놓는" 일은 실제로 일어난다.
구조로 막지 않으면 반드시 일어난다.

## 선언은 막지 않는다

`declare_schema()` 는 불일치가 있어도 **선언 자체를 거부하지 않는다.**
불일치는 `CRITICAL` Finding 으로 남고, 학습 착수 판정(실습 1-10)에서 차단된다.

문제를 숨기지 않고 드러내되, 진행을 억지로 막지도 않는다.
막는 지점은 한 곳(판정)이어야 추적이 가능하다.

## 같은 계약, 다른 파일

```text
plant_power_curated.csv 에 같은 스키마를 적용
[SCHEMA] PASSED  (curated)
  - (지적 사항 없음)
```

문제는 스키마가 아니라 데이터에 있었다.
이것을 확인하지 않으면 "스키마가 너무 빡센 것 아닌가"로 논쟁이 흘러간다.

## 자주 하는 실수

- **물리 범위를 안 적는다.** 가장 흔하다. 그러면 이 실습의 검사는 아무것도 잡지 못한다.
- **모르는 열을 일단 학습에 넣는다.** `operator_note` 같은 열이 우연히 라벨과 상관되면
  검증 점수가 올라가고, 현장에서 무너진다.
- **불일치를 발견하고 스키마를 데이터에 맞춰 고친다.** 방향이 반대다.
  스키마는 현장이 정하고, 데이터가 그것을 못 지킨 것이다.
