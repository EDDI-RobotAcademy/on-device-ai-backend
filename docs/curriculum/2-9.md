# 2-9. 망가진 데이터와 정상 데이터를 직접 비교하라

## 문제

> "데이터 정리했습니다. 훨씬 좋아졌어요."

이건 근거가 아니다. 근거는 다음 형태여야 한다.

## 실습

```bash
pytest -m lesson_2_9 -s
```

## 무엇을 보게 되는가

```text
품질 비교: 조치 전(dirty) → 조치 후(clean)

차원                 before    after    delta
-------------------------------------------
BALANCE              97.1     95.9     -1.2
COMPLETENESS         77.4    100.0    +22.6
LABEL_QUALITY        59.8    100.0    +40.2
NOISE                43.8    100.0    +56.2
UNIQUENESS           85.9    100.0    +14.1
VALIDITY             61.6     97.5    +36.0
-------------------------------------------
종합                  69.7     99.1    +29.4

학습 관점
  before : 전체 8,640행 → 학습 가능 8,251행 (부풀림 1.05배)
           정확도 상한 96.61% / baseline 85.07% / 소수 클래스 180개
  after  : 전체 8,640행 → 학습 가능 8,640행 (부풀림 1.00배)
           정확도 상한 100.00% / baseline 85.65% / 소수 클래스 150개

나빠진 축: BALANCE
```

## 이 실습에서 가장 중요한 장면

**BALANCE 만 점수가 내려갔다.**

```text
소수 클래스(FAULT) : 180 → 150
BALANCE 점수       : 97.1 → 95.9
```

왜인가. **라벨 오류가 FAULT 를 180건으로 부풀리고 있었다.**
FAULT 가 아닌 30건이 FAULT 로 잘못 붙어 있었고, 정정하니 실제 값인 150건이 드러났다.

> **나빠진 것이 아니라, 부풀려져 있던 것이 드러난 것이다.**

품질을 고치면 어떤 지표는 나빠 보인다.
그 방향을 뒤집으려 하면 안 된다 — 그러면 다시 오염시키는 것이다.

이걸 모르면 이런 대화가 나온다.

> "데이터 정리했더니 불량 데이터가 줄었는데요? 정리를 잘못한 거 아닌가요?"

## 학습 관점의 변화를 함께 본다

점수만 비교하면 "올랐다"로 끝난다. 무엇을 얻었는지는 여기서 나온다.

| | before | after | 의미 |
|---|---|---|---|
| 학습 가능 표본 | 8,251 | 8,640 | 중복·모순이 사라졌다 |
| 라벨 모순 | 113 | 0 | 모델이 배울 수 없던 것이 없어졌다 |
| 정확도 상한 | 96.61% | 100.00% | 천장이 사라졌다 |
| 결측 포함 행 | 347 | 0 | |

정확도 상한이 96.6% → 100% 로 올랐다는 것은,
**같은 모델을 학습시켜도 3.4%p 를 더 벌 수 있게 되었다**는 뜻이다.
이 숫자가 데이터 정리 작업의 가치다.

## 데이터를 고쳤다는 기록

```python
RemediationAction(
    kind=RemediationKind.EXCLUDE_SEGMENT,
    dimension=QualityDimension.COMPLETENESS,
    target="temperature_c / LOT 3개 구간",
    affected_rows=259,
    rationale=(
        "결측이 3개 LOT 에 몰려 있어 보간하면 그 구간의 현실이 조작된다. "
        "해당 LOT 을 학습 대상에서 제외한다."
    ),
    decided_by="데이터팀 · 설비운영팀 합의 (2026-04-10)",
)
```

근거 없이는 생성되지 않는다.

```python
RemediationAction(..., rationale="", decided_by="데이터팀")
# InvariantViolation: 'IMPUTE' 조치의 근거가 없다.
#                     근거 없는 데이터 수정은 조작과 구분되지 않는다.
```

**데이터를 고치는 것은 되돌릴 수 없는 행위다.**
누가, 왜, 무엇을, 몇 행이나 고쳤는지가 남지 않으면
석 달 뒤 아무도 그 데이터를 검증할 수 없다.

### 이 Use Case 는 데이터를 고치지 않는다

**고쳤다는 사실을 기록할 뿐이다.**
실제 수정은 데이터 파이프라인이 하고, 여기에는 그 근거만 남는다.

## 측정하지 않은 축은 고칠 수 없다

```python
# UNIQUENESS 를 측정한 적 없이 중복 제거를 기록하려 하면
IllegalStateTransition: UNIQUENESS 를 측정하지 않은 채로 조치를 기록할 수 없다.
                        무엇을 고쳤는지 확인할 방법이 없다.
```

before 가 없으면 after 도 의미가 없다.

## 고쳤다는 주장은 재측정으로만 확인된다

현장에서 가장 흔한 사고 — **고쳤다고 하고 확인하지 않는 것.**

```text
조치 기록
  EXCLUDE_SEGMENT on temperature_c / LOT 3개 구간 (259행) — ... [데이터팀 · 설비운영팀]
  상태: REMEDIATING
  미검증 축: COMPLETENESS

→ 게이트 판정
  ✗ COMPLETENESS 에 조치를 기록했으나 재측정하지 않았다
```

조치를 기록한 축은 '미검증' 상태가 되고, **다시 측정해야 게이트를 통과할 수 있다.**

```python
def record_remediation(self, action: RemediationAction) -> None:
    ...
    self._unverified.add(action.dimension)
    self._status = AssessmentStatus.REMEDIATING

def record_dimension(self, result: DimensionResult) -> None:
    ...
    self._unverified.discard(result.dimension)   # 재측정하면 풀린다
```

이 규칙이 Aggregate 안에 있다는 점이 중요하다.
Application 이나 Route 에 두면, 그 경로를 지나지 않는 코드가 반드시 생긴다.

## 자주 하는 실수

- **"좋아졌다"로 보고한다.** 어느 축이 몇 점 올랐는지가 없으면 검증할 수 없다.
- **나빠진 축을 숨긴다.** BALANCE 하락은 정리가 잘못된 증거가 아니라 잘된 증거였다.
- **조치 근거를 커밋 메시지에만 남긴다.** 데이터를 보는 사람은 커밋을 보지 않는다.
- **고치고 재측정하지 않는다.** 이 프로젝트에서는 구조적으로 막혀 있다.
