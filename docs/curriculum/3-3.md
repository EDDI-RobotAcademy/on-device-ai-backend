# 3-3. 이미지를 숫자로 바꿔라

## 문제

이미지를 숫자로 바꾸는 일은 세 단계다.

```text
1. 크기 조정   96×96 과 128×128 이 섞여 있다 → 전부 64×64 로
2. 배열 변환   (H, W, C) uint8 → (C, H, W) float32
3. 정규화      채널마다 평균을 빼고 표준편차로 나눈다
```

셋 다 **학습과 배포에서 똑같아야 한다.** 하나라도 다르면 현장에서만 틀린다.
그래서 계약(`ImageTensorSpec`)으로 고정한다.

## 실습

```bash
pytest -m lesson_3_3 -s
```

## 무엇을 보게 되는가

```text
  all            48개  shape=(3, 64, 64)  min=-2.118 max= 2.640 mean= 0.457 std= 0.879
              ng 20  ok 28
```

실습 1-4 에서 봤던 그 이미지들이다. 해상도가 섞여 있었고, 3장은 깨져 있었다.

```python
assert summaries["unreadable"].sample_count == 3
```

**51장 중 3장은 열리지 않는다.**
여기서 세어 두지 않으면 "48장으로 학습했다"는 사실이 어디에도 남지 않는다.

## 정규화 전후

```text
전 : min= 0.000 max= 1.000 mean= 0.573
후 : min=-2.118 max= 2.640 mean= 0.457
```

0~1 이던 값이 0 근처로 옮겨졌다.
이 `mean/std` 는 **배포할 때도 똑같은 값**을 써야 한다.

```python
@dataclass(frozen=True, slots=True)
class ImageTensorSpec:
    width: int
    height: int
    channels: int = 3
    mean: tuple[float, ...] = (0.485, 0.456, 0.406)
    std: tuple[float, ...] = (0.229, 0.224, 0.225)
```

기본값은 ImageNet 통계다. 그대로 쓸 수도 있고, 우리 데이터로 다시 뽑을 수도 있다.
**중요한 것은 어느 쪽이든 고정하고 기록하는 것이다.**

객체가 지키는 불변식:

```python
ImageTensorSpec(width=64, height=64, channels=1, mean=(0.5, 0.5, 0.5))
# InvariantViolation: 정규화 통계는 채널 수(1)와 개수가 같아야 한다.

ImageTensorSpec(width=64, height=64, std=(0.0, 0.2, 0.2))
# InvariantViolation: 표준편차가 0 이면 나눌 수 없다.
```

## 축 순서 — 가장 조용한 버그

```text
PyTorch    : (3, 224, 224)
TensorFlow : (224, 224, 3)
원소 수는 둘 다 150,528개로 같다.
```

**원소 수가 같아서 `reshape` 이 그냥 된다.**
그래서 축을 틀려도 에러가 안 나고, 모델은 조용히 이상한 것을 배운다.

이 실수는 모듈 4(ONNX/TFLite 변환)에서 다시 만난다.
PyTorch 모델을 TFLite 로 옮길 때 축 순서를 바꿔야 하는데,
바꾸지 않아도 변환은 성공하기 때문이다.

그래서 `TensorLayout` 을 명세에 넣는다 — 어느 관례를 쓰는지가 계약에 남는다.

```python
class TensorLayout(Enum):
    TIME_FIRST = "TIME_FIRST"      # (시간, 채널) — 시계열의 자연스러운 순서
    CHANNEL_FIRST = "CHANNEL_FIRST"  # (채널, ...) — PyTorch Conv 의 관례
    CHANNEL_LAST = "CHANNEL_LAST"    # (..., 채널) — TensorFlow / 이미지 라이브러리 관례
```

## 입력 크기와 연산량

```text
64×64   :      576,000 MACs
128×128 :    2,304,000 MACs  (4.0배)
```

**한 변을 2배로 하면 연산은 4배가 된다. 정확도는 4배가 되지 않는다.**

모듈 4 에서 "가장 빠른 모델이 아니라 가장 쓸 수 있는 모델"을 고를 때,
가장 먼저 검토하는 것이 입력 크기인 이유다.

## 실습 1-4 와의 연결

이미지 데이터에서 찾았던 결함들이 여기서 어떻게 되는지 확인한다.

| 실습 1-4 에서 찾은 것 | 3-3 에서 어떻게 되는가 |
|---|---|
| 깨진 파일 3장 | 건너뛰고 **세어 둔다** (48장으로 학습) |
| 해상도 2종류 | 크기 조정으로 흡수된다 |
| 초점 나간 6장 | **그대로 학습된다** — 크기 조정이 고쳐 주지 않는다 |
| 조명 바뀐 16장 | 정규화가 일부 흡수하지만 완전하지 않다 |
| 중복 4장 | **그대로 남는다** — 분할에서 새게 된다 (실습 3-8) |

**전처리는 품질 문제를 고쳐 주지 않는다.** 모듈 2 가 따로 있는 이유다.

## 자주 하는 실수

- **`transforms.Normalize` 의 mean/std 를 학습 때만 쓰고 배포에서 빠뜨린다.**
- **깨진 파일을 `try/except: pass` 로 넘긴다.** 몇 장으로 학습했는지 모르게 된다.
- **입력 크기를 정확도만 보고 키운다.** 연산량은 제곱으로 는다.
