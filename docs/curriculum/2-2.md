# 2-2. 결측치를 숨기면 AI가 대신 대가를 치른다

## 문제

결측률만 보면 아무것도 알 수 없다.

```text
3% 가 고르게 흩어져 있다   → 보간해도 된다
3% 가 한 구간에 몰려 있다   → 그 구간은 센서가 죽었다. 잘라내야 한다
3% 가 특정 LOT 에만 있다    → 그 LOT 의 수집 자체가 의심스럽다
```

같은 숫자, 다른 처방이다. 그런데 대부분의 파이프라인은 `df.isna().mean()` 하나만 본다.

그리고 가장 위험한 결측은 **결측률 0% 로 보이는 결측**이다.

## 실습

```bash
pytest -m lesson_2_2 -s
```

## 무엇을 보게 되는가

```text
[COMPLETENESS] 77.4 (C)  FAILED
  - WARNING  MISSING_RATIO_HIGH   (temperature_c) 비어 있는 값이 기준을 넘는다.
                                                  [측정 0.04016 / 기준 0.02]
  - CRITICAL MISSING_CONCENTRATED (temperature_c) 결측이 특정 구간/그룹에 몰려 있다.
                                                  [측정 0.7637 / 기준 0.6]
  - CRITICAL MISSING_HIDDEN       (temperature_c) 값 0.0 이 425 번 반복되는데
                                                  평균 연속 길이가 1.1 로 흩어져 있다.
                                                  [측정 0.04919 / 기준 0.01]
```

**26℃ 짜리 공장에 0℃ 가 425개 있다.**
그리고 그 0℃ 는 물리 범위(-20~120℃) 안이라 모듈 1의 범위 검사를 그대로 통과했다.

`fillna(0)` 한 줄이면 결측률은 0% 가 되고, 문제는 그대로 남는다.
아니, 더 나빠진다 — 이제 아무도 그것이 결측이었다는 사실을 모른다.

## 네 가지를 함께 잰다

| 측정 | 무엇을 드러내는가 |
|---|---|
| `missing_ratio` | 얼마나 비었나 |
| `longest_missing_run` | 연속으로 비었나 → 센서 단절 구간 |
| `concentration_ratio` | 특정 LOT 에 몰렸나 → 무작위 결측이 아니다 |
| `repeated_value` + `mean_run` | 누가 채워 넣었나 → 은폐된 결측 |

## 은폐 결측과 진짜 물리 상태를 가르는 법

`clean` 파일에도 `spindle_rpm = 0` 이 150개 있다. **설비가 실제로 멈춰 있었다.**
이것까지 잡으면 검사는 못 쓰는 도구가 된다.

가르는 기준은 **연속성**이다.

```text
fillna(0) 로 채운 값   → 원래 결측이 있던 자리에 흩어진다.  평균 연속 길이 1.1
설비 정지 중의 rpm=0   → 정지가 이어지는 동안 뭉친다.      평균 연속 길이 10.0
```

```python
def hidden_missing_suspected(self, max_scattered_run: float = 2.0) -> bool:
    return (
        self.repeated_value is not None
        and self.repeated_value_count > 0
        and self.repeated_value_mean_run < max_scattered_run
    )
```

측정기는 `평균 연속 길이`라는 숫자만 낸다.
'흩어졌다/뭉쳤다'의 기준선은 Policy 가 갖는다 — 라인마다 다를 수 있기 때문이다.

## 결측이 특정 LOT 에 몰렸다는 것

```text
상위 10% LOT 이 전체 결측의 76% 를 차지한다.
```

이것이 왜 CRITICAL 인가.

무작위 결측이면 평균으로 채워도 분포가 크게 바뀌지 않는다.
그런데 3개 LOT 에 몰려 있으면, **그 LOT 의 값이 다른 LOT 의 평균으로 채워진다.**
그 LOT 에서 무슨 일이 있었는지가 통째로 조작되는 것이다.

한 그룹의 최대 비중만 보면 이걸 놓친다. 현장에서 수집 문제는 보통
'한 곳'이 아니라 '몇 곳'에서 나기 때문이다. 그래서 **상위 10% 그룹의 몫**으로 잰다.

## 점수는 가장 나쁜 필드로 낸다

여섯 채널 중 하나가 못 쓰게 되면, 그 데이터는 그 채널을 못 쓴다.
평균을 내면 그 사실이 5/6 만큼 희석되어 사라진다.

```python
score=QualityScore.from_deductions([max(per_field.values(), default=0.0)])
```

## 어떻게 고칠 것인가

이 실습이 답을 주지는 않는다. 다만 선택지를 좁혀 준다.

| 상황 | 정당한 조치 |
|---|---|
| 흩어진 결측 | `IMPUTE` — 보간 |
| 연속 결측 구간 | `DROP_ROWS` / `EXCLUDE_SEGMENT` — 잘라낸다 |
| 특정 LOT 집중 | `EXCLUDE_SEGMENT` — 그 LOT 을 제외한다 |
| 은폐된 결측 | `RECOLLECT` 또는 원본 재확인 — 0 이 진짜인지부터 |

조치를 기록하는 방법은 [2-9](2-9.md) 에서 다룬다.

## 자주 하는 실수

- **`fillna(0)`.** 이 실습 전체가 그 한 줄에 대한 이야기다.
- **`fillna(mean)` 을 무조건 쓴다.** 결측이 몰려 있으면 그 구간을 조작하는 행위다.
- **결측률 하나만 보고 판단한다.** 패턴을 봐야 처방이 나온다.
- **0 이나 -999 를 결측 표식으로 쓰면서 문서화하지 않는다.**
