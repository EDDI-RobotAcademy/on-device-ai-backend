# 1-5. 시간축을 놓치면 현장을 잃는다

## 문제

시계열에서 행의 순서는 장식이 아니라 **데이터의 절반**이다.

- 타임스탬프가 뒤섞이면 "원인 → 결과"가 "결과 → 원인"이 된다.
- 같은 시각이 두 번 있으면 그 순간 설비가 두 대였다는 뜻이 된다.
- 10초 주기 데이터에 15분 구멍이 있으면, **그 구멍이 바로 사고 구간**인 경우가 많다.

pandas 는 이 중 어느 것도 알려주지 않는다.
`sort_values()` 한 줄이면 조용히 넘어간다.

## 실습

```bash
pytest -m lesson_1_5 -s
```

## 무엇을 보게 되는가

```text
[TIME_AXIS] FAILED  (raw)
  - CRITICAL TIME_OUT_OF_ORDER (timestamp) 29 개 행이 시간 역순이다.
                                           정렬로 덮으면 인과가 뒤집힌 채 학습된다.
  - CRITICAL TIME_DUPLICATED   (timestamp) 같은 시각이 40 번 중복된다.
                                           한 설비가 같은 순간에 두 값을 가질 수는 없다.
  - WARNING  TIME_GAP          (timestamp) 2 개 구간이 끊겼다. 가장 긴 공백은 910s 다.
                                           [측정 910 / 기준 30]
```

실습 1-1 에서 "181개가 사라졌다"고 했던 것의 정체가 여기서 드러난다.
15분짜리 공백 두 개다.

## 정렬은 문제를 해결하지 않는다

테스트가 직접 보여 준다.

```text
정렬 전후
  역순 행 수 : 29 → 0
  중복 시각  : 40 → 40
```

정렬이 지운 것은 **"순서가 틀렸다는 사실"**뿐이다.
데이터는 하나도 나아지지 않았고, 문제만 보이지 않게 되었다.

그래서 측정기는 **파일에 적힌 순서 그대로** 센다.

```python
# 1) 파일 순서 그대로의 차이 — 여기서 역순이 드러난다
deltas_written = as_written.diff()
out_of_order = int((deltas_written < 0).sum())

# 2) 정렬한 뒤의 차이 — 여기서 중복과 공백이 드러난다
ordered = as_written.sort_values()
```

두 관점이 모두 필요하다. 하나만 보면 절반을 놓친다.

## 결함은 서로 겹친다

심어 놓은 역순은 30쌍인데 측정값은 29다.
한 쌍이 중복 시각과 겹쳐서 역전이 성립하지 않았기 때문이다.

현장 데이터가 원래 그렇다. **결함은 독립적으로 나타나지 않는다.**
그래서 "정확히 30개"를 기대하는 검사는 현장에서 오작동한다.

## 커버리지 — 약속과 현실

```python
coverage_ratio = record_count / interval.expected_count(duration_seconds)
```

"10초 주기로 24시간"이라면 8,641개가 있어야 한다.
실제 8,460개 → 커버리지 97.9%.

기준을 95%로 두면 이 파일은 커버리지로는 통과한다.
공백은 `WARNING` 이고, 진행을 막는 것은 중복과 역순이다.
**모든 것을 CRITICAL 로 만들면 아무도 그 검사를 쓰지 않는다.**

## 수집 주기를 잘못 알고 있는 경우

```bash
# 1초 주기라고 알고 있었다면
[TIME_AXIS] ... TIME_INTERVAL_MISMATCH 약속 주기 1s 인데 실측 중앙 간격은 10s 다.
```

이런 착오는 흔하다. 설비 담당자와 데이터 담당자가 다른 문서를 보고 있다.
검사가 이것을 잡아 주면 회의 한 번이 줄어든다.

## 시간축이 없으면 이 검사를 요구할 수 없다

```python
if schema.time_index is None:
    raise UnsupportedOperation("시간축(TIME_INDEX)이 선언되지 않았다.")
```

시계열이 아니거나, 선언을 빠뜨린 것이다. 둘 다 사람이 확인해야 한다.
그래서 조용히 넘어가지 않고 멈춘다.

이것이 `TIME_AXIS` 가 기본 필수 검사 목록에 없는 이유이기도 하다.
이미지 데이터셋에는 요구할 수 없다. (→ 실습 1-10)

## 자주 하는 실수

- **읽자마자 정렬한다.** `pd.read_csv(...).sort_values('timestamp')` 가 반사적으로 나온다면
  이 실습을 다시 봐라.
- **중복 타임스탬프를 `drop_duplicates()` 로 지운다.** 왜 중복됐는지 모른 채 지우면,
  둘 중 어느 값이 진짜였는지 영원히 알 수 없다.
- **공백을 보간(interpolate)한다.** 설비가 멈춰 있던 15분을 매끄러운 곡선으로 채우면,
  모델은 "설비는 멈추지 않는다"를 배운다.
