# 1-10. 학습시키기 전에 데이터부터 검증하라

## 문제

앞의 아홉 실습에서 찾은 것을 모아 **단 하나의 질문**에 답한다.

> "이 데이터로 학습을 시작해도 되는가?"

이 판정은 감이 아니라 **재현 가능한 규칙**이어야 한다.
그래야 석 달 뒤 사고가 났을 때 "그때 왜 학습을 시작했나"를 설명할 수 있다.

## 실습

```bash
pytest -m lesson_1_10 -s
```

## 무엇을 보게 되는가 — 원본

```text
학습 착수 판정: FAILED  (raw)
수행한 검사: LABEL_SPACE, PARTITION, REPRESENTATIVENESS, SCHEMA,
             SIGNAL_PLAUSIBILITY, TIME_AXIS, TRAINING_SPEC
차단 사유:
  ✗ CRITICAL LABEL_UNDEFINED    (UNKNOWN)         정의된 클래스가 아니다.      [6]
  ✗ CRITICAL LABEL_DISAGREEMENT (condition)       작업자 판단이 갈린다.        [0.8811 / 0.9]
  ✗ CRITICAL BELOW_PHYSICAL_RANGE (current_a)     불가능한 최소값.             [-2.813 / 0]
  ✗ CRITICAL SIGNAL_STUCK       (voltage_v)       600 표본 동안 변하지 않았다. [0.0709 / 0.05]
  ✗ CRITICAL TIME_DUPLICATED    (timestamp)       같은 시각이 40 번 중복된다.  [0.0047 / 0]
  ✗ CRITICAL REPR_DISTRIBUTION_SHIFTED (temperature_c) 분포가 크게 다르다.    [12.43 / 0.25]
  ... (총 15건)
경고(진행은 가능):
  ! WARNING LABEL_IMBALANCED  (condition)        불균형이 크다.               [1385 / 10]
  ! WARNING UNDECLARED_FIELD  (operator_note)    스키마가 모르는 열이다.
  ! WARNING SIGNAL_SATURATED  (active_power_kw)  값이 잘려 있다.              [0.0326 / 0.02]
  ! WARNING TIME_GAP          (timestamp)        가장 긴 공백 910s.           [910 / 30]
```

아홉 개 실습에서 찾은 것이 **한 화면에 모인다.**
각 사유에 측정값과 기준이 붙어 있으므로, 무엇을 고쳐야 하는지가 명확하다.

## 무엇을 보게 되는가 — 정리본

```text
학습 착수 판정: PASSED_WITH_WARNINGS  (curated)
경고(진행은 가능):
  ! WARNING LABEL_IMBALANCED (condition) 클래스 불균형이 크다. [91.73 / 10]
```

경고가 남은 채로 통과했다.
클래스 불균형은 데이터를 고쳐서 없앨 문제가 아니라 **알고 대응할 문제**다.

## 검사하지 않은 것은 통과가 아니다

```text
학습 착수 판정: FAILED  (half)
누락된 검사: LABEL_SPACE, PARTITION, REPRESENTATIVENESS, SIGNAL_PLAUSIBILITY, ...
차단 사유:
  ✗ CRITICAL READINESS_INSPECTION_MISSING (PARTITION) PARTITION 검사를 수행하지 않았다.
```

**"검사하지 않았다"는 "문제 없다"가 아니다.**
이 원칙이 없으면 검사를 건너뛰는 것이 가장 빠른 통과 방법이 된다.

## 판정 기준은 현장이 정한다

같은 데이터, 다른 기준:

```text
경고 허용   : PASSED_WITH_WARNINGS
경고 불허   : FAILED  (차단 1건)
```

안전 관련 라인에서는 `allow_warnings=False` 로 조인다.
`ReadinessPolicy` 는 Value Object 이므로 라인마다, 프로젝트마다 다를 수 있다.

검사 목록도 마찬가지다.

```python
# 시계열: 기본 기준 + TIME_AXIS
required_kinds = DEFAULT_REQUIRED_KINDS | {InspectionKind.TIME_AXIS}
```

`TIME_AXIS` 가 기본값이 아닌 이유는 이미지 데이터셋에는 요구할 수 없기 때문이다.

## READY 인 데이터는 몰래 바뀌지 않는다

```python
container.inspect_time_axis().execute(...)
# IllegalStateTransition: READY 상태에서는 'TIME_AXIS 검사 기록' 을 할 수 없다.
#                         reopen(reason) 으로 판정을 되돌린 뒤 수정한다.
```

되돌리려면 **이유를 남겨야 한다.**

```python
dataset.reopen("전압 센서 교체 후 재수집분 반영")
# → status = INSPECTED, certificate = None
```

이 기록이 감사 근거가 된다.
"승인된 데이터를 조용히 수정하는 경로"가 없다는 것이 이 Aggregate 의 핵심 가치다.

## Aggregate 의 생명주기

```text
REGISTERED → PROFILED → DECLARED → INSPECTED → READY
                                          ↘ REJECTED
                                    ↖ reopen(reason)
```

각 전이가 무엇을 요구하는지는 코드에 박혀 있다.

- 열어보지도 않은 데이터에 스키마를 선언할 수 없다
- 스키마 없이 시간축/라벨/분할을 논할 수 없다
- 스키마조차 없는 Dataset 은 판정 대상이 아니다

## 모든 것이 이벤트로 남는다

```text
발행된 Domain Event
   1. DatasetRegistered
   2. DatasetProfiled
   3. DataSchemaDeclared
   4. InspectionRecorded
   ...
  15. DatasetCertifiedReady
```

운영 단계에서 "AI가 언제부터 이상해졌는지" 되짚으려면 이 기록이 필요하다.
관측 가능성은 나중에 붙이는 것이 아니라 **Architecture 단계부터** 있어야 한다. (CLAUDE.md §19)

## 모듈 2 와의 관계

이 판정은 모듈 2 의 **Data Quality Gate** 와 다르다.

| | 무엇을 묻는가 |
|---|---|
| **모듈 1 (여기)** | 데이터를 **이해했고 계약이 서 있는가** — 구조/시간/라벨/분할/대표성 |
| **모듈 2** | 그 데이터가 **얼마나 오염되었는가** — 결측/이상치/중복/노이즈/라벨오류 |

둘 다 통과해야 학습을 시작한다.
모듈 1 은 "이 데이터가 무엇인지 안다", 모듈 2 는 "이 데이터가 쓸 만하다"이다.

## 자주 하는 실수

- **판정 로직을 Application 이나 Route 에 쓴다.** `if len(errors) > 0` 이 라우트에 생기는 순간,
  같은 규칙이 세 군데로 복제되기 시작한다.
- **CRITICAL 하나 때문에 기준을 낮춘다.** 기준을 낮추는 것 자체는 정당할 수 있지만,
  **누가 언제 왜 낮췄는지**가 남아야 한다. `ReadinessPolicy` 를 코드로 관리하는 이유다.
- **판정을 한 번만 하고 잊는다.** 데이터가 늘어나면 다시 판정해야 한다.
  그래서 `reopen` 이 있다.

## 모듈 1 을 마치며

열 개의 실습이 하나의 Bounded Context 를 만들었다.

```text
domain/data/
├── dataset.py           Aggregate Root — 순서와 계약을 지킨다
├── source.py            어디서 왔는가
├── profile.py           무엇이 들어 있는가        (1-1)
├── schema.py            무엇을 의미하는가          (1-2, 1-3)
├── signal.py            값이 진짜인가              (1-4)
├── time_axis.py         순서가 맞는가              (1-5)
├── labeling.py          정답이 일관적인가          (1-6)
├── training_spec.py     모델이 먹을 수 있는가      (1-7)
├── partition.py         시험이 격리되었는가        (1-8)
├── representativeness.py 현실을 닮았는가           (1-9)
└── readiness.py         시작해도 되는가            (1-10)
```

교육 제목 하나마다 Domain 을 만들지 않았다. (CLAUDE.md §16)
열 개의 실습이 **하나의 문제**를 함께 다뤘을 뿐이다.
