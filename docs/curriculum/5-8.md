# 5-8. 문제가 발생하면 모델을 격리하라

## 문제

격리는 롤백이 아니다. **판단을 멈추는 것**이다.

```text
격리(quarantine)  이 모델의 판단을 더 이상 쓰지 않는다. 설비는 사람이 본다.
롤백(rollback)    이전 모델로 되돌린다 (실습 5-10)
```

## 왜 격리가 먼저인가

**이전 모델이 더 나으리라는 보장이 없다.**

입력이 변한 것이라면([5-7](5-7.md)) 이전 모델도 그 입력을 본 적이 없다.
v1 과 v3 가 같은 학습 데이터에서 나왔다면, 형식만 다를 뿐 배운 것은 같다.

> **모르는 상태에서 할 수 있는 가장 안전한 일은 멈추는 것이다.**

그리고 격리는 자동이어야 한다.
사람이 알아채고 결정하기까지 걸리는 시간 동안 불량이 계속 나가기 때문이다.

## 실습

```bash
pytest -m lesson_5_8 -s
```

## 사건에는 근거가 붙는다

```text
[INPUT_DRIFT] 05-23 16시 v1 — OPS_INPUT_DRIFT, OPS_INPUT_OUT_OF_RANGE, OPS_MULTI_FEATURE_DRIFT  (OPEN)
    WARNING  OPS_INPUT_DRIFT (temperature_c) ...
    CRITICAL OPS_INPUT_OUT_OF_RANGE (temperature_c) ...
    CRITICAL OPS_MULTI_FEATURE_DRIFT (05-23 16시) ...
```

```python
if not self.findings:
    raise InvariantViolation("근거 없는 사건은 기록하지 않는다.", subject="findings")
```

**소견이 사건의 본문이다.** "이상해서 멈췄습니다"는 기록이 아니다.

## 이유를 안 주면 관측에서 찾아 온다

```python
if not reason:
    watch = watch_for(self._watches, deployment.id)
    should, derived = command.policy.should_quarantine(watch.latest)
    if not should:
        raise ConflictingRequest("최근 관측에 격리할 근거가 없다. ...")
    reason = derived
```

사람이 이유를 지어내는 것보다 기계가 근거를 붙이는 편이 정확하다.

근거가 없으면 **409** 다.

```text
최근 관측에 격리할 근거가 없다. 그래도 멈추려면 이유를 직접 적어야 한다.
```

현장 판단을 끄는 것은 기록으로 남는 결정이다.

## 한 창으로 멈출 것인가, 지속을 확인할 것인가

**이 실습에서 실제로 어려운 결정이다.**

```text
한 창만 보면      05-21 08시 에 멈춘다   (스파이크 — 헛알람)
3창 연속을 기다리면 05-22 00시 에 멈춘다   (진짜 — 하루 늦다)
```

| | 빨리 멈추면 | 기다리면 |
|---|---|---|
| 비용 | 헛알람으로 라인을 세운다 | 그동안 불량이 나간다 |

**둘 다 비용이 있다.** 그 비용을 아는 사람이 기준을 정한다.

그래서 `IncidentPolicy` 는 상수가 아니라 **요청마다 바꿔 넣는 정책**이다.

```python
@dataclass(frozen=True, slots=True)
class IncidentPolicy:
    quarantine_on_critical: bool = True
    quarantine_on_warning_count: int = 4
```

지속 여부는 [5-4](5-4.md) 의 `FindOnset` 이 답한다.
**둘을 조합하는 것이 실무의 설계다.**

## 작은 이상이 여럿이면 큰 이상이다

```text
CRITICAL 이 하나라도 → 멈춘다
WARNING 이 4건 겹쳐도 → 멈춘다
```

```text
05-23 16시: 경고가 5건 겹쳤다 (OPS_LATENCY_REGRESSION; OPS_INPUT_DRIFT; ...).
작은 이상이 여럿이면 큰 이상이다.
```

각각은 "지켜보자" 수준인데 한 창에 다섯 개가 같이 나왔다면, 그건 다른 상황이다.

## 격리해도 모델은 그대로 있다

```text
배포 dep-line3  → QUARANTINED
  v1   2026-05-19 23:00:00  ...
  격리 사유: 05-23 16시: CRITICAL OPS_INPUT_OUT_OF_RANGE ...
```

버전은 그대로 v1 이다. **내리지도, 되돌리지도 않았다** — 쓰지 않을 뿐이다.

그리고 격리 중에는 새 버전을 밀어 넣을 수 없다.

```text
[ILLEGAL_STATE_TRANSITION] 격리 상태에서는 '새 버전 배포' 을 할 수 없다.
    원인을 확인해 resume 하거나, rollback 으로 되돌린 뒤에 한다.
```

급하다고 새 것을 올려 버리면 **무엇이 문제였는지 영영 모른다.**

## 원인을 확인해야 다시 켠다

```python
def resume(self, reason: str, occurred_at: str) -> None:
    if not reason.strip():
        raise InvariantViolation(
            "무엇을 확인했는지 없이 판단을 다시 켜지 않는다.", subject="reason"
        )
```

`"팬 교체 완료, 온도 정상 복귀 확인"` 은 기록이다.
`"다시 켬"` 은 기록이 아니다.

## 사건은 해결 방법과 함께 닫는다

```python
def resolved(self, resolution: str) -> Incident:
    if not resolution.strip():
        raise InvariantViolation(
            "무엇을 해서 끝났는지 없으면 같은 일이 또 일어난다.",
            subject="resolution",
        )
```

그 기록이 다음 사람의 출발점이다.
그리고 이 기록들이 쌓여 [5-11](5-11.md) 의 재학습 계획이 된다.

## 관측은 배포보다 오래 산다

이 Context 에 Aggregate 가 둘인 이유가 여기서 드러난다.

```text
Deployment    무엇이 어디에 올라가 있는가 — 결정
HealthWatch   그것을 지켜본 기록          — 사실
```

배포가 롤백되고 격리되고 내려가도, **"왜 그랬는가"는 남아야 한다.**
사건 기록은 HealthWatch 에 붙어 있고, 배포 상태와 무관하게 살아남는다.

## 자주 하는 실수

- **바로 롤백한다.** 이전 모델도 같은 입력을 본 적이 없다.
- **근거 없이 멈춘다.** 다음 사람이 왜 멈췄는지 모른다.
- **격리 중에 새 버전을 올린다.** 원인 분석이 불가능해진다.
- **사건을 이유 없이 닫는다.** 같은 일이 또 일어난다.
