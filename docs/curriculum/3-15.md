# 3-15. 데이터를 고치면 모델이 얼마나 달라지는가

## 문제

모듈 2 는 "이 데이터는 나쁘다"까지 말했다.
그런데 현장에서는 반드시 이 반문이 온다.

> "그래서 모델이 얼마나 나빠지는데요?"

품질 점수가 62점이라는 말로는 아무도 설득되지 않는다.

## 실습

```bash
pytest -m lesson_3_15 -s
```

## 시험지를 먼저 정한다

두 모델을 **같은 시험지**로 채점해야 한다.
그리고 그 시험지는 **두 학습 파일 어느 쪽과도 겹치지 않아야** 한다.

```text
plant_power_quality_dirty.csv    오염된 학습 데이터
plant_power_quality_clean.csv    정제된 학습 데이터
plant_power_quality_holdout.csv  ← 다른 날. 두 모델의 공통 시험지
```

정제된 파일의 일부로 채점하면 정제된 쪽이 자기 답안지를 본 셈이 된다.

## 게이트가 먼저 답을 알고 있었다

```text
Data Quality Gate (모듈 2)
  오염된 데이터 : FAILED
  정제된 데이터 : PASSED_WITH_WARNINGS
```

**학습을 돌리기 전에 이미 알 수 있었다.**
이 실습은 그 게이트를 **일부러 우회해서** 얼마나 나빠지는지를 재는 자리다 —
현장에서 이 우회를 하면 안 된다.

## 결과

```text
시행                      accuracy   macroF1   recall     loss      표본
오염된 데이터                    0.807     0.762    0.925    0.257     192
정제된 데이터                    0.984     0.954    0.923    0.095     192  ←
```

같은 192개로 채점했다. macro F1 0.762 → 0.954.

> **"품질 점수 62점"보다 이 한 줄이 설득력이 있다.**

## 무너진 것은 정밀도다

```text
재현율   0.925 → 0.923   (거의 같다)
정확도   0.807 → 0.984
macroF1  0.762 → 0.954
```

**오염된 모델도 이상을 놓치지는 않는다.**
무너진 것은 정상을 이상이라고 부르는 쪽 — 즉 정밀도다.

현장에서는 이것이 "알람이 너무 많다"로 나타난다 ([5-13](5-13.md)).

## 데이터를 손잡이에 적었다

```python
TrialRequest("run-quality-dirty", "오염된 데이터", {"data": "dirty"}, split="holdout")
```

데이터가 서로 다른 실험이다. 적어 두지 않았으면
`EXP_DATA_DIFFERS` 가 떴을 것이다 ([3-14](3-14.md)).

## 이 표가 예산을 지킨다

라벨을 다시 붙이고 결측을 메우는 일은 지루하고 티가 안 난다.
**이 표가 그 작업의 예산을 지켜 준다.**

## 자주 하는 실수

- **정제된 데이터의 test 분할로 채점한다.** 그쪽이 유리해진다.
- **품질 점수로 설득한다.** 아무도 설득되지 않는다.
- **재현율만 본다.** 무너진 곳이 안 보인다.
