# 3-7. AI가 데이터를 외우기 시작하는 순간을 잡아라

## 문제

학습 손실은 계속 떨어지는데 검증 손실이 올라가기 시작하는 지점.
그 지점이 **모델이 패턴 대신 표본을 외우기 시작한 순간**이다.

그리고 중요한 것: 저장해야 할 모델은 **마지막이 아니라 그 지점의 것**이다.

## 실습

```bash
pytest -m lesson_3_7 -s
```

## 무엇을 보게 되는가

```text
 epoch   train_loss    val_loss   train_acc   val_acc      gap
--------------------------------------------------------------
     1       1.1000      1.0500       0.400     0.420   -0.020
     2       0.6000      0.5500       0.750     0.760   -0.010
     3       0.3500      0.3800       0.880     0.870    0.010
     4       0.2000      0.3400       0.930     0.890    0.040  ← best
     5       0.1200      0.3900       0.960     0.880    0.080
     6       0.0600      0.4700       0.990     0.870    0.120
     7       0.0200      0.5800       1.000     0.860    0.140
```

**epoch 5 부터 검증 손실이 올라간다. 학습 손실은 계속 떨어진다.**

모델은 계속 '좋아지고' 있는데, 새 데이터에 대해서는 나빠지고 있다.

## 세 가지 신호

```text
WARNING  OVERFIT_ONSET        epoch 5 부터 검증 손실이 다시 올라간다.
                              저장해야 할 모델은 마지막이 아니라 epoch 4 의 것이다.
CRITICAL OVERFIT_LOSS_RISING  검증 손실이 최저점 대비 70.6% 올라간 채로 끝났다.
CRITICAL OVERFIT_GAP_WIDE     학습 정확도 100.0% vs 검증 정확도 86.0%.
                              모델이 패턴이 아니라 표본을 외우고 있다.
```

마지막 epoch 의 일반화 격차는 `+0.14` — 학습 100%, 검증 86%.
**14%p 만큼을 외운 것이다.**

## 저장해야 할 모델은 마지막이 아니다

```text
어느 가중치를 저장할 것인가
  epoch 2 : val_loss 0.30  val_acc 0.90   ← 이것
  epoch 3 : val_loss 0.55  val_acc 0.84   (마지막)
```

**마지막 가중치를 그대로 배포하면 최고 성능을 6%p 버리는 것이다.**

이 프로젝트의 학습기는 최저점의 가중치를 따로 보관한다.

```python
# 가장 좋았던 가중치를 따로 보관한다. 마지막이 아니라 이것을 저장한다.
if validation_loss < best_loss - min_delta:
    best_loss = validation_loss
    best_state = {k: v.detach().clone() for k, v in module.state_dict().items()}
```

그리고 평가할 때 그것을 불러온다.

```python
module.load_state_dict(trained.best_state)  # 마지막이 아니라 최고 지점
```

이걸 안 하면 실습 3-9 의 혼동 행렬이 **마지막 epoch 의 성능**을 보여 준다.
그건 우리가 배포할 모델이 아니다.

    **외우는 시간을 벌어 주는 것**이다.

    patience: int = 5

## 건강한 곡선에는 아무 말도 하지 않는다

```python
healthy = curve_of([
    (1.0, 1.0, 0.4, 0.41),
    (0.5, 0.48, 0.8, 0.79),
    (0.3, 0.29, 0.9, 0.88),
])
assert healthy.overfitting_epoch is None
assert OverfittingPolicy().inspect(healthy) == ()
```

검증 손실이 계속 떨어지는 동안은 조용하다.
**모든 곡선에 경고를 내는 검사는 아무도 보지 않는다.**

## 우리 모델은 어땠는가

```text
학습 손실 감소 85.3% / 최저점 epoch 9 / 일반화 격차 -0.021
외우기 시작한 지점: epoch 10

WARNING OVERFIT_ONSET  epoch 10 부터 검증 손실이 다시 올라간다.
                       저장해야 할 모델은 마지막이 아니라 epoch 9 의 것이다.
```

10 epoch 짜리 학습에서 9 번째가 최저점이었다.
격차는 `-0.021` — 검증이 학습보다 **오히려 좋다.** 아직 외우지 않았다는 뜻이다.

(음수 격차는 dropout 때문이다. 학습 중에는 dropout 이 켜져 있어 학습 정확도가 낮게 나온다.)

## 과적합은 나쁜 것인가

아니다. **과적합할 수 있다는 것은 모델이 그 데이터를 표현할 능력이 있다는 뜻이다.**
전혀 과적합하지 않는다면 대개 모델이 너무 작거나 학습이 안 되고 있는 것이다(실습 3-6).

문제는 과적합 자체가 아니라 **그 지점을 모르고 지나치는 것**이다.

## 자주 하는 실수

- **마지막 체크포인트를 배포한다.** 가장 흔하고 가장 조용한 손실이다.
- **검증 손실이 올라가는데 "조금 더 돌려보자"고 한다.** 그 시간에 외운다.
- **일반화 격차를 안 본다.** 검증 정확도만 보면 언제 외우기 시작했는지 늦게 안다.
