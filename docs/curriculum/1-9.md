# 1-9. Training Data와 Reality는 왜 다른가?

## 문제

학습 데이터는 언제나 **과거**이고, 대체로 **잘 정리된 과거**다.

- 3월에 모은 데이터로 학습하고 7월 현장에 배포한다.
- 신형 설비 3호기 데이터만 모으고 노후한 1호기에 배포한다.
- 정상 위주로 모으고, 정작 잡아야 할 이상은 거의 없다.

여기서 재는 것은 "데이터가 깨졌는가"가 아니라 **"현실을 대표하는가"**다.
데이터는 완벽하게 깨끗해도 이 검사에서 떨어질 수 있다.

## PSI — Population Stability Index

학습 데이터의 분위수로 구간을 나눈 뒤, 현실 표본이 그 구간에 어떻게 떨어지는지 본다.

```text
PSI = Σ (obs% - ref%) × ln(obs% / ref%)
```

업계 관행:

| PSI | 해석 |
|-----|------|
| < 0.10 | 안정 |
| 0.10 ~ 0.25 | 이동 중 (경고) |
| ≥ 0.25 | 심각 (차단) |

이 **해석(임계값)은 Domain 의 `RepresentativenessPolicy`** 가 갖는다.
Infrastructure 는 값만 계산한다.

## 실습

```bash
pytest -m lesson_1_9 -s
```

## 무엇을 보게 되는가 — 여름 현장

```text
field                      PSI    coverage
------------------------------------------
active_power_kw         0.6041      99.8%  ← 심각
current_a               0.6080      99.8%  ← 심각
voltage_v               0.0063     100.0%
temperature_c          12.4283      10.7%  ← 심각
spindle_rpm             0.0044     100.0%
```

**온도 PSI 12.43, 커버리지 10.7%.**

여름이 되었을 뿐인데 모델이 본 적 없는 세상이 되었다.
현장 온도의 89%가 학습 데이터 범위 **밖**이다. 모델은 그 구간을 외삽으로 찍는다.

전압과 회전수는 멀쩡하다. **전부 무너지는 것이 아니라 일부만 무너진다.**
그래서 필드별로 봐야 한다.

## 무엇을 보게 되는가 — 같은 계절 현장

```text
field                      PSI    coverage
------------------------------------------
active_power_kw         0.0063     100.0%
temperature_c           0.0332     100.0%
...
[REPRESENTATIVENESS] PASSED
```

비교 도구가 아무거나 잡아내는 것이 아님을 확인한다.
경보가 항상 울리면 아무도 경보를 보지 않는다.

## LOT 번호가 새로 생긴 것은 사건이 아니다

```text
처음 보는 범주 비율
  3월 2주차 : 0.0%   (LOT 번호만 새로 생김)
  7월       : 37.5%  (신규 제품 코드 투입)
```

`batch_id` 는 날짜가 바뀌면 **전부 새 값**이다.
이것을 "처음 보는 범주"로 세면 경보는 매일 100%가 되고 무의미해진다.

그래서 `GROUP` 역할의 필드는 세지 않는다.

```python
# GROUP 역할(LOT/배치 ID)은 세지 않는다. 그 값은 원래 매번 새로 생긴다.
# "오늘 LOT 번호가 처음 보는 값"은 사건이 아니다.
# "처음 보는 제품 코드"나 "학습에 없던 설비 호기"가 사건이다.
```

여기서도 실습 1-3 의 `FieldRole` 이 값을 한다.

## 표본이 적으면 "이상 없음"을 믿지 않는다

```text
WARNING REPR_SAMPLE_TOO_SMALL  현실 표본이 너무 적어 비교 자체를 신뢰할 수 없다.
                               이 상태의 '이상 없음'은 근거가 아니다.
```

20건으로 드리프트 없음을 주장할 수는 없다.
검사하지 않은 것과 통과한 것을 구분하는 원칙이 여기에도 적용된다.

## 운영 단계와의 연결

이 계산을 **배포 후에 반복하면 그게 Data Drift 감시**다.

```text
[모듈 1] 학습 전 : 학습 데이터 vs 최근 현장 표본 → 학습해도 되는가?
[모듈 5] 배포 후 : 학습 데이터 vs 지금 들어오는 데이터 → 재학습해야 하는가?
```

같은 도구, 다른 시점. 그래서 이 코드는 운영 모듈에서 재사용된다.
"AI가 언제부터 이상해졌는지 찾아라"의 출발점이 여기다.

## 그럼 어떻게 해야 하는가

이 검사가 실패했을 때의 선택지는 셋이다.

1. **여름 데이터를 모아 다시 학습한다.** (가장 정직하고 가장 느리다)
2. **온도를 입력에서 뺀다.** (계절 의존성을 포기하는 대신 안정성을 얻는다)
3. **여름에는 배포하지 않는다.** (적용 범위를 명시한다)

셋 다 정당한 선택이다. **하지 말아야 할 것은 이 사실을 모른 채 배포하는 것뿐이다.**

## 자주 하는 실수

- **학습 데이터 내부에서만 검증하고 끝낸다.** train/test 가 같은 과거에서 나왔다면
  둘 다 현실과 다를 수 있다.
- **PSI 를 전체 평균 하나로 본다.** 필드별로 봐야 무엇을 고칠지 알 수 있다.
- **커버리지를 보지 않는다.** PSI 가 낮아도 범위 밖으로 나가는 경우가 있다.
