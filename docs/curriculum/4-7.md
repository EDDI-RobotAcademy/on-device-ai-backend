# 4-7. INT8로 줄이고 정확도가 얼마나 살아남는지 확인하라

## 문제

INT8 은 앞의 둘과 다르다. 실수를 **정수 눈금 위에 올린다.**

```text
실수 범위 [-3.2, 4.8] 을 256칸으로 나눠 -128 ~ 127 에 대응시킨다
```

그러니 값은 **반드시** 달라진다. 여기서 물어야 할 질문이 바뀐다.

```text
"숫자가 같은가?"    → 아니다. 물을 필요도 없다.
"**답이 같은가?**"  → 이것만 묻는다.
```

## 실습

```bash
pytest -m lesson_4_7 -s
```

## 무엇을 보게 되는가

```text
FP32 : max|diff| 1.907e-06   argmax 일치 100.00%
FP16 : max|diff| 1.008e-03   argmax 일치 100.00%
INT8 : max|diff| 4.177e-01   argmax 일치 100.00%
```

INT8 의 `max|diff|` 는 **0.4** 다. FP32 기준(1e-4)으로 재면 즉시 탈락이다.

그런데 argmax 는 100% 일치한다.
**분류 모델이 내는 답은 크기 순서지 값이 아니다.**

```python
def tolerance_for(self, precision: Precision) -> float | None:
    ...
    return None   # INT8 — 값 자체를 비교하지 않는다
```

`EquivalencePolicy` 는 INT8 에 대해 값 비교를 **아예 하지 않는다.**
남는 검사는 `agreement_ratio` 하나뿐이다.

## 대표 데이터 없이는 정수 눈금을 정할 수 없다

```text
[CONVERSION_FAILED] representative_dataset:
    대표 데이터가 없다. INT8 양자화는 값의 범위를 모르면 할 수 없다.
```

```python
# 값의 범위를 알아야 정수 눈금을 정할 수 있다.
# 그 범위는 **train 분할에서** 뽑는다. 실습 1-7 과 같은 이유다.
samples = trained.dataset.features["train"]

def representative():
    for row in samples[:count]:
        yield [row[None].astype("float32")]

converter.representative_dataset = representative
```

**test 에서 뽑으면 평가 데이터가 모델 안으로 새어 들어간다.**

정규화 통계를 train 에서만 뽑는 것(실습 1-7)과 정확히 같은 이유다.
양자화 스케일도 학습 데이터로부터 정해지는 **모델의 일부**다.

## 전체 정확도는 한 클래스의 붕괴를 숨긴다

이것이 이 실습의 진짜 위험이다.

```text
클래스           FP32    INT8      차이
FAULT         0.90    0.55   -0.35
OVERLOAD      0.96    0.96   +0.00
NORMAL        0.99    0.99   +0.00
```

```text
전체 정확도  0.970 → 0.962   (−0.8%)
macro recall 0.950 → 0.833   (−11.7%)
```

전체 정확도는 **0.8% 밖에** 안 떨어졌다.
보고서에는 '정확도 유지'라고 쓸 수 있는 숫자다.

그런데 FAULT 재현율은 **35% 떨어졌다.**
설비 정지를 절반 가까이 놓치기 시작했다는 뜻이다.

INT8 은 대개 **소수 클래스부터 무너뜨린다.**
그 클래스의 표본이 적으니 양자화 범위를 잡을 때도 영향력이 작기 때문이다.

```python
def worst_class_drop_from(self, baseline: ArtifactAccuracy) -> tuple[str | None, float]:
    """가장 크게 떨어진 클래스. **평균은 이것을 숨긴다.**"""
```

그래서 `DeviceBudget` 에 `max_class_recall_drop` 이 따로 있다 ([4-10](4-10.md)).

## 이 모델에서는 정확도가 안 깎였다

```text
TFLITE/INT8   정확도 1.0000 / macro recall 1.0000
크기 16,273B → 9,512B
```

정직하게 기록한다. **항상 떨어지는 것은 아니다.**

층이 얕고 값의 분포가 좁아서 256칸으로도 충분했다.
대신 이 표에서 실제로 교환된 것은 정확도가 아니라 **속도**였다 —
INT8 이 FP32 보다 느리다. 그 이야기는 [4-8](4-8.md) 에서 한다.

**"양자화하면 정확도가 떨어진다" 도 "안 떨어진다" 도 미리 알 수 없다. 재야 안다.**

## 세 정밀도 정리

| | 값이 바뀌는가 | 무엇으로 검증하는가 | 대표 데이터 |
|---|---|---|---|
| FP32 변환 | 거의 안 바뀐다 | `max\|diff\| < 1e-4` | 불필요 |
| FP16 | 소수점 아래가 흔들린다 | `max\|diff\| < 1e-2` | 불필요 |
| INT8 | **크게 바뀐다** | **argmax 일치만** | **필요 (train)** |

## 자주 하는 실수

- **INT8 을 FP32 기준으로 검증한다.** 항상 실패하고, 결국 검증을 끈다.
- **test 데이터로 대표 데이터를 만든다.** 평가가 오염된다.
- **전체 정확도만 확인한다.** 소수 클래스의 붕괴를 놓친다.
- **양자화 후 재평가를 건너뛴다.** 무엇을 잃었는지 아무도 모른다.
