# 4-11. 구조를 줄이는 것과 숫자를 줄이는 것은 다르다

## 문제

[4-5](4-5.md) ~ [4-7](4-7.md) 은 **숫자를 좁혔다.** FP32 → FP16 → INT8.
구조는 손대지 않았다. 층도 채널도 그대로고, **곱셈 횟수도 그대로**다.

경량화에는 축이 하나 더 있다.

```text
양자화     재학습 없음. 곱셈 횟수 그대로. 파일만 작아진다.
구조 축소  **재학습 필수.** 곱셈 횟수가 실제로 준다.
```

## 실습

```bash
pytest -m lesson_4_11 -s
```

## 다섯 가지를 해 보면

```text
폭 절반 · 재학습 없음    params   955  MAC  71.0%↓  크기 57.1%↓  정확도 0.045  BLOCKED
폭 절반 · 재학습          params   955  MAC  71.0%↓  크기 57.1%↓  정확도 1.000  OK
가지치기 50% · 그대로     params 3,187  MAC   0.0%↓  크기 -0.4%↓  정확도 0.833  BLOCKED
가지치기 50% · 미세조정   params 3,187  MAC   0.0%↓  크기 -0.4%↓  정확도 1.000  BLOCKED
채널 가지치기 50%         params 3,187  MAC   0.0%↓  크기 -0.4%↓  정확도 0.788  BLOCKED
```

**다섯 가지를 해 봤고 하나가 남았다.**

## 본론 (1) — 구조를 줄이면 재학습이 따라온다

```text
재학습 없음 : 정확도 0.045
재학습      : 정확도 1.000
둘 다 MAC 71%↓ / 크기 57%↓
```

모양이 달라졌으니 **배운 가중치를 물려받을 수 없다.**
새 구조는 무작위 초기값에서 시작한다 — 그래서 미세조정이 절차의 일부다.

양자화와 여기서 갈린다.

## 본론 (2) — 비구조적 가지치기는 장부상의 경량화다

```text
파라미터 수   3,187 (그대로)
0 아닌 것     1,619
희소도        49%
파일 크기     -0.4%
곱셈 횟수     +0.0%
```

```text
CRITICAL STRUCT_SPARSITY_NOT_REALIZED
         가중치의 49% 가 0인데 파일은 -0.4% 밖에 안 줄었다.
         **0도 저장되고 0도 곱해진다.**
```

희소 연산을 지원하는 런타임이 있어야 비로소 이득이 생긴다.
이 사실을 모르면 "50% 가지치기 했는데 왜 그대로죠?"에서 하루를 쓴다.

## 가장 놓치기 쉬운 한 줄

```text
그대로     : 희소도 49%  정확도 0.833
미세조정   : 희소도  6%  정확도 1.000
```

```text
CRITICAL STRUCT_PRUNE_UNDONE
         50% 를 0으로 만들었는데 미세조정 뒤에 0이 6% 만 남았다.
         **미세조정이 0을 다시 채웠다.**
```

옵티마이저가 0인 자리에도 기울기를 흘려서 다시 채운 것이다.
**마스크로 붙잡아 두지 않으면 가지치기가 없던 일이 된다.**

## 채널을 0으로 만드는 것과 떼어내는 것은 다르다

채널을 통째로 0으로 만들어도 **그 채널은 여전히 거기 있다.**
실제로 떼어 내서 더 작은 층으로 다시 조립해야 곱셈이 준다 —
그건 결국 '폭 줄이기'와 같은 일이고, 그래서 재학습이 따라온다.

## 두 축은 곱해진다

```text
구조 축소 : 파라미터 개수를 줄인다
양자화    : 파라미터 하나의 크기를 줄인다
```

순서는 구조 축소가 먼저다 — 재학습이 필요하기 때문이다.

## 자주 하는 실수

- **파라미터 수가 줄었다고 빨라졌다고 말한다.** MAC 을 봐야 한다.
- **가지치기 뒤에 미세조정하고 마스크를 안 건다.** 가지치기가 사라진다.
- **줄인 뒤 재학습을 건너뛴다.** 정확도가 무너진다.
- **2% 줄이려고 재학습 절차를 하나 더 만든다.** 남는 장사가 아니다.
