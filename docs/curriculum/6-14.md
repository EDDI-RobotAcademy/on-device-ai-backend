# 6-14. 실시간 추론 Endpoint를 띄워라

## 문제

모듈 6 은 지금까지 **모델을 디바이스로 보내는 길**만 봤다. 반대 방향도 있다.

```text
온디바이스   모델이 현장에 있다. 네트워크가 끊겨도 판단한다.
Endpoint     모델이 클라우드에 있다. 디바이스는 물어본다.
```

Endpoint 가 유리한 자리는 분명히 있다 —
무거운 모델, 잦은 교체, 실시간이 아닌 작업(라벨 재검증 등).

**그러나 이 과정의 주제에서는 대개 답이 아니다.** 이유가 셋이다.

## 실습

```bash
pytest -m lesson_6_14 -s
```

## 실제로 띄운다

```text
create_model → create_endpoint_config → create_endpoint
```

**세 번의 진짜 boto3 요청이다** — API 이름이 틀리면 여기서 터진다.

```text
[line3-inspection] InService
  갈래       AllTraffic 1
  인스턴스   1대  월 $83
  응답       왕복 포함 48ms / 사이클 30ms
```

## 이유 (1) — 왕복 지연은 경량화로 못 푼다

```text
CRITICAL EP_CYCLE_TIME_MISSED
         왕복 42ms + 추론 6ms = 48ms 인데 사이클 타임은 30ms 다.
         **모델을 아무리 줄여도 왕복 시간은 안 줄어든다.**
```

모듈 4 에서 지연시간을 0.003ms 까지 줄였다.
**그 노력이 왕복 42ms 앞에서 의미가 없어진다.**
이건 구조로 푸는 문제다.

## 이유 (2) — 네트워크가 끊기면 라인이 선다

```text
CRITICAL EP_NO_OFFLINE_FALLBACK
         네트워크가 끊기면 즉시 판단이 멈춘다.
         **공장 회선은 끊긴다** — 정전, 스위치 교체, 공사.
```

사이클 타임이 넉넉해도 이건 남는다.
온디바이스 모델을 함께 두지 않으면 그 시간 동안
라인이 서거나 검사 없이 흘러간다.

> **이 과정이 온디바이스인 이유다.**

## 이유 (3) — 요청이 없어도 시간당 과금된다

```text
인스턴스 2대
월 $1,305
시간당 요청 30건 → 인스턴스당 15건
```

```text
WARNING EP_ALWAYS_ON_COST   요청이 하나도 없어도 그대로 나간다.
WARNING EP_UNDERUSED        인스턴스 한 대가 시간당 15건을 받는다.
```

**분당 한 건짜리 일에 상시 GPU 서버 두 대를 두고 있다.**
배치 변환(Batch Transform)이나 서버리스가 맞는 모양이다.

그리고 실습이 끝나면 **반드시 지운다.**

```python
container.teardown_endpoint().execute(TeardownEndpointCommand(name=...))
```

교육 계정에서 가장 자주 나는 사고가 이것이다 —
실습이 끝난 엔드포인트가 한 달을 돈다.

## 클라우드에서는 A/B 가 숫자 하나다

```text
blue 0.9 / green 0.1
      ↓ update_endpoint_weights_and_capacities
blue 0.5 / green 0.5
```

디바이스에서는 OTA 로 웨이브를 나눠야 했다 ([6-8](6-8.md)).
**클라우드에서는 숫자 하나를 바꾸면 된다.**
그 편함이 엔드포인트의 진짜 장점이고,
[5-14](5-14.md) 의 규율(멈춤 기준·최소 표본)은 여기서도 그대로 필요하다.

## 확인하지 못한 것

```text
update_endpoint_weights_and_capacities  moto 지원 O  → 테스트가 실제로 쓴다
update_endpoint (설정 교체)             moto 지원 X  → 실계정에서 검증 필요
invoke_endpoint                         moto 는 **고정 응답**을 돌려준다
```

`invoke_endpoint` 로는 추론이 돌지 않는다.
그래서 이 실습에서 확인하는 것은 "모델이 잘 맞히는가"가 아니라
**"엔드포인트라는 구조가 무엇을 요구하는가"**다.

## 자주 하는 실수

- **모델을 줄여서 지연을 맞추려 한다.** 왕복은 안 줄어든다.
- **오프라인 대비를 안 한다.** 회선이 끊기면 라인이 선다.
- **실습 후 안 지운다.** 한 달치 청구서가 온다.
- **인스턴스 한 대로 현장을 의존한다.** 그 한 대가 전부다.
