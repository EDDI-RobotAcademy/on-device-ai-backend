# 4-2. PyTorch 모델을 디바이스용 모델로 바꿔라

## 문제

학습에 쓰던 모델은 **파이썬 함수**다. 층마다 파이썬 인터프리터가 호출된다.

디바이스에 파이썬이 있으리라는 보장은 없다.
첫 단계는 파이썬을 벗어난 그래프로 굳히는 것이다.

## 실습

```bash
pytest -m lesson_4_2 -s
```

## 무엇을 보게 되는가

```text
후보 TORCHSCRIPT/FP32
  변환   : PYTORCH → TORCHSCRIPT (FP32)  표본 66개  max|diff| 0.000e+00  argmax 일치 100.00%
  크기   : 18,409B (가중치 12,748 + 오버헤드 5,661)
  속도   : p50 0.0198ms / p95 0.0205ms
  정확도 : 1.0000 / macro recall 1.0000
```

파라미터는 그대로 3,187개다. **모델을 바꾼 게 아니라 실행 방법을 바꿨다.**

- 기준(PyTorch eager) 0.0316ms → TorchScript 0.0205ms
- 파일은 오히려 커졌다 (16,273B → 18,409B). 그래프 구조가 함께 담기기 때문이다.

## trace 는 실행해 보고 기록한다

```python
scripted = torch.jit.trace(module, example)
scripted = torch.jit.freeze(scripted)   # dropout/BN 을 상수로 굳힌다
```

`trace` 는 모델을 **한 번 실행해 보고 그 경로를 기록한다.**

그래서 `forward` 안에 입력에 따라 갈리는 `if` 가 있으면 **한쪽만 남는다.**
학습용 코드를 그대로 내보내면 안 되는 이유가 이것이다.

`freeze` 는 dropout 같은 학습 전용 동작을 상수로 굳힌다.
`eval()` 을 호출하는 것을 잊어도 여기서 고정된다.

## 변환 도구는 축이 틀려도 성공한다

이것이 이 모듈 전체를 관통하는 문장이다.

```text
CRITICAL CONVERT_NOT_VERIFIED (TORCHSCRIPT)
         변환 후 같은 답을 내는지 확인하지 않았다. 변환 도구는 축이 틀려도 성공한다.
```

`ConversionRecord` 에 `equivalence` 가 없으면 그 후보는 선택될 수 없다.
**'변환 성공' 은 검증이 아니다.**

## 값이 비슷한 것과 답이 같은 것은 다르다

```text
CRITICAL CONVERT_PREDICTION_CHANGED (TORCHSCRIPT)
         10 개 표본에서 예측이 바뀌었다.
         값이 조금 달라진 것이 아니라 **답이 달라진 것**이다.
```

`max|diff|` 는 3e-05 로 작다. 그런데 200개 중 10개에서 답이 바뀌었다.
결정 경계에 있던 표본은 아주 작은 차이로도 넘어간다.

그래서 `NumericalEquivalence` 는 두 가지를 함께 담는다.

```python
@dataclass(frozen=True, slots=True)
class NumericalEquivalence:
    sample_count: int
    max_abs_diff: float
    mean_abs_diff: float
    agreement_ratio: float
    """argmax 가 일치한 표본의 비율. 분류 모델에서 실제로 중요한 것은 이 숫자다."""
```

## 표본이 적으면 '같다'고 말할 수 없다

```text
WARNING CONVERT_SAMPLE_TOO_FEW (TORCHSCRIPT)
        4 개 표본으로 동등성을 판단했다. 그 숫자로는 우연히 맞았을 수 있다.
```

그리고 대조에 쓰는 입력은 **실제 평가 데이터**다.

```python
features = trained.dataset.features["test"][:sample_count]
```

0으로 채운 텐서는 아무것도 검증하지 못한다. 어떤 축 오류든 0은 0으로 나온다.

## PyTorch 런타임은 아직 필요하다

```python
@property
def is_deployable_on_device(self) -> bool:
    """PyTorch 는 파이썬을 요구한다. 대부분의 임베디드 환경에 파이썬은 없다."""
    return self is not RuntimeTarget.PYTORCH
```

TorchScript 는 파이썬 없이 돈다. 다만 **PyTorch 런타임(libtorch)은 여전히 필요하다.**
수십 MB짜리 런타임이 들어갈 디바이스인지는 따로 확인해야 한다.

그래서 이것이 마지막 단계가 아니다.

## 한 번의 변환은 네 가지를 한다

```text
1. 내보낸다        → ModelArtifact          크기는 파일에서 잰다
2. 대조한다        → NumericalEquivalence   같은 답을 내는가
3. 잰다            → BenchmarkResult        얼마나 빠른가
4. 다시 평가한다   → ArtifactAccuracy       무엇을 잃었는가
```

넷 중 하나라도 빠지면 비교표에 올릴 수 없다 (`ConvertModel` use case).

## 자주 하는 실수

- **변환 성공을 검증으로 착각한다.** 도구는 축이 틀려도 성공한다.
- **0 텐서로 대조한다.** 아무 오류도 잡지 못한다.
- **`eval()` 없이 trace 한다.** dropout 이 켜진 채로 굳는다.
- **입력에 따라 갈리는 forward 를 trace 한다.** 한쪽 경로만 남는다.
