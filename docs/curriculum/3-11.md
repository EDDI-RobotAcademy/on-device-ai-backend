# 3-11. 이미지로 정상과 불량을 가르는 모델을 학습시켜라

## 문제

[3-3](3-3.md) 은 이미지를 숫자로 바꾸는 데서 멈췄다. 여기서 그 숫자로 **모델을 만든다.**

두 캡스톤 주제에 각각 대응한다.

```text
castings-train/  ok / ng                 자동차 다이캐스팅 표면 균열
food/            ok / foreign / burnt    식품 제조 공정 표면 (이물 · 탄자국)
```

## 실습

```bash
pytest -m lesson_3_11 -s
```

## 같은 Aggregate 를 쓴다

이미지 학습이라고 `ImageTrainingRun` 을 새로 만들지 않았다.
**학습이라는 사건은 하나이기 때문이다.**

```python
TrainingRun.prepare(...)         # 표: 창을 자른다
TrainingRun.prepare_images(...)  # 이미지: 창이 없다
```

달라지는 것은 재료를 어디서 가져오느냐뿐이다.
학습 곡선을 보는 규칙(`LearningPolicy`, `OverfittingPolicy`)도 하나뿐이다.

## 이미지에는 이미지의 게이트가 있다

표의 게이트(모듈 1·2)는 결측치·시간축·중복을 본다.
이미지에는 그런 열이 없다. 대신 **장수·폴더·해상도**가 있다.

```text
CRITICAL IMG_TOO_FEW_SAMPLES   'ng' 가 11장뿐이다.
WARNING  IMG_IMBALANCED        많은 쪽이 적은 쪽의 10.9배다.
WARNING  IMG_MIXED_RESOLUTION  해상도가 2 종류다.
CRITICAL IMG_UNREADABLE        3장이 열리지 않는다.
```

**재는 것은 Infrastructure, 판정은 Domain.** 모듈 1·2 와 같은 구조다.

폴더가 하나뿐인 경우는 소견이 아니라 **불변식 위반**이다 —
`ImageDataRef` 가 애초에 만들어지지 않게 막는다.

## 이 실습의 본론

같은 데이터, 같은 구조, 같은 학습률. **마지막 한 줄만 바꾼다.**

```text
                accuracy   macro_recall
AVERAGE 풀링      0.542        0.544
MAX     풀링      0.958        0.956
```

파라미터 수도 연산량도 같다. **공짜로 얻은 정확도다.**

### 왜 이런 일이 생기는가

```text
이물(foreign)    몇 화소짜리다. 48×48 을 전부 평균내면 사라진다.
탄자국(burnt)    넓게 퍼져 있다. 평균에도 남는다.
```

**그래서 한쪽만 못 맞힌다.** 혼동 행렬을 봐야 이게 보인다 — 정확도 하나로는 안 보인다.

```python
class GlobalPooling(Enum):
    AVERAGE = "AVERAGE"   # 넓게 퍼진 변화에 강하다
    MAX     = "MAX"       # 작고 국소적인 결함에 강하다
```

**"어느 쪽이 옳은가"는 코드가 아니라 결함의 생김새가 정한다.**

## 정확도가 100% 가 아니다

다이캐스팅 모델은 0.86 근처에서 멈춘다. 일부러 그렇게 만들었다 —
**불량의 12% 는 흐릿하게 그려 두었다.**

100% 가 나오는 이미지 데이터셋은 대개 문제를 잘못 만든 것이다.

## 분할은 클래스 비율을 유지한 채 섞는다

시계열은 시간 순서로 자른다 ([3-8](3-8.md)). 이미지에는 시간이 없다.
순서대로 자르면 폴더 순서 때문에 **test 가 한 클래스로만 채워진다.**

```text
train        224장  burnt 70  foreign 70  ok 84
validation    48장  burnt 15  foreign 15  ok 18
test          48장  burnt 15  foreign 15  ok 18
```

겹치는 표본은 0이다 — 자를 시간 축이 없어서 경계 누출이 애초에 안 생긴다.

## 계약이 어긋나면 준비 단계에서 막는다

```text
ShapeMismatch: 모델 입력 (3, 64, 64) 과 이미지 명세 (3, 48, 48) 가 다르다.
ShapeMismatch: 모델의 출력 클래스 수(2)와 폴더 수(3)가 다르다.
```

학습 때 48 로 줄이고 배포 때 64 로 줄이면 **아무 에러도 안 난다.**
현장에서만 틀린다. 그래서 계약을 하나로 두고 준비 단계에서 맞춰 본다.

## 자주 하는 실수

- **전역 평균 풀링을 기본값으로 쓴다.** 작은 결함은 평균에 묻힌다.
- **정확도만 본다.** 어느 클래스를 못 맞히는지가 안 보인다.
- **순서대로 분할한다.** test 가 한 폴더로만 채워진다.
- **폴더를 하나 더 만들고 모델은 그대로 둔다.** 그 클래스는 영원히 안 나온다.
