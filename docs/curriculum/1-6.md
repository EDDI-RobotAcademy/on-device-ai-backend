# 1-6. 정상과 이상을 누가 결정하는가?

## 문제

라벨은 데이터에 들어 있지 않다. **사람이 넣는 것이다.**

그래서 라벨 품질 문제는 대부분 결측이나 오타가 아니라,
**정의가 없거나, 정의가 사람마다 다른** 데서 나온다.

> "이 정도 표면 흠집이 불량인가?"
> → 품질팀은 불량, 생산팀은 양품. 두 사람이 같은 사진에 다른 라벨을 붙인다.
> → 모델은 그 모순을 그대로 학습하고, 현장에서는 "AI가 오락가락한다"고 말한다.

## 라벨은 이름만으로 만들 수 없다

```python
LabelDefinition(name="NG", meaning="", decided_by="품질팀")
# InvariantViolation: 'NG' 의 판단 기준이 없다. 기준 없는 라벨은 사람마다 달라진다.

LabelDefinition(name="NG", meaning="표면 균열 길이가 1mm 이상", decided_by="")
# InvariantViolation: 'NG' 을 누가 정했는지 없다. 분쟁이 나면 되돌릴 근거가 없다.
```

`meaning` 은 **다른 사람이 읽고 같은 판단을 내릴 수 있는 문장**이어야 한다.
`decided_by` 는 분쟁이 났을 때 되돌아갈 근거다.

이 둘이 없으면 객체가 만들어지지 않는다. 나중에 채우는 것이 아니다.

## 무엇을 보게 되는가

```text
[LABEL_SPACE] FAILED  (raw)
  - CRITICAL LABEL_UNDEFINED    (UNKNOWN)   정의된 클래스가 아니다.       [측정 6]
  - CRITICAL LABEL_MISSING      (condition) 라벨이 비어 있는 표본이 있다. [0.0014 / 0]
  - CRITICAL LABEL_DISAGREEMENT (condition) 작업자 2 명의 판단이 갈린다.  [0.8811 / 0.9]
  - WARNING  LABEL_IMBALANCED   (condition) 클래스 불균형이 크다.         [1385 / 10]
```

**일치율 88.1%.** 100건 중 12건에서 두 작업자의 판단이 달랐다.
모델이 배우는 것은 결함이 아니라 **사람의 기준 차이**다.

기준을 합의한 뒤(`curated`):

```text
[LABEL_SPACE] PASSED_WITH_WARNINGS  (curated)
  - WARNING LABEL_IMBALANCED (condition) 클래스 불균형이 크다. [91.73 / 10]
```

불균형은 남는다. **현장이 원래 그렇다.**
불량률 1%인 라인에서 불량 데이터를 50% 모으는 것은 불가능하고, 억지로 맞추면 왜곡이다.
불균형은 데이터를 고쳐서 없앨 문제가 아니라 **알고 대응할 문제**다.
(대응 방법은 모듈 2 와 모듈 3 에서 다룬다)

## 교차 검토 규약

```text
라벨 필드가 `condition` 이면, 2차 작업자의 판단은 `condition_review` 열에 둔다.
두 열이 모두 채워진 행이 "교차 검토된 표본"이고, 값이 다른 행이 "불일치"다.
```

이 규약은 기술적 편의가 아니라 **조직의 약속**이다.
약속이 없으면 라벨 일치율을 측정할 방법 자체가 없다.

## 검토가 없으면 일치율은 1.0 이 아니라 0.0 이다

```python
@property
def agreement_ratio(self) -> float:
    if self.reviewed_sample_count == 0:
        return 0.0    # ← 1.0 이 아니다
```

검토를 한 적이 없는데 "일치율 100%"라고 말하는 시스템이 가장 위험하다.
그래서 `LABEL_NO_CROSS_REVIEW` 는 CRITICAL 이다.

> 검사하지 않았다는 것은 문제가 없다는 뜻이 아니다.

이 원칙은 실습 1-10 에서 다시 나온다.

## 정의를 먼저, 측정을 나중에

```python
# 1. 정의를 확정한다
dataset.define_label_space(command.label_space)

# 2. 그 다음 측정한다
measurement = self._measurer.measure(dataset.source, space.field_name)

# 3. 정의와 측정을 맞대어 판정한다
report = command.policy.inspect(space, measurement)
```

정의 없이 측정하면 **무엇과 비교할지** 알 수 없다.
`UNKNOWN` 이라는 값이 데이터에 있다는 사실은, 정의가 있어야 문제가 된다.

## 라벨 필드는 스키마가 정한다

```python
LabelSpace(field_name="batch_id", ...)
# SchemaMismatch: 'batch_id' 의 역할은 GROUP 이다. LABEL 이 아니다.
```

실습 1-3 에서 확정한 역할이 여기서 강제된다.

## 자주 하는 실수

- **클래스 이름 목록만 만든다.** `["OK", "NG"]` 는 라벨 정의가 아니다.
- **교차 검토를 생략한다.** 시간이 없다는 이유로 가장 먼저 잘리는 것이 이것이고,
  가장 비싸게 돌아온다.
- **불균형을 오버샘플링으로 "해결"하고 넘어간다.** 그 전에 정의와 일치율부터 봐야 한다.
  기준이 다른 라벨을 아무리 복제해도 기준은 여전히 다르다.
