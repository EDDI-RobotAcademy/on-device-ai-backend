# 2-3. 이상치는 데이터에 숨어 있는 사고다

## 문제

이상치를 지우기 전에 물어야 할 것이 있다. **이게 오류인가, 사고인가?**

```text
NORMAL 라벨 구간에 있는 이상치  → 라벨이 틀렸거나, 아직 아무도 모르는 사고다
FAULT 라벨 구간에 있는 이상치   → 그게 신호다. 지우면 배울 것이 없어진다
```

라벨을 보지 않고 이상치를 지우는 것이 데이터 품질 작업에서
가장 흔하고 가장 비싼 실수다.

## 실습

```bash
pytest -m lesson_2_3 -s
```

## 무엇을 보게 되는가

```text
[VALIDITY] 61.6 (D)  FAILED
  - WARNING  VALIDITY_OUTLIER_RATIO     (active_power_kw) MAD 기준 이상치 121건
  - CRITICAL VALIDITY_RATE_VIOLATION    (active_power_kw) 직전 표본 대비 변화가 불가능하다
  - CRITICAL VALIDITY_OUTLIER_IN_NORMAL (active_power_kw) 이상치의 99% 가 'NORMAL' 구간에 있다
```

설비가 340~390kW 를 쓰는 동안 **아무도 이상하다고 기록하지 않았다.**
여기서 할 일은 삭제가 아니라 조사다.

## 세 가지 척도를 함께 쓴다

| 척도 | 성질 | 잡는 것 |
|---|---|---|
| z-score | 평균·표준편차 기반 | 표준적인 극단값 |
| MAD | 중앙값 기반, **강건** | 오염된 데이터에서도 계속 본다 |
| 변화율 | 직전 표본 대비 | 값 하나만 보면 정상인 것 |

### z-score 는 이상치가 많아지면 눈이 먼다 (masking)

```text
같은 데이터, 다른 척도
  z-score(평균 기반) :  12건
  MAD(중앙값 기반)   : 340건
  → 이상치가 평균과 표준편차를 자기 쪽으로 끌어당겼다.
```

이상치가 많을수록 평균과 표준편차가 오염되고, 오염될수록 이상치를 못 찾게 된다.
**이상치를 찾는 도구가 이상치에 오염되는 것**이다.

그래서 두 값의 차이(`masking_gap`)를 따로 잡아 경고한다.

```python
@property
def masking_gap(self) -> int:
    """MAD 는 잡았는데 z-score 는 놓친 표본 수."""
    return max(self.mad_outlier_count - self.z_outlier_count, 0)
```

### 변화율 위반 — 단변량으로는 절대 안 잡히는 것

```text
전류 540A 는 물리 범위(0~600A) 안이다. 값 하나만 보면 정상이다.
직전 표본과 비교해야 '10초 만에 300A 가 뛰었다'가 보인다.
```

모듈 1의 물리 범위 검사(1-2, 1-4)는 값 하나만 본다.
그래서 이 오염을 통과시킨다.

## 정상 데이터에도 이상치는 있다

`clean` 파일 결과:

```text
[VALIDITY] 97.5 (A)  PASSED_WITH_WARNINGS
  - WARNING VALIDITY_OUTLIER_RATIO (spindle_rpm) MAD 기준 이상치가 150 건이다.
```

전부 FAULT 구간이다. 설비가 실제로 멈췄으니 rpm 이 0 이다.
**이건 잡음이 아니라 우리가 찾으려는 바로 그 사건이다.**

지웠다면 학습할 것이 사라진다. 그래서 이상치 비율은 CRITICAL 이 아니라 WARNING 이다.
CRITICAL 이 되는 것은 **이상치가 정상 구간에 몰려 있을 때**다.

## '정상 라벨'이 무엇인지는 Policy 가 안다

```python
모름 = ValidityPolicy(normal_label=None).evaluate(measurement)   # 판단 못 함
앎   = ValidityPolicy(normal_label="NORMAL").evaluate(measurement)  # CRITICAL
```

측정기는 라벨별 이상치 개수만 센다. 어떤 라벨이 '아무 일도 없었음'인지는
라인마다 다른 **도메인 지식**이므로 Policy 가 들고 있다.

측정기에 넣으면, 라인마다 측정기를 새로 만들어야 한다.

## 기준이 0 이 아닌 이유

```python
max_rate_violation_ratio: float = 0.005
"""0 이 아니다. 설비가 실제로 정지하면 값은 실제로 급변한다.
정상 데이터에도 급변은 있고, 기준은 그 사실을 인정한 자리에 있어야 한다."""
```

모든 것을 0 으로 두면 정상 데이터도 매번 걸린다. 그러면 아무도 이 검사를 보지 않는다.

## 어떻게 고칠 것인가

| 상황 | 조치 |
|---|---|
| 계측 오류가 확인됨 | `DROP_ROWS` |
| 계측 한계에서 잘림 | `CLIP` (정보가 사라진다는 것을 알고) |
| **사고였음이 확인됨** | `RELABEL` — 지우는 게 아니라 라벨을 고친다 |
| 판단 불가 | `RECOLLECT` 또는 현장 확인 |

## 자주 하는 실수

- **`z-score > 3` 으로 걸러내고 끝낸다.** 오염된 데이터에서는 절반을 놓친다.
- **이상치를 라벨과 무관하게 지운다.** 우리가 찾으려던 사고를 지운다.
- **`clip()` 을 습관적으로 쓴다.** 큰 값일수록 정보가 사라지는데, 큰 값이 대개 사건이다.
