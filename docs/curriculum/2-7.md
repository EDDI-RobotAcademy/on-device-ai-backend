# 2-7. 중복 데이터는 AI에게 같은 현실을 반복해서 가르친다

## 문제

**행 전체가 같아야 중복이 아니다. 모델이 보는 것이 같으면 중복이다.**

타임스탬프는 모델의 입력이 아니다(실습 1-7).
따라서 타임스탬프만 다르고 입력 값이 같은 두 행은, 모델에게는 **같은 표본**이다.

## 모듈 1은 이 중복을 절대 잡지 못한다

```bash
pytest -m lesson_2_7 -s
```

```text
같은 파일, 두 관점
  [모듈 1] 시간축 중복 :   0건  ← 타임스탬프는 전부 유일하다
  [모듈 2] 입력 중복   : 276건  ← 모델이 보는 값은 같다
```

실습 1-5 의 시간축 검사는 `duplicate_timestamp_count == 0` 을 확인하고 통과시켰다.
틀린 것이 아니다. **다른 것을 본 것이다.**

무엇을 중복이라 부를지는 **'모델이 무엇을 보는가'**가 정한다.

```python
# 중복 판정은 입력(feature) 열로만 한다.
features = frame[target.feature_fields].round(self._round_digits)
duplicated_mask = features.duplicated(keep="first")
```

## 중복이 만드는 피해는 셋이다

### 1. 가중치 왜곡

중복된 구간이 여러 번 학습된다. 모델이 그쪽으로 끌려간다.
"이 패턴이 자주 나온다"고 배우는데, 실제로는 한 번 일어난 일이다.

### 2. 분할 누수 — 실습 1-8 과 이어진다

```text
CRITICAL UNIQUENESS_EXACT_DUPLICATE  입력이 완전히 같은 행이 276 개 (156 묶음)다.
                                     무작위로 나누면 원본은 train, 사본은 test 로 간다.
```

시험 문제를 미리 본 것이다. 검증 점수가 올라가고, 현장에서 무너진다.

실습 1-4 에서 찾은 **중복 이미지 4장**도 정확히 같은 문제였다.
전력이든 이미지든, 중복은 결국 분할에서 터진다.

### 3. 표본 수 착시

```text
8,640행처럼 보이는 데이터
  전체 행        : 10,000
  서로 다른 표본 : 7,500
  부풀림         : 1.33배
```

"데이터가 1만 건 있습니다"라는 보고가 틀린 것이다.

## 두 종류의 중복

| 종류 | 어떻게 생기는가 | 심각도 |
|---|---|---|
| **완전 중복** | 수집 재전송, 배치 중복 적재 | CRITICAL |
| **근접 중복** | 센서 홀드 (값이 갱신되지 않음) | WARNING |

근접 중복은 인접 행과 사실상 같은 값이 반복되는 경우다.
센서가 죽은 것은 아니고(그건 실습 1-4 의 고착),
값이 몇 표본 동안 갱신되지 않은 상태다.

```python
scale = np.maximum(np.abs(previous), 1.0)
close = np.abs(current - previous) <= self._near_tolerance * scale
```

절대값이 아니라 **상대 오차**로 본다. 380V 와 0.5rpm 을 같은 잣대로 잴 수 없다.

## 중복이 라벨 오류를 드러낸다

```text
CRITICAL UNIQUENESS_LABEL_CONFLICT  같은 입력에 다른 라벨이 붙은 행이 113 개다.
                                    중복이 라벨 오류를 드러냈다.
```

실습 2-4 에서 본 것과 **같은 113건**이다. 다른 각도에서 다시 만난 것이다.

> 품질의 여섯 축은 독립적이지 않다.
> 같은 사고가 여러 축에 그림자를 남긴다.

이것이 여섯 축을 **함께** 보는 이유이고, 하나만 보면 안 되는 이유다.

## 어떻게 고칠 것인가

| 상황 | 조치 | 주의 |
|---|---|---|
| 완전 중복 | `DEDUPLICATE` | 어느 쪽이 원본인지 확인 |
| 근접 중복(센서 홀드) | `DROP_ROWS` 또는 수집 주기 재확인 | 홀드 구간은 정보가 없다 |
| 라벨 모순 중복 | `RELABEL` 또는 `DROP_ROWS` | 실습 2-4 와 함께 |

`DEDUPLICATE` 후에는 **표본 수가 줄어든다.** 그 감소가 실습 2-9 의 비교에서
"학습 가능 표본" 변화로 나타난다.

## 자주 하는 실수

- **`df.drop_duplicates()` 를 전체 열 기준으로 돌린다.** 타임스탬프가 다르면
  아무것도 지워지지 않는다. 그리고 문제는 그대로 남는다.
- **중복을 지우고 표본 수가 줄었다고 아쉬워한다.** 원래 없던 데이터다.
- **분할 후에 중복을 확인한다.** 이미 누수가 일어난 뒤다.
