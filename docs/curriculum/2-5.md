# 2-5. 불균형 데이터는 AI의 판단을 왜곡한다

## 문제

불량률 0.3% 인 라인에서 **"정확도 99.7%"** 는 아무 의미가 없다.
전부 정상이라고 찍어도 나오는 숫자다.

그런데 이 숫자는 보고서에 아주 잘 어울린다. 그래서 위험하다.

## 불균형은 없앨 문제가 아니다

현장이 원래 그렇다. 불량률 1% 인 라인에서 불량 데이터를 50% 모으는 것은 불가능하고,
억지로 맞추면 그게 왜곡이다.

그래서 여기서 재는 것은 "얼마나 쏠렸는가"가 아니라
**"쏠림 때문에 무엇을 못 하게 되는가"**다.

## 실습

```bash
pytest -m lesson_2_5 -s
```

## 무엇을 보게 되는가

```text
불량률 0.3% 라인
  baseline 정확도  : 99.70%   ← 전부 NORMAL 이라고 찍었을 때
  불균형 비율      : 332배
  소수 클래스 표본 : 30개
  평가 집합 기대치 : 4.5개

[BALANCE] ... CRITICAL BALANCE_BASELINE_TOO_HIGH
```

## 네 가지 숫자가 서로 다른 이야기를 한다

### 1. baseline_accuracy — 지표가 먼저 무너진다

```python
@property
def baseline_accuracy(self) -> float:
    """아무것도 배우지 않고 다수 클래스만 찍었을 때의 정확도."""
    return max(self.class_counts.values()) / self.total_count
```

이 값이 95% 를 넘으면 **정확도라는 지표 자체를 쓸 수 없다.**
필요한 것은 재현율(recall)과 PR-AUC 다.

`'정확도 99.7%' 짜리 모델을 만들었다`는 보고서는
`아무것도 만들지 않았다`와 구별되지 않는다.

### 2. minority_count — 비율이 아니라 개수

```text
같은 50배 불균형, 다른 처방
  FAULT 2,000개 :  95.0점  PASSED_WITH_WARNINGS
  FAULT    20개 :  62.0점  FAILED
```

2,000개는 손실 가중치나 재표집으로 다룰 수 있다.
20개는 **데이터를 더 모으는 것 외에 방법이 없다.**

비율만 보면 이 둘이 같아 보인다. 그래서 개수를 따로 잰다.

### 3. expected_minority_in_test — 평가할 표본이 남는가

```text
평가 집합에 FAULT 가 15개 남는다.
그중 3개를 놓치면 재현율이 80%, 4개면 73% 다.
```

이 숫자로는 아무 결정도 못 한다. 모델 A 와 B 를 비교해도 차이가 우연인지 알 수 없다.

분할(실습 1-8)과 이어지는 지점이다. **나누기 전에 나눌 수 있는지부터 봐야 한다.**

### 4. imbalance_ratio — 학습이 소수 클래스를 무시하는가

가장 흔히 보는 숫자지만, 위 세 개보다 덜 중요하다.
비율이 크더라도 개수가 충분하고 평가가 가능하면 다룰 방법이 있기 때문이다.

## 그래서 WARNING 이다

```text
[BALANCE] 95.9 (A)  PASSED_WITH_WARNINGS
  - WARNING BALANCE_IMBALANCED (FAULT) 다수 클래스가 소수 클래스의 49배다.
```

오염 없는 `clean` 파일도 49배 불균형이다. 그게 현장이다.
막지 않고 **알려 준다.** 대신 baseline 정확도가 너무 높거나 소수 클래스 개수가
부족하면 CRITICAL 이 된다 — 그건 다룰 방법이 없어지는 지점이기 때문이다.

## 어떻게 대응할 것인가

| 상황 | 대응 |
|---|---|
| 비율만 나쁨, 개수는 충분 | `RESAMPLE` — 손실 가중치 / 오버샘플링 |
| 개수 자체가 부족 | `RECOLLECT` — 더 모은다. 다른 방법이 없다 |
| 평가 집합이 얇음 | 분할 전략 변경 (계층 분할) 또는 교차 검증 |
| baseline 이 너무 높음 | **지표를 바꾼다** — 정확도 대신 재현율·PR-AUC |

마지막 항목은 데이터 조치가 아니다. 그런데도 여기서 잡아 주는 이유는,
그 결정을 학습 시작 전에 내려야 하기 때문이다.

## 자주 하는 실수

- **SMOTE 를 먼저 돌린다.** 라벨 오류(2-4)가 있는 상태에서 오버샘플링하면
  틀린 라벨이 복제된다.
- **정확도로 모델을 고른다.** 불균형 데이터에서 정확도는 다수 클래스 비율의 다른 이름이다.
- **불균형을 데이터 결함으로 취급해 균형을 맞춘다.** 그러면 배포 환경과 분포가 달라진다.
