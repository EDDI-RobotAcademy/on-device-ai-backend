# 6-12. 실험을 기록하지 않으면 다시 만들 수 없다

## 문제

[3-14](3-14.md) 는 실험을 **비교**했다. 그건 한 사람의 노트북 안에서였다.
클라우드에서 학습을 돌리기 시작하면 문제가 달라진다.

```text
학습 잡이 30개 돈다.
아티팩트는 S3 에 있다.
파라미터는 각자의 노트북에 있다.
두 달 뒤 그 사람이 퇴사한다.
```

남는 것은 `s3://.../model.tar.gz` 파일 하나다.
**그 파일이 무엇으로 만들어졌는지 아무도 모른다.**

## 실습

```bash
pytest -m lesson_6_12 -s
```

## 재현에 필요한 넷

```text
데이터    어떤 데이터셋의 어느 버전인가
코드      어떤 커밋인가
설정      어떤 하이퍼파라미터인가
결과      무엇이 나왔는가
```

넷 중 하나라도 없으면 그 실험은 **다시 만들 수 없다.**
그리고 다시 만들 수 없는 모델은 **고칠 수도 없다.**

## 노트북이 아니라 S3 에 둔다

```text
experiments/{실험}/trials/{시행}/record.json
```

키 구조는 [6-2](6-2.md) 의 규칙을 그대로 따른다.
자주 걸러내는 것(실험)을 앞에 둔다 — 그래야 "이 실험의 시행 전부"가 접두어로 좁혀진다.

## 대장

```text
[window-length-sweep] 시행 2건
  win15             data=power-2026-05-11 code=a1b2c3d
    lr=3e-3 seed=42 stride=15 window=15
    accuracy=0.93 macro_f1=0.91
  win30             data=power-2026-05-11 code=a1b2c3d
    lr=3e-3 seed=42 stride=30 window=30
    accuracy=0.96 macro_f1=0.94  ←
  재현 가능 2/2건
```

## 넷 중 하나만 빠져도 막는다

```text
CRITICAL EXPR_NOT_REPRODUCIBLE
         'mystery' 에 코드 버전 가 없다.
         **이 시행은 다시 만들 수 없다.**
```

지표는 다 있다. 코드 버전 한 줄이 없다.
같은 데이터, 같은 파라미터로 돌려도 다른 숫자가 나올 수 있고 —
**왜 다른지 영영 알 수 없다.**

## 기록만 있고 파일이 없는 경우

```text
CRITICAL EXPR_ARTIFACT_MISSING
         1건이 **없는 파일**을 가리킨다: ghost.
         기록만 있고 결과물이 없으면 그 기록은 종이다.
```

**S3 에 실제로 있는지 확인한다.** 기록만 믿으면 안 된다 —
수명 주기 규칙이 지웠거나([6-13](6-13.md)), 다른 계정으로 옮겼을 수 있다.

## 데이터 버전은 클라우드에서 더 자주 어긋난다

```text
CRITICAL EXPR_DATA_VERSION_MIXED
         데이터 버전이 2종류인데 파라미터에 적혀 있지 않다.
         **모델을 비교한 것이 아니라 데이터를 비교한 것이다** ([3-14](3-14.md)).
```

클라우드에서는 잡마다 데이터가 다르기 쉬워서 더 자주 일어난다.

## 진짜 S3 요청이다

```python
store.record(entry)          # boto3 put_object
store.load(experiment_id)    # boto3 list_objects_v2 (paginated) + get_object
```

moto 안에서 돌지만 **요청은 진짜 boto3 가 만든다.**

## 자주 하는 실수

- **지표만 남긴다.** 조건이 없으면 재현할 수 없다.
- **노트북에 남긴다.** 사람이 바뀌면 사라진다.
- **아티팩트 존재를 확인 안 한다.** 기록만 있는 실험이 생긴다.
- **데이터 버전을 안 적는다.** 모델 비교가 데이터 비교가 된다.
