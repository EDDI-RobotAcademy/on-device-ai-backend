# 4-3. ONNX로 모델의 실행 경로를 바꿔라

## 문제

TorchScript 까지 왔지만 아직 PyTorch 런타임이 필요하다.

ONNX 는 파일 형식이자 **연산자 규격**이다.
PyTorch 의 연산이 ONNX 연산자로 **치환**되므로, 그 과정에서 의미가 조금 바뀔 수 있다.

## 실습

```bash
pytest -m lesson_4_3 -s
```

## 무엇을 보게 되는가

```text
후보 ONNX/FP32
  변환   : PYTORCH → ONNX (FP32)  표본 66개  max|diff| 3.815e-06  argmax 일치 100.00%
  크기   : 14,169B (가중치 12,748 + 오버헤드 1,421)
  속도   : p50 0.0080ms / p95 0.0088ms
  정확도 : 1.0000 / macro recall 1.0000
```

기준 대비 **3.6배 빨라졌고 파일은 오히려 작아졌다.**

## 치환은 숫자를 아주 조금 바꾼다

```text
TORCHSCRIPT : max|diff| 0.000e+00   argmax 일치 100.00%
ONNX        : max|diff| 3.815e-06   argmax 일치 100.00%
```

TorchScript 는 **같은 커널**을 쓰므로 차이가 정확히 0 이다.
ONNX Runtime 은 **다른 구현**을 쓰므로 부동소수점 마지막 자리가 흔들린다.

중요한 것은 그 흔들림이 **예측을 바꾸지 않았다**는 사실이다.
그래서 `EquivalencePolicy(max_abs_diff_fp32=1e-4)` 를 통과한다.

## 오버헤드가 형식마다 다르다

```text
ONNX/FP32          가중치  12,748B + 오버헤드   1,421B
TFLITE/FP32        가중치  12,748B + 오버헤드   4,032B
TFLITE/FP16        가중치   6,374B + 오버헤드   5,350B
TORCHSCRIPT/FP32   가중치  12,748B + 오버헤드   5,661B
TFLITE/INT8        가중치   3,187B + 오버헤드   6,325B
```

같은 가중치를 담는데 **ONNX 가 가장 작다.**

TorchScript 는 파이썬 코드 조각과 디버깅 정보를 함께 담고,
TFLite 는 인터프리터가 읽을 수 있는 형태의 메타데이터를 담는다.
ONNX 는 그래프만 담는다.

이 표는 [4-5](4-5.md) 에서 다시 다룬다.

## 배치 축만 동적으로 열어 둔다

```python
torch.onnx.export(
    module,
    (example,),
    path,
    input_names=["input"],
    output_names=["logits"],
    # 배치 축만 동적으로 둔다. 나머지가 동적이면 런타임이 최적화를 포기한다.
    dynamic_axes={"input": {0: "batch"}, "logits": {0: "batch"}},
    opset_version=17,
)
```

창 길이(30)와 채널 수(6)는 **고정**이다.
그 둘이 열려 있으면 런타임이 메모리 계획을 미리 세울 수 없다.

## 스레드 수를 여기서도 고정한다

```python
options = ort.SessionOptions()
options.intra_op_num_threads = 1     # 디바이스 조건에 맞춘다 (실습 4-1)
options.inter_op_num_threads = 1
```

세션을 만들 때 스레드를 안 잡으면 ONNX Runtime 은 코어를 전부 쓴다.
그렇게 잰 숫자는 **디바이스에서 재현되지 않는다.**

실습 4-1 의 `MeasurementProtocol(threads=1)` 은 측정 프로토콜이고,
이 설정은 그 프로토콜을 실제로 지키기 위한 런타임 설정이다. **둘 다 있어야 한다.**

## 이 파일은 여러 런타임이 읽는다

```text
ONNX 파일 하나
    ├── ONNX Runtime      (CPU / GPU / NNAPI / CoreML)
    ├── TensorRT          (NVIDIA)
    └── OpenVINO          (Intel)
```

프레임워크를 벗어났다는 것이 실제로 뜻하는 바다.
디바이스가 바뀌어도 같은 파일을 쓸 가능성이 생긴다.

## 자주 하는 실수

- **모든 축을 동적으로 연다.** 유연해 보이지만 최적화가 꺼진다.
- **opset 을 안 적는다.** 런타임 버전에 따라 다른 연산자가 선택된다.
- **스레드를 안 고정하고 잰다.** 4-1 의 측정 프로토콜이 무의미해진다.
- **변환 후 대조를 건너뛴다.** 치환된 연산자가 원래 의미와 다를 수 있다.
