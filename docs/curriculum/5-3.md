# 5-3. AI의 모든 판단을 로그로 남겨라

## 문제

"로그를 남기고 있습니다"는 답이 아니다.
**무엇을 남기고 있는가**가 답이다.

그리고 로그는 나중에 추가할 수 없다. **지나간 시간은 다시 안 온다.**

## 실습

```bash
pytest -m lesson_5_3 -s
```

## 무엇을 보게 되는가

```text
언제       : 2026-05-20 00:04:50
어느 디바이스 : DEV-01
어느 버전  : v1
무엇이라고 : NORMAL
얼마나 확신 : 0.882
몇 ms      : 0.0282
입력 지문  : ac8dfc9629dc0b89
정답       : (없음)
```

여섯 개가 각각 **나중에 나올 질문 하나씩**에 대응한다.

| 항목 | 없으면 못 하는 것 |
|---|---|
| 시각 | "언제부터 이상해졌죠?" (5-4) |
| 디바이스 | "전부요, 아니면 한 대만요?" (5-5) |
| 배포 버전 | "어느 모델이 낸 답이에요?" (5-2, 5-10) |
| 지연시간 | "느려진 건가요?" (5-5) |
| 확신도 | "모델이 헷갈리기 시작한 건가요?" (5-6) |
| 입력 지문 | "그때 그 입력 다시 넣어볼 수 있어요?" |

## 현장에는 정답이 거의 없다

```text
로그 34,533건  디바이스 3대  버전 1종  정답 11.9%
```

**모듈 5 전체가 이 한 줄 위에 서 있다.**

정답이 붙은 것은 11.9% 다. 나머지 88% 는 모델이 맞았는지 틀렸는지 아무도 모른다.
그래서 현장 정확도를 실시간으로 잴 수 없고,
지연시간·예측분포·입력분포로 **대신** 본다 ([5-5](5-5.md), [5-6](5-6.md), [5-7](5-7.md)).

```python
@property
def is_correct(self) -> bool | None:
    """정답이 붙어 있을 때만 답할 수 있다."""
    if self.ground_truth is None:
        return None
    return self.ground_truth == self.predicted_label
```

`False` 가 아니라 **`None`** 이다.
**'틀렸다' 와 '모른다' 는 다른 것이고, 현장은 대부분 '모른다' 다.**

## 빠진 항목마다 못 하게 되는 일이 정해져 있다

```text
CRITICAL LOG_MISSING_DEVICE (디바이스)
         디바이스가 빠진 로그가 있다.
         전부 이상한 것인지 한 대만 이상한 것인지 구분할 수 없다.  [측정 0.4 / 기준 1]
CRITICAL LOG_MISSING_VERSION (배포 버전)
         어느 모델이 낸 답인지 모른다. 롤백해도 나아졌는지 알 수 없다.
WARNING  LOG_MISSING_DIGEST (input_digest)
         입력 지문이 없다. 이상한 예측을 발견해도
         그때 무엇이 들어왔는지 되짚을 수 없다.
```

그래서 로그를 받는 API 는 **"받았습니다"만 돌려주지 않는다.**

```http
POST /deployments/dep-line3/logs   →  202 + LogCoverage
```

"받았습니다"만 돌려주면 반년 뒤에야 로그가 쓸모없다는 걸 알게 된다.

## 한 창에 두 버전이 섞이면

```text
WARNING LOG_MIXED_VERSIONS (deployment_version)
        한 창에 배포 버전이 2종 섞여 있다.
        이 구간의 숫자는 어느 모델의 것도 아니다.
```

배포 직후 구간이 대개 이렇게 된다.
그 창의 p95 를 "v2 의 성능"이라고 부르면 틀린다.

## 원본은 못 남긴다. 지문을 남긴다

```python
def _digest(device_id: str, moment: str) -> str:
    """입력 지문. 원본 신호를 전부 남길 수는 없다."""
    return hashlib.sha1(f"{device_id}|{moment}".encode()).hexdigest()[:16]
```

30 표본 × 6 채널을 추론마다 남기면 하루에 수 GB 가 된다.
지문은 16자다. **"그때 그 입력"을 되짚는 열쇠**로는 충분하다.

## 운영의 창 자르기는 학습과 다르다

```text
학습 (실습 3-8)   stride = window_length — 겹치면 분할이 샌다
운영              stride = 3            — 표본 몇 개마다 다시 판단한다
```

디바이스는 분할을 하지 않는다. **샐 것이 없다.**
겹치는 창으로 계속 판단하는 것이 오히려 정상이다.

## 예측은 진짜, 지연시간은 합성

이 실습의 로그는 **모듈 4 에서 고른 그 결과물**을 4일치 현장 신호에 실제로 돌려 만든다.
그래서 분포 이동도 확신도도 꾸며낸 숫자가 아니다.

지연시간만은 합성한다. 정직하게 밝혀 둔다 —
PC 에서 아무리 재도 디바이스의 발열 감쇠(thermal throttling)를 재현할 수 없다.

## 저장소는 지금 인메모리다

```python
class InMemoryInferenceLogStore:
    """domain.operations.ports.InferenceLogStore 구현."""
```

현장에서는 여기가 DynamoDB 나 S3 나 CloudWatch Logs 다.
모듈 6 에서 그쪽으로 옮긴다. **Domain 은 그 사실을 모른다.**

## 자주 하는 실수

- **예측만 남긴다.** 나머지 다섯 개가 없으면 5-4 부터 전부 못 한다.
- **정답이 없으니 정확도를 추정한다.** 없는 것을 있는 척하면 판단이 더 나빠진다.
- **로그를 나중에 붙인다.** 지나간 시간은 다시 안 온다.
- **"받았습니다"만 돌려준다.** 로그가 쓸모없다는 걸 반년 뒤에 안다.
