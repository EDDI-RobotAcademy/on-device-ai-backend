# 3-9. Accuracy 뒤에 숨어 있는 실패를 찾아라

## 문제

정확도 97.4% 짜리 모델을 만들었다. 보고서에 쓰기 좋은 숫자다.

그 숫자 뒤를 본다.

## 실습

```bash
pytest -m lesson_3_9 -s
```

## 무엇을 보게 되는가

```text
실제 \ 예측
                       FAULT  OVERLOAD    NORMAL
------------------------------------------------
FAULT                      7         0         1
OVERLOAD                   0        42         0
NORMAL                     0         4       141

class       support   recall  precision      f1
FAULT             8    0.875      1.000   0.933
OVERLOAD         42    1.000      0.913   0.955
NORMAL          145    0.972      0.993   0.983

정확도 0.974 / macro recall 0.949 / baseline 0.744
```

정확도 97.4% 다. 그런데 **FAULT 재현율은 87.5%** 다.

설비 정지 8건 중 1건을 놓쳤다.
**그 1건이 이 시스템을 만든 이유였다.**

## 가장 흔한 실패 — 소수 클래스를 아예 예측하지 않는다

```text
실제 \ 예측
                       FAULT  OVERLOAD    NORMAL
------------------------------------------------
FAULT                      0         0         8
OVERLOAD                   0        42         0
NORMAL                     0         0       145

정확도 0.959 / macro recall 0.667 / baseline 0.744
```

```text
CRITICAL EVAL_CLASS_NEVER_PREDICTED (FAULT)
         'FAULT' 를 한 번도 예측하지 않았다.
         이 클래스에 대해서는 모델이 존재하지 않는 것과 같다.
```

정확도 95.9%. baseline(74.4%)보다 **높다.**
손실도 잘 떨어졌을 것이고, 곡선도 예뻤을 것이다.

그런데 이 모델은 트립을 하나도 못 잡는다.

**macro recall 은 0.667 이다.** 클래스마다 같은 무게로 세면 실패가 바로 보인다.

```python
@property
def macro_recall(self) -> float:
    """클래스마다 같은 무게로 센 재현율. 불균형에 속지 않는 지표다."""
```

## 정확도가 baseline 을 못 넘으면 막는다

```text
CRITICAL EVAL_NO_BETTER_THAN_BASELINE
         정확도 74.4% 인데 다수 클래스만 찍어도 74.4% 다.
         모델이 실제로 벌어들인 것은 거의 없다.
```

전부 NORMAL 이라고 찍은 모델. 학습을 안 한 것과 결과가 같다.
실습 2-5, 3-6 에서 본 `baseline_accuracy` 가 여기서 판정 기준이 된다.

## 놓치면 안 되는 클래스는 기준이 다르다

트립을 놓치는 것과 과부하를 놓치는 것은 무게가 다르다.
**그 무게는 현장이 정한다.**

```python
EvaluationPolicy(
    critical_labels=frozenset({"FAULT"}),
    min_critical_recall=0.95,     # 치명 클래스
    min_recall_per_class=0.5,     # 나머지
)
```

같은 재현율이라도 FAULT 면 `CRITICAL`, 다른 클래스면 `WARNING` 이 된다.

## 정밀도와 재현율은 다른 실패를 말한다

```text
실제 \ 예측
                       FAULT  OVERLOAD    NORMAL
------------------------------------------------
FAULT                      8         0         0
OVERLOAD                   0        42         0
NORMAL                    60         0        85

class       support   recall  precision      f1
FAULT             8    1.000      0.118   0.211
```

```text
WARNING EVAL_PRECISION_RECALL_IMBALANCE (FAULT)
        'FAULT' 정밀도 0.12 vs 재현율 1.00. 한쪽으로 치우친 모델이다.
```

트립은 **하나도 안 놓쳤다**(재현율 100%).
대신 정상 60건을 트립이라고 했다(정밀도 12%).

**현장에서는 이 모델을 곧 꺼 버린다.** 알람이 하루에 60번 울리면 아무도 안 본다.

| 지표 | 무엇을 말하는가 | 낮으면 |
|---|---|---|
| 재현율(recall) | 이 클래스를 **놓치지 않았는가** | 사고를 못 잡는다 |
| 정밀도(precision) | 이 클래스라고 한 것이 **맞았는가** | 헛경보가 쏟아진다 |

둘 다 필요하다. 어느 쪽을 더 볼지는 현장이 정한다.

## 지연시간도 평가의 일부다

```text
p50 0.103ms / p95 0.120ms
```

**정확도만 재는 평가는 절반짜리다.**

이건 PC 에서 잰 숫자다. 디바이스에서는 10~100배가 된다.
그 사이를 메우는 것이 모듈 4다.

```python
def _latency(self, module, features) -> tuple[float, float]:
    """배치 1개짜리 추론 시간. 디바이스에서 재는 것과 같은 방식이다."""
    for _ in range(5):   # 워밍업 — 첫 호출은 항상 느리다
        module(sample)
```

## 혼동 행렬은 손으로 만들 수 있다

```python
matrix = ConfusionMatrix.from_pairs(
    ("A", "B"), [("A", "A"), ("A", "B"), ("B", "B"), ("B", "B")]
)
assert matrix.accuracy == 0.75
assert matrix.recall_of("A") == 0.5
assert matrix.precision_of("B") == pytest.approx(2 / 3)
```

(정답, 예측) 쌍만 있으면 만들어진다. torch 도 sklearn 도 필요 없다.
그래서 이 판정 로직은 파일 없이 시험할 수 있다.

## 자주 하는 실수

- **정확도 하나로 모델을 고른다.** 불균형 데이터에서 정확도는 다수 클래스 비율의 다른 이름이다.
- **혼동 행렬을 안 본다.** 어느 클래스를 무엇으로 착각하는지가 개선의 단서다.
- **재현율만 올린다.** 헛경보가 쏟아지면 시스템이 꺼진다.
- **지연시간을 나중에 잰다.** 정확도를 다 맞춘 뒤에 30ms 를 못 맞추면 처음부터 다시다.
