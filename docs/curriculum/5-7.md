# 5-7. Data Drift를 직접 찾아라

## 문제

실습 1-9 에서 이미 PSI 를 봤다. 그때는 **학습 전에** 물었다.

```text
학습 전   "이 데이터가 현실을 대표하는가?"
학습 후   "현실이 학습 데이터에서 얼마나 멀어졌는가?"
```

같은 계산, 다른 질문이다. 그리고 이쪽이 훨씬 중요하다 —
**데이터는 고정돼 있는데 현실은 계속 움직이기 때문이다.**

## 실습

```bash
pytest -m lesson_5_7 -s
```

## 1일차가 낮게 나오는 것이 먼저다

```text
창별 최대 PSI
  05-20 00시        0.0051
  05-20 08시        0.0052
  05-20 16시        0.0050
  05-21 00시        0.0119
  05-21 08시        7.3032   ← 도장 부스 문이 열렸다 (한 창)
  05-21 16시        0.0110
  05-22 00시        4.6248   ← 여기서부터 이어진다
  ...
  05-23 16시        9.4578
```

1일차 PSI 가 0.005 다. **이 숫자가 낮게 나오는 것이 먼저다.**
1일차부터 PSI 가 튀면 드리프트를 재는 게 아니라 창을 잘못 자른 것이다.

### 관측 창은 공정 주기의 배수여야 한다

이 설비의 느린 부하 주기는 8시간이다.

```text
창 4시간 → 1일차 PSI 1.47   (주기의 절반만 담긴다 — 온도가 오르는 구간만)
창 8시간 → 1일차 PSI 0.005  (주기 하나를 온전히 담는다)
```

4시간 창의 분포를 학습 전체 분포와 견주면 **드리프트가 없어도 PSI 가 튄다.**
그러면 1일차부터 알람이 울리고, 진짜 드리프트가 시작돼도 구분할 수 없다.

실습 1-9 에서 최근 표본을 한 주기에 맞췄던 것과 같은 이유다.

## 학습 분포를 안 남겨 두면 잴 수 없다

```text
WARNING OPS_NO_DRIFT_BASELINE
        입력 분포를 비교할 기준이 없다.
        학습 데이터의 분포를 남겨 두지 않으면 드리프트를 잴 수 없다.
```

드리프트는 **두 분포의 비교**다.
현장 데이터를 아무리 봐도 학습 분포가 없으면 달라졌는지 알 수 없다.

그래서 배포할 때 그것을 함께 내보내야 한다 ([5-1](5-1.md)).

## PSI 는 '다르다', 범위 밖은 '본 적 없다'

```text
CRITICAL OPS_INPUT_OUT_OF_RANGE (temperature_c)
         'temperature_c' 이 학습 때 본 적 없는 범위로 들어온다.
         모델은 이 구간에서 무슨 답을 할지 아무도 모른다 —
         틀리는 게 아니라 **정의되지 않는다.**  [측정 0.785 / 기준 0.01]
```

4일차에는 표본의 78.5% 가 학습 범위 밖이다.

| 지표 | 무엇을 말하는가 | 심각도 |
|---|---|---|
| PSI | 분포의 모양이 다르다 | WARNING |
| 범위 밖 비율 | **아예 본 적 없다** | CRITICAL |

뒤쪽이 훨씬 심각하다.
본 적 없는 구간에서 모델의 출력은 정의되지 않는다 —
그리고 [5-6](5-6.md) 에서 봤듯 **그때도 확신도는 높게 나온다.**

## 여러 채널이 동시에 움직이면 공정이 바뀐 것이다

```text
CRITICAL OPS_MULTI_FEATURE_DRIFT
         4개 채널이 동시에 움직였다.
         센서 하나가 고장 난 게 아니라 **공정 자체가 바뀐 것**에 가깝다.
```

```text
센서 하나 고장  → 채널 하나만 움직인다
공정 변화       → 여러 채널이 같이 움직인다
```

이 구분이 조치를 가른다. 앞은 정비 요청이고, 뒤는 재학습이다.

## 세 가지 드리프트 중 하나는 잴 수 없다

**이 사실을 아는 것이 이 모듈의 핵심이다.**

```text
입력 드리프트   들어오는 값이 변했다          → 잰다 (실습 5-7)
예측 드리프트   나가는 답이 변했다            → 잰다 (실습 5-6)
개념 드리프트   입력과 정답의 관계가 변했다   → **못 잰다**
```

개념 드리프트를 재려면 정답이 있어야 한다. 현장에는 없다.
그래서 앞의 둘로 **대신** 본다 — 대신 본다는 사실을 잊으면 안 된다.

## 기준은 통계가 아니라 재학습 비용이 정한다

```text
PSI 0.14, 기준 0.1  → OPS_INPUT_DRIFT        (조치)
PSI 0.14, 기준 0.2  → OPS_INPUT_DRIFT_WATCH  (지켜보기)
```

같은 숫자, 다른 판정.

교과서는 0.1 / 0.2 를 관례로 든다. 그러나 실제로 정하는 것은 이것이다.

```text
라벨링에 2주가 걸리는 현장  → 기준을 낮게 잡아 미리 시작한다
재학습이 하루면 끝나는 현장 → 기준을 높게 잡아 헛수고를 줄인다
```

## 자주 하는 실수

- **창을 아무렇게나 자른다.** 공정 주기와 안 맞으면 드리프트 없이도 PSI 가 튄다.
- **학습 분포를 안 남긴다.** 나중에는 비교 대상이 없다.
- **PSI 만 본다.** 범위 밖 표본이 훨씬 심각하다.
- **개념 드리프트를 재고 있다고 믿는다.** 정답 없이는 못 잰다.
