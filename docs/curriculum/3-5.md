# 3-5. 첫 번째 모델을 직접 학습시켜라

## 문제

학습은 **오래 걸리는 작업**이다 (CLAUDE.md §11).
HTTP 요청이 그것을 붙잡고 기다리는 구조를 만들면 안 된다.

```text
Command  →  Job          →  Job Status         →  Result
학습 요청 →  TrainingRun  →  RUNNING/COMPLETED  →  ModelVersion
```

## 실습

```bash
pytest -m lesson_3_5 -s
```

## 무엇을 보게 되는가

```text
학습 기록
  상태        : COMPLETED
  데이터      : power-model
  구조        : CNN1D input=(30, 6) hidden=(16, 32) k=5 → 3 classes
  설정        : epochs=10 batch=32 lr=0.003 opt=ADAM seed=42
  창          : length=30 stride=10 (겹침 67%) / FAULT 30% 이상 → ...
  epoch       : 10 (최저점 9)
  모델 버전   : mv-power-model-cnn1d-s42
```

**학습이 끝나야 `ModelVersion` 이 생긴다.** 그 전에는 '학습 중'이라는 상태만 있다.

## Aggregate 는 학습하지 않는다

```python
class TrainingRun(EventRecorder):
    """한 번의 학습.

    이 Aggregate 는 '학습하는 객체'가 아니라 **'학습이라는 사건의 기록'**이다.
    계산은 Infrastructure 가 하고, 여기에는 그 진행과 결과가 남는다.
    """
```

Application 이 하는 일은 네 줄이다.

```python
run.start()                  # 상태를 RUNNING 으로
outcome = trainer.train(...)  # Infrastructure 가 계산한다
for record in outcome.epochs:
    run.record_epoch(record)  # 결과를 Aggregate 에 기록
run.complete(version_id)      # 끝났다고 표시
```

학습률을 조정하거나 손실이 이상하면 멈추는 판단은 **여기에 없다.**
그건 Domain(`LearningPolicy` / `OverfittingPolicy`)의 일이다.

## HTTP 는 기다리지 않는다

```bash
POST /training-runs/run-1/start
→ 202 Accepted   {"status": "PREPARED", ...}
```

`202 Accepted` — "받았고, 하고 있다"는 뜻이다.
응답 시점의 상태는 아직 `PREPARED` 다. 그래서 200 이 아니라 202 다.

```bash
GET /training-runs/run-1
→ 200  {"status": "COMPLETED", "epoch_count": 10, "model_version_id": "mv-..."}
```

진행 상황은 물어본다. 라우트는 `BackgroundTasks` 에 던지고 즉시 돌아온다.

```python
@router.post("/{run_id}/start", status_code=status.HTTP_202_ACCEPTED)
def start_training_run(run_id, background: BackgroundTasks, container):
    view = container.get_training_run().execute(GetTrainingRunQuery(run_id=run_id))
    background.add_task(
        container.execute_training_run().execute,
        ExecuteTrainingRunCommand(run_id=run_id),
    )
    return TrainingRunResponse.from_view(view)
```

## 설정 하나하나가 결과를 바꾼다

```text
epochs=10 batch=32 lr=0.003 opt=ADAM seed=42
```

**특히 `seed`.** 이것이 없으면 "어제는 됐는데요"를 설명할 방법이 없다.

```python
def train(self, data, architecture, config, ...):
    torch.manual_seed(config.seed)
    np.random.seed(config.seed)
    generator = torch.Generator().manual_seed(config.seed)  # DataLoader 셔플까지
```

같은 seed 면 같은 결과가 나온다. 테스트가 그것을 확인한다.

```python
assert run_once() == pytest.approx(run_once(), rel=1e-9)
```

## 말이 안 되는 설정은 객체가 거부한다

```python
TrainingConfig(learning_rate=5.0)   # InvariantViolation
TrainingConfig(epochs=0)            # InvariantViolation
EarlyStoppingRule(patience=0)       # InvariantViolation
```

학습을 3분 돌린 뒤가 아니라 **설정을 만드는 순간**에 걸린다.

## 상태 전이가 순서를 지킨다

| 하려는 일 | 상태 | 결과 |
|---|---|---|
| epoch 기록 | `PREPARED` | `IllegalStateTransition` — 시작하지 않았다 |
| 완료 | epoch 0개 | `InvariantViolation` — 기록이 없다 |
| 재시작 | `COMPLETED` | `IllegalStateTransition` |
| 실패 처리 | `COMPLETED` | `IllegalStateTransition` — 이미 끝났다 |
| epoch 을 거꾸로 | `RUNNING` | `InvariantViolation` — 순서대로여야 한다 |

## 실패도 기록된다

```python
run.fail("  ")
# InvariantViolation: 실패 이유가 없으면 다시 시도할 근거가 없다.

run.fail("CUDA out of memory (batch_size=512)")
# status = FAILED, failure_reason 에 남는다
```

Application 은 예외를 잡아 기록하고 **다시 던진다.**

```python
except Exception as exc:
    run.fail(f"{type(exc).__name__}: {exc}")
    commit(self._runs, run, self._publisher)
    raise
```

기록하고 삼키면 아무도 실패를 모른다. 기록하지 않고 던지면 이유가 남지 않는다.

## 모든 것이 이벤트로 남는다

```text
TrainingRunPrepared
TrainingRunStarted
EpochCompleted × 10
TrainingRunCompleted
```

모듈 5(운영)에서 "이 모델이 언제 어떤 설정으로 만들어졌나"를 되짚을 근거다.

## 자주 하는 실수

- **HTTP 핸들러 안에서 `model.fit()` 을 부른다.** 30분짜리 요청이 만들어진다.
- **seed 를 안 박는다.** 재현이 안 되면 개선했는지 운이 좋았는지 알 수 없다.
- **학습 스크립트에 하이퍼파라미터를 상수로 박는다.** 어떤 설정으로 만든 모델인지 남지 않는다.
