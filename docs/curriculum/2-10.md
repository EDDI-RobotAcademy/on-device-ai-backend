# 2-10. AI를 학습시키기 전에 Data Quality Gate를 통과시켜라

## 문제

여섯 축을 다 쟀다. 점수도 냈다. 이제 **통과시킬 것인가, 막을 것인가.**

## 실습

```bash
pytest -m lesson_2_10 -s
```

## 무엇을 보게 되는가 — 같은 파일, 두 게이트

```text
[모듈 1] 학습 착수 판정: PASSED_WITH_WARNINGS  (dirty)
         수행한 검사: LABEL_SPACE, PARTITION, SCHEMA,
                     SIGNAL_PLAUSIBILITY, TIME_AXIS, TRAINING_SPEC
```

```text
[모듈 2] Data Quality Gate: FAILED  (dirty)
         종합 점수: 69.7 (D)

차원                    점수  판정
--------------------------------------------
BALANCE             97.1  PASSED_WITH_WARNINGS
COMPLETENESS        77.4  FAILED
LABEL_QUALITY       59.8  FAILED
NOISE               43.8  FAILED
UNIQUENESS          85.9  FAILED
VALIDITY            61.6  FAILED

차단 사유:
  ✗ COMPLETENESS 는 차단 축이며 판정이 FAILED 다
  ✗ LABEL_QUALITY 는 차단 축이며 판정이 FAILED 다
  ✗ NOISE 점수 43.8 < 50
  ✗ 종합 점수 69.7 < 80
```

하나는 통과하고 하나는 막는다. **둘은 다른 질문을 하고 있다.**

| | 묻는 것 |
|---|---|
| **모듈 1** | 이 데이터가 **무엇인지 아는가** — 구조/시간/라벨정의/분할/대표성 |
| **모듈 2** | 이 데이터가 **쓸 만한가** — 결측/이상치/라벨오류/불균형/잡음/중복 |

둘 다 통과해야 모델 학습(모듈 3)으로 넘어간다.

## 점수와 차단 축을 함께 본다

모듈 1의 판정은 순수하게 **심각도 기반**이었다 — CRITICAL 하나면 차단.
품질은 그렇게 다룰 수 없다. 잡음이 조금 있는 데이터는 흔하고,
그때마다 막으면 **아무도 이 게이트를 쓰지 않는다.**

그래서 네 가지 차단 사유를 둔다.

| 차단 사유 | 언제 |
|---|---|
| 차단 축 FAILED | `LABEL_QUALITY` / `COMPLETENESS` 는 점수와 무관하게 막는다 |
| 축 점수 미달 | 한 축이라도 50점 아래 |
| 종합 점수 미달 | 가중 평균 80점 아래 |
| 측정 누락 / 조치 미검증 | 아래 참조 |

`NOISE` 는 차단 축이 아니지만 점수 43.8 로 막혔다.
반대로 점수가 80점이고 CRITICAL 이 하나 있는 `NOISE` 는 통과한다 — 그건 의도다.

## 측정하지 않은 축이 있으면 통과할 수 없다

```text
[한 축만 측정한 경우]
Data Quality Gate: FAILED
종합 점수: 100.0 (A)
측정하지 않은 축: BALANCE, LABEL_QUALITY, NOISE, UNIQUENESS, VALIDITY
차단 사유:
  ✗ BALANCE 를 측정하지 않았다
  ...
```

**종합 점수는 100점인데 막혔다.**

'측정하지 않았다'는 '문제 없다'가 아니다.
모듈 1(실습 1-10)과 같은 원칙이고, 실습 2-4(라벨 규칙 없음)와도 같은 원칙이다.

이 원칙이 없으면 검사를 건너뛰는 것이 가장 빠른 통과 방법이 된다.

## 조치했으면 재측정해야 한다

```text
✗ COMPLETENESS 에 조치를 기록했으나 재측정하지 않았다
```

실습 2-9 에서 본 규칙이 게이트에서 강제된다.
**고쳤다는 주장은 측정으로만 확인된다.**

## 기준은 현장이 정한다

```text
같은 데이터에 대한 두 기준
  일반 라인 : PASSED_WITH_WARNINGS (종합 99.1)
  안전 라인 : FAILED (종합 99.1)
    ✗ BALANCE 점수 95.9 < 96
    ✗ 종합 점수 99.1 < 100
```

```python
QualityGatePolicy(
    minimum_overall_score=99.5,
    minimum_dimension_score=96.0,
    blocking_dimensions=frozenset(QualityDimension),  # 전부 차단 축
)
```

`QualityGatePolicy` 는 Value Object 다. 라인마다, 제품마다, 안전 등급마다 다를 수 있다.
그리고 코드로 관리되므로 **누가 언제 왜 기준을 바꿨는지**가 git 에 남는다.

## 판정된 평가는 몰래 바뀌지 않는다

```python
IllegalStateTransition: PASSED 상태에서는 'NOISE 측정 기록' 을 할 수 없다.
                        reopen(reason) 으로 판정을 되돌린 뒤 수정한다.
```

되돌리려면 이유를 남겨야 한다. 모듈 1의 `Dataset.reopen` 과 같은 구조다.

## 전체 과정이 이벤트로 남는다

```text
QualityAssessmentStarted
QualityDimensionMeasured × 6
RemediationRecorded
QualityGateBlocked
```

누가 언제 무엇을 측정했고 왜 막혔는지가 남는다.
석 달 뒤 "그때 왜 학습을 시작했나"에 답할 수 있는 유일한 근거다.
(CLAUDE.md §19 — 관측 가능성은 나중에 붙이는 것이 아니다)

## API 로 해보기

```bash
# 1. 평가 시작
curl -X POST localhost:8000/datasets/plant-power-quality/quality-assessments \
     -H 'Content-Type: application/json' -d '{"assessment_id": "qa-2026-04"}'

# 2. 여섯 축 측정 (라벨은 규칙과 함께)
for d in completeness validity balance noise uniqueness; do
  curl -X POST localhost:8000/quality-assessments/qa-2026-04/dimensions/$d \
       -H 'Content-Type: application/json' -d '{}'
done
curl -X POST localhost:8000/quality-assessments/qa-2026-04/dimensions/label-quality \
     -H 'Content-Type: application/json' -d @label-rules.json

# 3. 점수와 학습 영향
curl -X POST localhost:8000/quality-assessments/qa-2026-04/score \
     -H 'Content-Type: application/json' -d '{}'

# 4. 게이트
curl -X POST localhost:8000/quality-assessments/qa-2026-04/gate \
     -H 'Content-Type: application/json' -d '{}'
```

전체 흐름은 [`api-examples.http`](../../api-examples.http) 에 있다.

## 자주 하는 실수

- **게이트를 통과할 때까지 기준을 낮춘다.** 기준을 낮추는 것 자체는 정당할 수 있지만,
  **누가 언제 왜 낮췄는지**가 남아야 한다.
- **게이트를 한 번만 통과하고 잊는다.** 데이터가 늘어나면 다시 판정해야 한다.
- **모듈 1만 통과시키고 학습을 시작한다.** 이 모듈 전체가 그 반례다.

## 모듈 2 를 마치며

열 개의 실습이 하나의 Bounded Context 를 만들었다.

```text
domain/data_quality/
├── assessment.py       Aggregate Root — 측정 → 조치 → 재측정 → 게이트
├── target.py           남의 Aggregate 를 우리 언어로 번역한 VO       (2-1)
├── dimensions.py       품질의 축과 점수                              (2-1, 2-8)
├── completeness.py     값이 있는가                                   (2-2)
├── validity.py         값이 말이 되는가                              (2-3)
├── label_quality.py    정답이 맞는가                                 (2-4)
├── balance.py          클래스가 고른가                               (2-5)
├── noise.py            신호가 묻히지 않았는가                        (2-6)
├── uniqueness.py       같은 것을 반복하고 있지 않은가                 (2-7)
├── comparison.py       고치기 전과 후                                (2-9)
├── remediation.py      무엇을 왜 고쳤는가                            (2-9)
└── gate.py             통과시킬 것인가                               (2-10)
```

이 Context 는 `domain/data` 를 **한 줄도 import 하지 않는다.**
두 모듈은 같은 파일을 보지만 서로를 모른다. 그 경계를 테스트가 지킨다.

```bash
pytest tests/test_architecture.py -k Bounded_Context
```
