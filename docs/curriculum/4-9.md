# 4-9. Memory와 Compute 병목을 직접 찾아라

## 문제

[4-8](4-8.md) 에서 INT8 이 오히려 느려졌다. **왜인지 설명할 수 있어야 한다.**

층이 느린 이유는 둘 중 하나다.

```text
계산이 많다      → COMPUTE_BOUND. 연산을 줄이면 빨라진다.
데이터를 나른다  → MEMORY_BOUND.  연산을 줄여도 안 빨라진다. 옮기는 게 느리다.
```

## 실습

```bash
pytest -m lesson_4_9 -s
```

## 무엇을 보게 되는가

```text
layer                       MACs       bytes   intensity  병목
----------------------------------------------------------------------
features.0                14,400       4,624        3.11  COMPUTE_BOUND
features.1                     0       3,840        0.00  MEMORY_BOUND
features.2                76,800      16,128        4.76  COMPUTE_BOUND
features.3                     0       7,680        0.00  MEMORY_BOUND
pool                           0       3,968        0.00  MEMORY_BOUND
dropout                        0         256        0.00  MEMORY_BOUND
classifier                    96         536        0.18  MEMORY_BOUND
----------------------------------------------------------------------
합계                        91,296      37,032        2.47
  edge-mcu: 2 GMAC/s, 1.6 GB/s → 균형점 1.2 MAC/byte
  지배적 병목: COMPUTE_BOUND
```

## 산술 강도와 균형점

```text
산술 강도 = MAC 수 / 옮긴 바이트 수          "1바이트를 나를 때 몇 번 계산하는가"
균형점    = 연산 성능(MAC/s) / 대역폭(byte/s)  "이 기계가 감당하는 비율"

강도 < 균형점  → 메모리가 못 따라온다 (MEMORY_BOUND)
강도 > 균형점  → 연산기가 못 따라온다 (COMPUTE_BOUND)
```

이 보드의 균형점은 **1.25 MAC/byte** 다 (2 GMAC/s ÷ 1.6 GB/s).

Conv 층들은 강도가 3~5 로 균형점보다 높다 → **연산 병목.**
ReLU·pool·dropout 은 계산이 0 인데 데이터는 옮긴다 → 메모리 병목.

연산량 기준으로 세면 **전체의 99.9% 가 연산 병목 구간**이다.

```text
INFO ROOFLINE_COMPUTE_BOUND (compute)
     연산 병목이 우세하다. 양자화로 크기는 줄어도 속도는 기대만큼 안 빨라질 수 있다.
```

**이 한 줄이 4-8 의 결과를 미리 설명한다.** INT8 은 옮기는 바이트를 줄이는 기술이다.
이 모델은 옮기는 데서 막히지 않았으므로, 줄여도 얻을 것이 없었다.

## 병목은 모델의 성질이 아니다

이 실습에서 가장 중요한 문장이다.

```text
대역폭이 좁은 보드: 8 GMAC/s, 0.4 GB/s → 균형점 20.0 MAC/byte
    → 지배적 병목 MEMORY_BOUND

연산기가 약한 보드: 0.2 GMAC/s, 3.2 GB/s → 균형점 0.1 MAC/byte
    → 지배적 병목 COMPUTE_BOUND
```

**모델은 하나도 안 바뀌었다. 균형점만 바뀌었다.**

```python
layer.arithmetic_intensity          # 4.76 — 층의 성질, 고정
layer.bottleneck(machine_balance)   # 판정 — 기계가 정한다
```

그러니 "이 모델은 메모리 병목이다"라는 말은 **보드를 빼고는 성립하지 않는다.**

## 메모리 병목이면 양자화가 잘 듣는다

```text
layer                       MACs       bytes   intensity  병목
----------------------------------------------------------------------
depthwise                  8,000     122,000        0.07  MEMORY_BOUND
classifier                   500       3,000        0.17  MEMORY_BOUND
----------------------------------------------------------------------
합계                         8,500     125,000        0.07

INFO ROOFLINE_MEMORY_BOUND (memory)
     연산의 100% 가 메모리 병목 구간이다. 연산을 줄여도 별로 안 빨라진다 —
     데이터를 줄여야 한다. 양자화(FP16/INT8)가 잘 듣는 상황이다.
```

depthwise convolution 처럼 계산 대비 데이터 이동이 많은 층이 그렇다.
**이런 모델에서는 INT8 이 실제로 빨라진다** — 옮기는 바이트가 1/4 이 되기 때문이다.

| 병목 | 효과가 있는 최적화 | 효과가 없는 최적화 |
|---|---|---|
| MEMORY_BOUND | 양자화, 채널 수 줄이기, 융합 | 연산 줄이기 |
| COMPUTE_BOUND | 연산 줄이기, 더 빠른 커널, 가속기 | 양자화(속도 면에서) |

## 한 층이 전체를 차지하면 거기부터 고친다

```text
WARNING ROOFLINE_SINGLE_HOTSPOT (features.2)
        'features.2' 한 층이 전체 연산의 84% 를 차지한다.
        여기를 고치지 않으면 나머지를 아무리 줄여도 소용없다.
```

두 번째 Conv 층(16→32채널, 커널 5) 하나가 76,800 MAC 이다.
나머지 여섯 층을 전부 없애도 전체는 16% 밖에 안 줄어든다.

## 측정은 Infrastructure, 판정은 Domain

```python
# infrastructure/optimization/measurement.py
costs.append(
    LayerCost(
        name=layer.name,
        mac_count=layer.mac_count,               # 모듈 3 의 프로파일러가 이미 센 값
        weight_bytes=layer.parameter_count * 4,
        activation_bytes=(previous + current) * 4,  # 입력 + 출력
    )
)
```

Infrastructure 는 **숫자만 센다.** 병목이 무엇인지는 말하지 않는다.

```python
# domain/optimization/roofline.py
def bottleneck(self, machine_balance: float, *, tolerance: float = 0.25) -> BottleneckKind:
    ratio = self.arithmetic_intensity / machine_balance
    if ratio < 1.0 - tolerance:
        return BottleneckKind.MEMORY_BOUND
    if ratio > 1.0 + tolerance:
        return BottleneckKind.COMPUTE_BOUND
    return BottleneckKind.BALANCED
```

판정은 Domain 이 한다. torch 없이, 파일 없이 시험할 수 있다.

## 자주 하는 실수

- **보드를 빼고 병목을 말한다.** 균형점 없이는 판정할 수 없다.
- **연산량만 줄인다.** 메모리 병목 구간에서는 아무 일도 안 일어난다.
- **양자화가 항상 빠르게 만든다고 믿는다.** 연산 병목이면 오히려 느려진다.
- **핫스팟을 안 찾고 전체를 조금씩 줄인다.** 84% 를 놔두고 16% 를 다듬는다.
