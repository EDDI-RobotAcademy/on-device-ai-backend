# 2-6. Noise를 제거하지 않으면 AI가 Noise를 배운다

## 문제

모델은 우리가 가르친 것을 배운다. 잡음을 남겨 두면 잡음을 배운다.

그런데 **반대쪽 함정이 더 위험하다.**

전력 데이터에서 우리가 찾는 것은 대부분 짧고 뾰족한 사건이다.
이동평균 창을 키울수록 SNR 은 좋아지고, 그 사건은 사라진다.

그래서 이 검사는 두 방향을 함께 본다.

```text
SNR 이 너무 낮다        → 잡음이 신호를 덮었다
고주파 성분이 너무 없다  → 이미 누군가 과하게 매끈하게 만들었다
```

## 무엇을 보게 되는가

```text
[NOISE] 43.8 (F)  FAILED
  - CRITICAL NOISE_SNR_LOW (voltage_v) 신호 대 잡음비가 2.6dB 다.
                                       이 상태로 학습하면 모델이 잡음의 모양을 외운다.
                                       [측정 2.638 / 기준 20]
  - WARNING  NOISE_JITTER  (voltage_v) 값이 매 표본마다 방향을 바꾼다(톱니).
                                       [측정 0.9933 / 기준 0.75]
```

**여섯 채널 중 다섯은 멀쩡한데 전압 하나가 무너졌다.**
그래도 이 축의 점수는 43.8 이다 — 평균이 아니라 **가장 나쁜 채널**로 내기 때문이다.

평균을 내면 55점짜리 감점이 1/6 로 희석되어 91점이 된다.
그러면 "품질 A등급 데이터"로 학습을 시작하고, 전압 채널은 계속 쓰레기다.

## SNR 을 어떻게 재는가

```text
추세  = 이동 중앙값 (튀는 값에 끌려가지 않는다)
잔차  = 원신호 - 추세
SNR   = 10·log10( var(추세) / robust_var(잔차) )
```

이동 '평균'이 아니라 이동 '중앙값'을 쓴다.
평균은 이상치 하나에 추세 자체가 끌려가서 잔차가 과소평가된다.

### 잔차도 강건하게 재야 한다

`clean` 파일에는 설비 정지(FAULT) 구간이 150개 있다.
정지하면 전력이 150kW → 15kW 로 떨어진다. 이것을 잔차의 **분산**으로 재면
SNR 이 25dB 에서 6dB 로 무너진다. **진짜 사건이 잡음으로 계산되는 것이다.**

```python
def _robust_variance(residual: np.ndarray) -> float:
    """MAD 기반 잔차 분산.

    설비 정지처럼 드물고 큰 사건은 잔차를 크게 만든다.
    그것은 잡음이 아니라 신호다. 중앙값 기반 척도는 거기에 끌려가지 않는다.
    """
    mad = np.median(np.abs(residual - np.median(residual)))
    return (1.4826 * mad) ** 2
```

실습 2-3 에서 배운 것과 **같은 이유**로 여기서도 강건 척도를 쓴다.

## 톱니(jitter)는 계통 문제의 신호다

```text
부호 반전율 99.3%. 백색잡음이면 약 67% 가 나온다.
```

값이 거의 매 표본마다 방향을 바꾼다는 뜻이다.
이건 무작위 잡음이 아니라 **전원 주파수와 샘플링 주파수의 간섭(aliasing)**이다.

```python
max_reversal_ratio: float = 0.75
"""백색잡음의 기대값이 약 0.67 이다. 0.75 를 넘으면 거의 매 표본 방향이 바뀐다는 뜻으로,
전원 주파수와 샘플링 주파수의 간섭(aliasing) 같은 계통 문제를 의심해야 한다."""
```

중요한 것: **필터링이 아니라 수집 설정을 고쳐야 한다.**
톱니를 필터로 지우면 겉보기 SNR 은 좋아지지만, 실제 신호는 여전히 없다.

## 과하게 매끈한 데이터도 막는다

```text
CRITICAL NOISE_OVERSMOOTHED  고주파 성분이 거의 없다. 누군가 이미 평활화한 데이터일 수 있다.
                             짧고 뾰족한 이상 징후는 그 과정에서 사라진다.
```

SNR 은 완벽한데 사건이 하나도 없는 데이터.
"품질이 좋아 보이는" 데이터가 실은 아무것도 배울 수 없는 데이터인 경우다.

이 검사가 없으면, **잡음을 지우려는 노력이 그대로 데이터를 망가뜨리는 방향으로 간다.**

## 어떻게 고칠 것인가

| 상황 | 조치 | 주의 |
|---|---|---|
| 백색잡음 | `SMOOTH` | 창 크기를 사건 지속시간보다 짧게 |
| 톱니(aliasing) | 수집 설정 변경 → `RECOLLECT` | 필터로 덮지 말 것 |
| 특정 채널만 붕괴 | 그 채널을 입력에서 제외 | 학습 설계(1-7) 재검토 |
| 이미 평활화됨 | 원본 재확보 | 되돌릴 수 없다 |

## 자주 하는 실수

- **일단 이동평균부터 건다.** 창 크기를 정하기 전에 사건 지속시간을 먼저 재야 한다.
- **채널별 SNR 을 평균 낸다.** 망가진 하나가 사라진다.
- **톱니를 필터로 지운다.** 증상만 지우고 원인은 계속 데이터를 오염시킨다.
