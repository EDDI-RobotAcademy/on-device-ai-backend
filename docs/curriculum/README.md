# 실습 교재

온디바이스 AI 엔지니어 과정의 실습 문서다.
각 문서는 하나의 실습이며, **테스트를 돌려 결과를 눈으로 확인하는 것**으로 끝난다.

## 시작하기

```bash
bash scripts/setup.sh      # 라이브러리 전부 설치 + 점검 + 실습 데이터 생성 + 전체 테스트
```

이후에는 실습별로:

```bash
pytest -m lesson_1_5 -s    # 실습 1-5 의 결과를 출력과 함께 본다
```

`-s` 를 빼면 통과/실패만 보인다. **반드시 `-s` 를 붙여서 숫자를 봐라.**
숫자를 보지 않는 실습은 아무것도 가르치지 않는다.

보드에 올라가는 쪽(온디바이스 추론 실행 코드)은 [`edge-agent/`](../../edge-agent/README.md) 에 있다.
실습 [5-12](5-12.md) 를 백엔드에서 본 뒤, 같은 다섯 단계가 디바이스에서 어떻게 도는지 거기서 본다.

API 로 같은 흐름을 해보려면:

```bash
.venv/bin/uvicorn main:app --reload   # http://127.0.0.1:8000/docs
```

## 네 게이트, 그리고 그 뒤

앞의 네 모듈은 **각각 다른 질문**을 한다. 앞을 통과했다고 뒤가 통과되지 않는다.

```text
모듈 1  이 데이터가 무엇인지 아는가   → 구조/시간/라벨정의/분할/대표성
모듈 2  이 데이터가 쓸 만한가          → 결측/이상치/라벨오류/불균형/잡음/중복
모듈 3  이 모델이 쓸 만한가            → 학습곡선/과적합/평가규율/클래스별성능/지연시간
모듈 4  이 모델을 이 디바이스에 올릴 수 있는가
                                       → 변환동등성/지연시간/크기/RAM/클래스별하락
------------------------------------------------------------------------
모듈 5  이것이 **아직** 괜찮은가       → 로그/시간선/지연시간/예측분포/입력분포
모듈 6  이것을 **수천 대에서** 할 수 있는가
                                       → 업링크/데이터레이크/원격학습/OTA/롤백/계보
        그리고 다시 모듈 1 로 돌아간다
```

```text
데이터 → 품질 → 모델 → 최적화 → 운영 → 클라우드 → **다시 데이터**
```

네 게이트를 모두 통과해야 배포로 넘어가고, 배포한 뒤에는 모듈 5 가 계속 묻는다.
그리고 다섯 게이트는 같은 형태를 갖는다.

```text
측정(Infrastructure) → 판정(Domain Policy) → 인증서(Certificate) → 이벤트
```

| `plant_power_model_train.csv` | 모듈 3. 두 게이트를 통과한 36시간 학습 데이터 |
| `plant_power_model_field.csv` | 모듈 3. **현장 홀드아웃** — 이틀 뒤 12시간 |
| `plant_power_operations.csv` | 모듈 5. **배포 뒤 4일치 현장 신호**, 디바이스 3대 (O01~O06) |
| `castings/` | 다이캐스팅 부품 이미지 51장. 결함 5종 (I01~I05) |

`clean` 과 `dirty` 는 **열 구성도, 행 수도, 타임스탬프도 완전히 같다.**
그래서 모듈 1의 검사로는 둘을 구분할 수 없다 — 그것이 실습 2-1 의 출발점이다.

모듈 5 의 데이터에는 **오염이 없다. 대신 시간이 있다.**
4일치가 하루씩 조금씩 달라지고, 그 변화를 잡아내는 것이 모듈 5 전체다.
추론 로그는 이 파일에 없다 — **모듈 4 가 고른 결과물을 실제로 돌려서** 만든다.

**정답을 모르는 상태로 실습하지 마라.** 정답을 아는 데이터로 눈을 만든 뒤에,
정답을 모르는 현장 데이터로 나가는 것이 순서다.

## 구조와의 관계

각 실습 문서 상단의 YAML 은 그 실습이 코드의 어느 지점과 연결되는지를 적어 둔 것이다.

```text
Curriculum → Capability → Use Case → Domain → Application → Infrastructure → API → Test
```

교육 제목 하나마다 Domain 을 만들지 않는다.
열 개의 실습이 하나의 Bounded Context(`domain/data`)를 함께 만든다.
