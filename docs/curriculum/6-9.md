# 6-9. 문제가 생기면 이전 모델로 되돌려라

## 문제

모듈 5 의 롤백은 기록 하나를 바꾸는 일이었다.
수천 대에서는 다르다.

> **롤백도 또 하나의 롤아웃이다.**

똑같이 단계로 나가고, 똑같이 오프라인 디바이스를 만나고, 똑같이 시간이 걸린다.
**"되돌렸습니다"라고 말한 순간에도 현장의 절반은 아직 새 모델을 돌리고 있다.**

## 실습

```bash
pytest -m lesson_6_9 -s
```

## 되돌리기는 이제 시작이다

```text
롤아웃 ro-1-rollback  v1.0.0  → RUNNING
------------------------------------------------------------------------------
  wave-1           2대  (대기)
  wave-2           6대  (대기)
------------------------------------------------------------------------------
  도달 0/8대 (0.0%)  실패 0  미도달 0
```

**아직 아무것도 안 돌아갔다.** 계획을 세우고 첫 단계를 시작했을 뿐이다.

모듈 5 의 롤백은 여기서 끝났다. 여기서는 이제 시작이다.

## 되돌리는 데도 단계가 있다

**되돌리는 것도 잘못될 수 있다.**
이전 모델이 지금 환경에서 안 돌 수도 있다 — 펌웨어가 바뀌었거나, 설정이 달라졌거나.

그래서 되돌릴 때도 몇 대로 먼저 확인한다.

## 새 버전을 받은 디바이스만 되돌린다

```text
v2.0.0 을 받은 디바이스 : 8대  ← 되돌린다
아직 v1.0.0 인 디바이스 : 16대 ← 그대로 둔다
되돌리기 대상          : 8대
```

```python
affected = [
    device.device_id
    for device in fleet.reachable_devices()
    if device.current_version == broken.version
]
```

전부에게 다시 내보내면 **멀쩡한 디바이스까지 건드린다.**
OTA 는 그 자체로 위험한 작업이다 — 안 해도 되는 대상에는 안 하는 것이 맞다.

## 돌아갈 곳이 없으면 되돌릴 수 없다

```text
[CONFLICTING_REQUEST] 돌아갈 버전이 없다. 첫 배포였다면 되돌릴 곳이 없다 —
    격리(모듈 5)가 유일한 수단이다.
```

실습 5-1 의 **"첫 배포는 좁게"** 가 여기서 값을 한다.
되돌릴 수 없으니 겪는 대수를 줄이는 수밖에 없다.

```text
[DEPLOYMENT_VERSION_NOT_FOUND] v0.9.0: 'v0.9.0' 은 이 플릿에 등록된 적이 없다.
    돌아갈 곳이 없으면 롤백이 아니다.
```

그래서 채널에서 밀려난 릴리스를 **지우지 않는다** ([6-7](6-7.md)).

## 진행하던 작업은 취소한다

```python
self._gateway.cancel(broken.id, command.reason)
```

안 그러면 꺼져 있던 디바이스가 나중에 깨어나
**되돌린 뒤에 새 모델을 받는다.** 그게 가장 찾기 어려운 버그가 된다.

## 무엇이 무엇을 되돌렸는가

```text
원래 롤아웃 ro-1          → ROLLED_BACK
  2026-05-25 09:00:00  되돌림 — v2.0.0 배포 후 FAULT 재현율 붕괴

새 롤아웃 ro-1-rollback   → RUNNING
  2026-05-25 09:00:00  시작 — wave-1 (2대)
```

**양쪽에 남는다.** 사건 조사는 이 두 이력을 나란히 읽는다.

이유 없는 되돌리기는 막는다 — `'일단 되돌림'` 은 반년 뒤에 아무 도움이 안 된다.

## 되돌리는 동안 현장은 섞여 있다

**이게 수천 대의 현실이다.**

```text
디바이스 24대
  버전
    v2.0.0                8대
    v1.0.0               16대
```

일부는 되돌아갔고 일부는 아직이다. **이 상태가 몇 시간에서 며칠 간다.**

그 사이에 들어오는 추론 로그는 두 모델이 섞여 있다 —
모듈 5 의 `LOG_MIXED_VERSIONS` 가 여기서 나온다.

## 롤백이 듣는 경우와 아닌 경우

```text
새 모델 자체가 나빴다        → 롤백이 듣는다
세상이 변했다 (입력 드리프트) → **이전 모델도 그 입력을 본 적이 없다**
```

후자면 필요한 것은 롤백이 아니라 재학습이다 —
그리고 그 재학습이 [6-4](6-4.md) 다. 순환이 여기서 다시 시작된다.

## API

```http
POST /rollouts/ro-1/rollback   → 202
{
  "fleet_id": "line3",
  "new_rollout_id": "ro-1-rollback",
  "reason": "v2.0.0 배포 후 FAULT 재현율 붕괴",
  "to_version": "v1.0.0"
}
```

**202 다.** 되돌리기 계획을 받았다는 뜻이지 되돌아갔다는 뜻이 아니다.

## 자주 하는 실수

- **"되돌렸다"고 보고한다.** 아직 절반은 새 모델을 돌리고 있다.
- **전부에게 다시 내보낸다.** 멀쩡한 디바이스까지 건드린다.
- **진행하던 작업을 안 취소한다.** 깨어난 디바이스가 새 모델을 받는다.
- **드리프트를 롤백으로 고치려 한다.** 이전 모델도 그 입력을 모른다.
