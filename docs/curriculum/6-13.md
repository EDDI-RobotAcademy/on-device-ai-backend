# 6-13. S3에 버전과 권한을 걸어라

## 문제

[6-2](6-2.md) 는 "어디에 둘 것인가"를 정했다. 여기서는 **"어떻게 지킬 것인가"**를 정한다.

기본값 그대로 만든 버킷에는 이런 성질이 있다.

```text
같은 키에 다시 쓰면 **옛 것이 사라진다**  → 되돌릴 곳이 없어진다 ([6-9](6-9.md))
보관 규칙이 없으면 **원본이 영원히 쌓인다** → 3,000대면 1년에 7.5 TiB
권한이 넓으면 **되돌릴 수 없는 사고가 난다** → s3:* 에는 DeleteBucket 이 있다
```

## 실습

```bash
pytest -m lesson_6_13 -s
```

## 만들기만 한 버킷

```text
[ondevice-ai-lake]
  버저닝      **꺼짐**
  암호화      **없음**
  공개 차단   **꺼짐**
  보관 규칙   **없음**
  권한 0줄

  CRITICAL GOV_NO_VERSIONING
  CRITICAL GOV_NO_ENCRYPTION
  CRITICAL GOV_PUBLIC_ACCESS_OPEN
  WARNING  GOV_NO_LIFECYCLE
```

**켜야 켜진다.** 만들었다고 지켜지는 것은 하나도 없다.

## 걸고 나서 다시 읽는다

```python
gateway.harden(versioning=True, encryption="AES256",
               block_public_access=True, expiration_days=365)
governance = gateway.inspect()   # ← 다시 읽는다
```

**"설정했다"와 "설정되어 있다"는 다른 이야기다.**
누군가 콘솔에서 껐을 수도 있고, 코드가 다른 버킷에 걸었을 수도 있다.

## 이 실습에서 가장 중요한 한 줄

```text
**버저닝은 사고가 난 뒤에 켤 수 없다.** 켠 시점 이후의 객체만 지킨다.
```

```text
버저닝 켬 → 같은 키에 두 번 쓰기 → 버전 2개 남음 → 롤백 가능
버저닝 끔 → 같은 키에 두 번 쓰기 → v1 은 이미 없다
```

[6-9](6-9.md) 의 롤백은 이 위에서만 성립한다.

## 권한 한 줄이 버킷을 연다

```text
CRITICAL GOV_PUBLIC_STATEMENT
         'PublicRead' 가 누구에게나(*) 허용한다.
         **이 한 줄이 버킷을 인터넷에 연다.**
```

"모델 파일만 공개하려고" 넣은 한 줄이다.
**현장 신호에는 생산량과 가동 패턴이 들어 있다** — 경쟁사가 읽으면 원가 구조가 보인다.

```text
WARNING GOV_OVERBROAD_ACTION
        'TrainingJob' 가 s3:* 를 허용한다.
        **s3:* 에는 DeleteBucket 이 들어 있다.**
```

학습 잡은 읽고 쓰기만 하면 된다.
그런 사고는 대개 자정에 도는 배치가 낸다.

## 보관 규칙이 없으면 청구서가 대신 정한다

3,000대가 하루 7 MiB 씩 올리면 1년에 7.5 TiB 다 ([6-1](6-1.md)).
**지울 것을 정하지 않으면 아무도 안 지운다.**

## 자주 하는 실수

- **데이터가 들어온 뒤에 버저닝을 켠다.** 그 전 것은 못 지킨다.
- **설정하고 확인 안 한다.** 다른 버킷에 걸렸을 수 있다.
- **역할에 s3:* 를 준다.** 삭제 권한이 따라간다.
- **보관 규칙을 미룬다.** 청구서가 대신 정한다.
