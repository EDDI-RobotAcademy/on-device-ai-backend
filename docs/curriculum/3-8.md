# 3-8. Training과 Validation을 분리하라

## 문제

분할은 실습 1-8 에서 이미 했다. 시간순으로 나눴고, 누수가 0초임을 확인했다.

**그런데 창으로 자르는 순간 다시 새기 시작한다.**

## 실습

```bash
pytest -m lesson_3_8 -s
```

## 무엇을 보게 되는가

```text
분할 사용 기록
  train      :   905개 (70%)
  validation :   194개
  test       :   195개
  경계 겹침  : 40 표본

CRITICAL PROTOCOL_SPLIT_OVERLAP
         분할 사이에 40 개 표본이 겹친다.
         창이 겹치면(실습 3-4) 나눠도 겹친다.
```

창 길이 30, stride 10 이므로 경계마다 **20 표본**이 양쪽에 걸친다.
경계가 둘(train|validation, validation|test)이니 40 표본.

**시험 문제의 일부를 이미 본 것이다.**

```python
def _boundary_overlap(starts, window_length, cuts) -> int:
    """분할 경계에서 두 쪽이 공유하는 원본 표본 수."""
    for cut in cuts:
        last_end = starts[cut - 1] + window_length
        next_start = starts[cut]
        overlap += max(0, last_end - next_start)
```

## 겹침을 없애면

```text
stride 30 (겹침 0%)
  경계 겹침  : 0 표본
  train      :   302개
  validation :    64개
  test       :    66개
```

누수가 사라졌다. 대신 **표본이 3분의 1로 줄었다.**

겹침을 없앤 대가다. **공짜로 얻는 것은 없다.**

그리고 test 66개로 낸 정확도를 얼마나 믿을 것인가 — 이 질문이 실습 3-10 으로 이어진다.

## 분할해 놓고도 새는 세 경로

### 1. 검증 집합을 보고 하이퍼파라미터를 고른다

```text
WARNING PROTOCOL_VALIDATION_OVERUSED
        검증 집합으로 50 번 점수를 냈다.
        그중 가장 좋은 것을 고르면, 그 점수에는 우연이 섞여 있다.
```

50번 실험하고 가장 좋은 것을 보고하면,
그 점수는 실력이 아니라 **50번 중 가장 운 좋았던 한 번**이다.

검증 집합은 학습에 쓰이지 않았지만, **선택에는 쓰였다.**
그 순간부터 그 점수는 더 이상 '미지'가 아니다.

### 2. test 집합을 중간에 본다

```text
CRITICAL PROTOCOL_TEST_REUSED
         평가 집합을 3 번 봤다.
         두 번째부터 그것은 test 가 아니라 두 번째 validation 이다.
         되돌릴 수 없다.
```

**되돌릴 수 없다.** 새 데이터를 구하는 것 외에 방법이 없다.

그래서 `max_test_evaluations` 의 기본값은 `1` 이다.

### 3. 평가 집합이 너무 작다

```text
CRITICAL PROTOCOL_TEST_TOO_SMALL
         평가 집합이 너무 작아 최종 보고 숫자를 신뢰할 수 없다.
```

15개로 낸 정확도는 한 건만 틀려도 **6.7%p** 가 움직인다.
그 숫자로 모델 A 와 B 를 비교할 수는 없다.

실습 2-5 의 `expected_minority_in_test` 와 같은 이야기다.

## 학습기가 스스로 센다

```python
SplitUsage(
    train_sample_count=905,
    validation_sample_count=194,
    test_sample_count=195,
    validation_evaluations=10,   # epoch 마다 한 번
    test_evaluations=0,
    overlapping_samples=40,
)
```

epoch 마다 검증했으니 10번이다. **이건 정상이다** — 조기 종료의 근거다.

문제가 되는 것은 그 점수를 보고 **설정을 바꿔 다시 돌리는** 횟수다.
그 횟수는 사람이 세야 하고, 그래서 `SplitUsage` 에 자리를 만들어 두었다.

## 분할은 '나눴다'로 끝나지 않는다

```python
@dataclass(frozen=True, slots=True)
class EvaluationProtocol:
    """분할을 어떻게 쓸 것인지에 대한 계약."""
    min_validation_samples: int = 50
    min_test_samples: int = 50
    max_validation_evaluations: int = 20
    max_test_evaluations: int = 1
    require_disjoint: bool = True
```

**어떻게 쓸 것인지까지 계약이어야 한다.**
그리고 그 계약 위반은 실습 3-10 의 승인 판정에서 모델을 막는다.

## 자주 하는 실수

- **"시간순으로 나눴으니 안전하다"고 믿는다.** 창을 겹치면 다시 샌다.
- **test 로 중간 점검을 한다.** 그 순간 test 는 사라진다.
- **실험 횟수를 세지 않는다.** 100번째 실험의 "최고 기록"은 대개 우연이다.
- **겹침을 늘려 표본 수를 부풀린다.** 표본은 늘고 정보는 그대로다.
